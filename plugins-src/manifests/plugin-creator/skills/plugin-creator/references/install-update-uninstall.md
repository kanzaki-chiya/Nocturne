# 插件安装、更新、卸载与状态说明

本参考记录桌面端「设置 › 插件」页面的实际操作路径与状态流转。Agent 不得替用户复制安装目录或改写 `<NOCTURNE_HOME>/plugins.json`，所有安装、启用与卸载均由用户在界面完成。

## 1. 首次安装与启用

1. 打开桌面端左栏底部「设置」，进入「Agent 能力」下的「插件」页。
2. 点击页面右上角「安装插件…」，在系统文件夹选择器中选中插件源码根目录（包含 `.nocturne-plugin/plugin.json` 的目录）。
3. Nocturne 会将目录复制到 `<NOCTURNE_HOME>/plugins/installed/local/<name>/<version>/`（跳过 `.git` 与符号链接），自动跳转到该插件详情页并提示「已安装 <显示名>」。安装后插件归入「Nocturne」分组，ID 为 `nocturne:<name>@local`。
4. **新装插件默认处于关闭状态（`off`）**，其技能、Hook 与 MCP 服务器尚未生效。
5. 点击详情页头（或列表行）的启用开关，弹出「启用 <显示名>」确认框，依次展示本次启用将运行的「Hook」「技能」「MCP 服务器」以及「不运行」项。
6. 核对无误后点击「启用」，界面提示「已启用 <显示名>」。Nocturne 会计算整目录 SHA-256 指纹并写入 `<NOCTURNE_HOME>/plugins.json`。
7. **生效时机**：
   - 技能与 MCP 服务器在空闲会话立即生效（运行中会话在 Turn 边界生效）；
   - Hook 在之后新打开的会话中生效。

## 2. 立即试用

- 当插件处于已启用状态（`on`）且至少包含一个可调用技能（未被停用、未被同名用户/项目技能覆盖、未被设为只限模型、未与内置命令重名）时，详情页顶部 hero 右侧会显示「立即试用」按钮。
- 点击「立即试用」（插件含多个可用技能时会先弹出「选择技能」菜单）：
  - 关闭设置页，在当前工作区新开一个草稿会话；
  - 在输入框中预填 `/<技能名> ` 并将光标置于末尾并聚焦；
  - **不会自动发送**，用户补充具体需求后按回车或点发送即可试用。

## 3. 更新已安装的本地插件

修改插件源码后，原有安装副本不会自动变化，需要按以下步骤更新：

1. 在插件源码的 `.nocturne-plugin/plugin.json` 中提高 `version`（例如从 `0.1.0` 升至 `0.1.1`）。
2. 用 `check_plugin` 确认更新后的目录仍然 `installable: true`。
3. 打开「设置」→「插件」，再次点击「安装插件…」，选择**同一插件源码根目录**。
4. Nocturne 会以新副本原子替换整个 `<NOCTURNE_HOME>/plugins/installed/local/<name>/` 目录，同时保留 `<NOCTURNE_HOME>/plugins.json` 中该插件原有的启用记录。
5. **内容变化后的状态流转**：
   - 若该插件原先为已启用（`on`）且目录内容发生变化，整目录指纹不再匹配，状态会自动变为 `changed`（界面显示警告标记「已更改」以及「重新确认」按钮）；
   - 处于「已更改」状态期间，插件的 Hook 会停止运行，技能与 MCP 服务器会被立即移除；
   - 点击「重新确认」，在确认框核对最新组件后点击「启用」，更新指纹并恢复为 `on`。

## 4. 卸载本地插件

1. 在「设置」→「插件」列表中点击对应插件，进入插件详情页。
2. 点击详情页头右上角「卸载」（仅本地安装的 `nocturne:<name>@local` 插件显示此按钮；内置插件与 Codex / Claude Code 来源插件不在 Nocturne 内卸载）。
3. 在「卸载 <显示名>？」确认框中再次点击「卸载」，返回插件列表并提示「已卸载 <显示名>」。
4. 卸载会删除 `<NOCTURNE_HOME>/plugins/installed/local/<name>/`、`<NOCTURNE_HOME>/plugins.json` 中该插件的记录以及 `<NOCTURNE_HOME>/plugins/cache/mcp-tools/` 下对应的工具缓存，但**不会删除** `<NOCTURNE_HOME>/plugins/data/<name>-local`（`PLUGIN_DATA`）。

## 5. 插件状态与跳过原因对照

### 插件状态（`PluginState`）

| 内部状态 | 界面表现 | 含义 |
|---|---|---|
| `off` | 开关关闭，列表行呈停用样式 | 未启用，技能、Hook 与 MCP 服务器均不加载。 |
| `on` | 开关开启 | 已启用且目录指纹一致（内置插件免指纹确认）。 |
| `changed` | 显示「已更改」状态与「重新确认」按钮，开关关闭 | 非内置插件启用后目录内容被修改或校验失败，已暂停加载；需点「重新确认」重新启用。 |

### 不运行与 MCP 跳过原因

| 类别 | 内部原因码 | 界面文案 | 含义 |
|---|---|---|---|
| Hook 不运行 | `point` | 不支持的点位 | 兼容清单使用了 4 个上下文点位之外的事件点，或未知点位名。 |
| Hook 不运行 | `type` | 不支持的类型 | 非 `command` 类型 Hook（如 `prompt`、`agent`、`mcp_tool`）或非 stdio MCP。 |
| Hook 不运行 | `async` | 异步 | 声明了 `async: true` 的 Hook。 |
| Hook 不运行 | `user_config` | 需要用户配置 | 命令或参数中包含 `${user_config.*}` 占位符。 |
| MCP 跳过 | `http` | 不支持 HTTP | 插件 MCP 声明了 `type: "http"`。 |
| MCP 跳过 | `stored` | 不支持凭据库 | 插件 MCP 的 `env` 中声明了 `{ stored: true }`。 |
| MCP 跳过 | `conflict` | 与配置同名 | 服务器 ID 与用户/项目配置文件或 `mcp.json` 同名，配置文件优先。 |
| MCP 跳过 | `invalid` | 配置无效 | 服务器名称、字段格式或环境变量名不合法。 |
