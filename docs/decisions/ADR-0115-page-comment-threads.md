# ADR-0115：页面评论自动回传与讨论串

- 状态：已接受（2026-11-24）
- 修订：[ADR-0113](ADR-0113-page-comments.md) 第 4 节「评论不自动发送」、第 5 节「不把评论锚点带到新版本」「不做讨论串、已解决」
- 相关：[ADR-0114](ADR-0114-project-page-library.md)（页面库）、[ADR-0109](ADR-0109-page-versions.md)、[ADR-0088](ADR-0088-inline-html.md)（沙箱空壳）
- 效果图：第 ① 节页面库、第 ②–④ 节桌面评论与讨论串

## 背景

ADR-0113 让用户能在面板页面上留评论，但评论要等下一条消息一起发，模型改完也只在对话里说一句，用户得自己对照页面去找改了哪里。目标形态参照 Innei/ryugi：评论钉上去就送到会话，模型改页面并在评论下回复，处理完标为已解决。

用户已定（2026-11-24）：
- 评论自动回传；
- 做讨论串、模型回复和已解决；
- 解决后评论从页面上去掉，不做重新打开；
- 弹窗保留「添加」（攒在输入框上方随消息发），另加「发送」。

## 决定

### 1. 范围

只做桌面端的面板页面，和 ADR-0113 相同。手机网页、安卓不做。

### 2. 发送方式

- 新评论弹窗的按钮改为「取消」「添加」「发送」：
  - 「添加」：行为与 ADR-0113 相同，放进输入框上方的标签，随下一条消息发；
  - 「发送」：立刻交给这个面板标签所属的会话，不经输入框。会话空闲就直接开一轮；会话忙就进入现有的待发队列（`enqueueInput`），在安全点交付，输入框上方的待发列表照常显示这一条。
- 「发送」的消息就是一条只带 `pageComments`、文字为空的用户消息，沿用 ADR-0113 的字段与英文块，不新增事件。

### 3. 评论 id 与讨论串

- **评论 id**：Core 在写入 `message.user` 时给每条评论分配 id `c<k>`，在本会话该页面内从 1 递增，写进 `pageComments.comments[].id`（可选字段，旧日志没有）。
- **用户在讨论串里回复**：讨论串底部是回复框和发送按钮。回复也立即发送（规则同第 2 节「发送」），作为一条 `pageComments` 消息，其中这一项带 `replyTo: "<评论 id>"` 和 `note`，不带新的位置。
- **模型回复**：新工具 `reply_page_comment`，输入 `{ page, comment, text, resolve? }`，只读、免确认、仅主会话（同 `render_html`）。`comment` 不存在或已解决时返回 `invalid_input`。回复写在 `tool.completed` 的结构化结果里，不新增事件类型。
- **用户手动解决**：讨论串右上角的勾（`aria-label`、`title` 为「解决」）。点击后写一条持久事件 `page.comment_resolved { page, comment }`。它不属于任何 Turn，回退不撤销（同 ADR-0111 的 `page.model_called`）；但评论本身被回退撤掉时，这条事件随之失效。
- **派生视图**：`SessionPage` 新增 `comments`。每条包含：
  - `id`、`version`（留评论时的版本）、`path`、`text`、`x`、`y`、`note`；
  - `replies[]`：每条 `{ by: "user" | "model", text, version, seq }`；
  - `resolved`、`pending`（已发出但模型还没回复，或还在待发队列里）。

  全部由有效事件派生。回放、回退、分叉沿用。

### 4. 交给模型的块

- ADR-0113 的英文块里，每条评论加上 `id`。
- 回复项写明 `reply to <id>`，并附上这条讨论串之前的往来，按时间顺序列出 `by` 与 `text`。
- 块末尾的指示改为：按评论修改页面（`render_html` 传 `page`），然后对每条评论调用 `reply_page_comment` 说明改了什么；已处理的评论带 `resolve: true`，需要用户回答的留着不解决。

### 5. 页面上的显示

- **圆点**：未解决的评论在留评论那一版和之后所有版本上都显示圆点，已解决的评论不显示。
  - 新版本上由空壳按 `path` 重新定位；`path` 找不到时按 `text` 找；都找不到时用原 `x`、`y`。
  - 圆点不进入截图和下载。
- **讨论串**：点圆点展开讨论串浮层，依次显示：
  - 用户评论与每条回复，每条带头像、`你` / `Nocturne`、`v<n>` 与时间；
  - 底部回复框与发送按钮；
  - 右上角「解决」勾。

  `pending` 时底部显示加载圈，不显示文字。
- **评论按钮上的数字**：未解决条数加上已「添加」但还没发出的条数。
- **页面库**：页面有未解决评论时，标题后显示一个强调色圆点（ADR-0114 第 4 节）。
- 除上面列出的按钮文字、`aria-label`、`title` 外，不加任何说明文字。

### 6. 兼容

- `pageComments.comments[]` 新增可选 `id`、`replyTo`，沿用非 `.strict()` 写法，不提升 `formatVersion`。
- 新事件 `page.comment_resolved` 按 `page.model_called` 等已有新增事件的兼容做法加入；基线 Runtime 读取包含该事件的日志时，完整解析以 `session_log_newer` 拒绝打开会话。新 Runtime 可以读取旧日志。回复项在日志编码中补上旧模式要求的空锚点字段，解码为无锚点的 `replyTo` 项。
- 旧日志里没有 `id` 的评论派生为不可回复的历史评论：不显示圆点，也不计入未解决数。

## 不做的事

- 不做重新打开已解决的评论。
- 不做 `@` 提及和多人评论。
- 不做手机端评论。

## 修订（2026-11-26）：清退新评论、续回与 `reply_page_comment`（ADR-0125 第一批）

按 [ADR-0125](ADR-0125-open-artifact-replaces-cadenza.md) 第一批，移除内置工具 `reply_page_comment`，桌面端移除面板评论模式开关与讨论串回复输入框，Core/RPC 拒绝新提交的 `pageComments`。历史面板上的已有讨论串（用户评论、模型历史回复、跨版本定位圆点）继续只读展示，并保留本地「解决」（`resolvePageComment` / `page.comment_resolved`）操作以便收起旧讨论。
