# ADR-0037：压缩保留最近原文、可设置阈值与缓存友好的压缩请求

- 状态：已接受（维护者 2026-10-01 确认）
- 日期：2026-10-01

## 背景

现行两级压缩（[context.md](../architecture/context.md) 第 6 节）有四个实际问题：

1. **压缩后忘记刚做到哪**。L1 修剪的边界取「最新闭合边界」，连上一步刚读到的文件、刚看到的报错也一起换成占位；L2 摘要同样尽量覆盖到最新边界。压缩一发生，最近几步的原文全部丢失，模型常常重新 read、重跑命令，或者干脆忘了刚改到哪。
2. **阈值写死**。修剪与摘要共用 80%，不能按模型调整。大窗口模型（1M）有人希望在 200k–300k 就压缩，以保持注意力；也有人希望只在溢出时才压缩。
3. **压缩本身打掉缓存**（2026-10-01 缓存审计）。
   - L2 摘要请求用独立的 system、把历史渲染成一段文本转录、工具集为空，与主请求没有任何共同前缀，整段历史按未命中计费。
   - L1 修剪每次只要超过阈值、存在新边界就执行，跨 Turn 小额修剪会反复改写同一大段历史，每次都让其后的缓存失效。
4. **估算与文档不一致**。第 5 节写的是「上一次请求 Provider 报告的输入 token + 此后新增内容的估算」，实现只用「字符数 / 4」，从未使用上游报告的用量。中文内容按字符 / 4 会低估 2–4 倍，大段中文文件读入后，压缩来得比预期晚，容易直接溢出。

参考：
- Pi 在摘要时保留最近一段原文（按 token 计）。
- OpenCode 的修剪保护最近约 40k token 的工具输出（`PRUNE_PROTECT`），并且回收量不足约 20k 时不执行（`PRUNE_MINIMUM`）。
- Claude Code 的摘要请求沿用主对话的上下文，只在末尾追加摘要指令。

## 决定

### 1. 可设置的摘要阈值

新增设置 `compaction.threshold`，可以写在 `config.json`、`settings.json` 和可信项目配置里，按通用分层「高层覆盖低层」合并（[config.md](../architecture/config.md)）。

- **写法**：百分比字符串（`"90%"`，相对可用输入预算）或绝对 token 数（整数 `200000`，或字符串 `"200k"` / `"1.5m"`）。
- **校验**：百分比须落在 (0, 100%]，绝对值须为正整数。不另设上下限。
- **生效值**：绝对值超过当前模型预算时按预算处理。百分比随模型窗口缩放，绝对值切换模型时不变。
- **默认值**：未设置时为 90%。
- 不可信项目的该字段忽略，与其他字段一致。
- `/settings` 新增一行「压缩阈值」，打开后是单位分段按钮（百分比 / token）加一个输入框，存储仍是单个字段。

### 2. 两级阈值与触发

记可用输入预算为 `B`，摘要阈值为 `S`（第 1 条的生效值），修剪阈值 `P = min(0.8·B, S)`。

- 估算超过 `P` 时尝试 L1 修剪（第 4 条）。
- 修剪后（或修剪不可行时）估算仍超过 `S`，尝试 L2 摘要（第 3 条）。
- `S = 100%` 表示不做任何预防性压缩（修剪与摘要都不做），只在请求超出预算或上游报 `context_overflow` 时强制压缩（`mustCompact`，现有路径不变，两级按 6.5 依次尝试）。
- 每个 Turn 每种压缩至多一次、失败处理与 `compaction_failed` 路径均不变（context.md 6.5、6.6）。

### 3. L2 摘要保留最近原文

**保留区大小**：`K = clamp(0.2·B, 20k, 40k)`，且不超过 `0.25·B`（小窗口模型的保留区不至于挤占摘要之后的空间）。

**边界选择**：在最新摘要之后的闭合边界里，选最早的、其后历史估算 ≤ `K` 的边界 `b`。也就是说，摘要覆盖到 `b`，`b` 之后的原文（最多约 `K` token）原样保留。
- 候选边界之前必须确有新内容（沿用 6.6「边界只取新内容」）。
- 最后一步本身就超过 `K`（一次巨大的工具输出）时，退到最新闭合边界，即现行为。
- 摘要请求装不下时，沿用 6.6 的回退规则逐步提前边界。

**最近文件提示**：摘要之后注入一段有界的提示「本会话最近读过或改过的文件：…」，最多 20 个路径，按最近使用排序，只列路径、不带内容。
- 来源是被摘要覆盖的 `tool.started` 事件中种类为 `read` / `edit` 的权限主体（`subjects`）。主体是工具声明产出的通用数据，Context 不按工具名写分支。
- 路径随事件持久化，恢复会话后结果相同。

有效历史变为：最新摘要 + 最近文件提示 + 摘要之后的事件（修剪规则照旧）+ 被覆盖的进行中 Turn 的 `message.user` 原文。

### 4. L1 修剪：保护最近原文，按回收量批量执行

- **保护区**：修剪边界取最早的、其后历史估算 ≤ `K` 的闭合边界，与第 3 条用同一个 `K` 和同一套选法。保护区内的工具输出不修剪。
- **最小回收量**：只有本次能回收的 token ≥ `R = min(20k, 0.1·B)` 时才执行修剪；不足时跳过修剪，估算超过 `S` 时直接走摘要。
- 最小回收量同时起到滞后作用：一次修剪会回收一大段，之后要再积累足够多的可修剪内容才会再次修剪，不再跨 Turn 小额反复改写同一段历史。

### 5. 摘要请求沿用主请求的前缀

摘要请求不再自建 system 和文本转录，改为：

- **前缀与主请求一致**：system 块、工具声明，以及主请求投影中直到边界 `b` 的全部消息，都与主请求相同，包括修剪占位、图片按当前模型能力处理的结果、上一个摘要。
- **摘要指令**：末尾追加一条 user 消息，写明「请把以上对话压缩为摘要，不要调用工具」，后面跟摘要结构要求（目标、已完成、关键文件、未决事项、下一步）。
- **缓存标记**：`cachePrefix` 覆盖全部 system 块与边界 `b` 之前的消息。
- **思考档位**：不带 `reasoningEffort`，按协议即关闭思考，避免思考用完 4k 输出上限。代价见「后果」。
- **输出上限**：沿用约 4,000 token。
- **模型仍调用工具时**：只要输出里有非空文本，就把文本作为摘要，忽略工具调用；没有文本则按摘要失败处理（6.6）。
- **装不下时的退路**：强制压缩时主请求本身已超预算，沿用前缀的摘要请求可能装不下。这时退回现行做法：独立 system 加文本转录，工具输出按修剪规则省略。退回也装不下，再按 6.6 提前边界。

前缀能否命中取决于上游的缓存机制：
- 按前缀自动缓存的服务（DeepSeek、OpenAI 兼容、Responses）直接命中边界 `b` 之前的部分。
- Anthropic 只在缓存标记附近查找已写入的缓存项。之前某一步的主请求恰好在 `b` 附近写过标记、且仍在有效期内时才能命中，不保证。

### 6. 估算按实现文档第 5 节落地，并按字符类别计数

- **锚定上游用量**：取最近一次主请求同一模型的上游用量（`inputTokens + outputTokens`，按 [events.md](../protocols/events.md) 的口径，`inputTokens` 已含缓存读写），加上其后新增内容的估算。
- **锚点失效**：之后发生过压缩，或模型、服务商切换过，锚点失效，改用纯估算，直到下一次请求返回用量。
- **字符计数**：估算函数改为 CJK 统一表意文字、假名、谚文与全角标点按 1 字 1 token 计，其余字符按 4 字符 1 token 计。适用于所有估算场景（纯估算、新增内容、边界选择、`/context` 报告）。

### 7. 不变的部分

- 不新增事件、不新增工具。`context.compacted` 的形状不变，旧会话按原样重放。
- 「每种压缩 `throughSeq` 严格递增」「摘要累积」「修剪只作用于最新摘要之后」等不变量不变。
- 可逆压缩（`context_ref` 加找回工具）与分层摘要不做：被省略的内容大多可以重新 read 或重跑取回，原文仍在事件日志里。确有需要时，再给占位加 seq 与只读找回工具。

## 后果

- 压缩之后最近约 20k–40k token 的原文仍在，模型能接着刚才的报错和改动继续。代价是摘要之后的上下文比现在多出这一段，压缩频率略升。
- 修剪次数明显减少，每次回收量变大，缓存失效次数随之减少。
- 摘要请求在前缀自动缓存的服务上大部分按缓存读计费。Anthropic 在开启思考的会话里，由于思考参数不同，消息部分的缓存可能失效，system 与工具声明部分仍可命中。
- 估算锚定上游用量后，中文会话的压缩时机更准确；锚点失效的那一步仍是粗估。
- 设置层新增一个字段，`/settings` 多一行。

## 备选方案

- **保留区按条数计（最近 N 步）**：步长差异太大，一步可能是几百 token，也可能是几万 token，按 token 计更可控。
- **摘要请求带上全部历史（包括保留区），让模型只总结边界之前的部分**：前缀更长、命中更多，但要求模型自行区分哪段需要总结，结果不稳定，保留区内容也会被重复写进摘要。
- **最近文件提示附带文件内容**（Claude Code 的做法）：效果更好，但每次摘要都会注入一大段内容，与保留区重复，也不好设上限。只给路径，由模型按需 read。
- **维持字符 / 4、只给 CJK 乘系数**：仍然完全不用上游用量，长会话误差会累积。

## 确认记录

维护者 2026-10-01 确认：
- `S = 100%` 时修剪也停止；
- 保留区与最小回收量按第 3、4 条取值；
- 摘要请求不带思考档位。
