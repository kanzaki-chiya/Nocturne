# ADR-0048：技能（Agent Skills）——兼容 `.claude/skills` 与 `.agents/skills`、模型按需加载、桌面端「设置 › 技能」

- 状态：已接受（维护者 2026-10-06 拍板，见文末「已拍板」）
- 日期：2026-10-06

## 背景

技能（skill）是一个目录，里面有一个带 YAML 前言的 `SKILL.md`，可以附带脚本、参考文档和模板。模型平时只看到每个技能的名字和一句说明，需要时才读入正文，这种做法叫渐进加载。这个格式已经是开放规范（agentskills.io），Claude Code、Codex 以及其他三十多个工具都在用，社区里也有大量现成的技能。

Nocturne 现在没有技能。桌面端的斜杠补全给它预留了一个 `"skills"` 分组（desktop.md），但目前是空的。维护者要求兼容 `~/.claude/skills`，这样已经装好的技能可以直接用。

本机现状是这个 ADR 的约束来源：`~/.claude/skills` 下有 110 个技能，每一个都是指向 `~/.codex/skills/…` 的符号链接；`~/.agents/skills` 下有 120 个，和前者大部分重名。108 个能解析出说明，说明合计约 4 万字符，最长的一条 1019 字符。也就是说：

1. 必须跟随符号链接，并按真实路径去重；
2. 必须处理跨目录重名；
3. 如果把全部说明原样塞进每次请求的上下文，要占一万多 token，必须设预算。

Claude Code 的一部分前言字段会改变执行或权限，例如 `allowed-tools` 预先放行工具、`` !`cmd` `` 在加载时执行命令、`hooks` 注册钩子、`context: fork` 起子代理。按 AGENTS.md 第 3 节，权限判定只能发生在权限层，所以这些字段不能照搬。

## 决定

### 1. 格式

- 一个技能就是一个包含 `SKILL.md` 的目录。前言按 Agent Skills 规范解析，正文是 Markdown。前言解析失败的技能跳过并发出警告，不影响其他技能。
- `name` 缺省时取目录名。规范要求名字只含小写字母、数字和连字符，最长 64 字符；实际上不少技能用了大写（如 `Humanizer-zh`），所以只警告、不拒绝。名字比较不区分大小写。
- `description` 缺省时，该技能不进入模型可见的目录（第 4 节），只能由用户手动调用，并在列表里标出原因。`when_to_use` 存在时接在 `description` 后面。

**支持的字段：**

| 字段 | 作用 |
|---|---|
| `name`、`description`、`when_to_use` | 名字与说明 |
| `disable-model-invocation: true` | 不进入模型目录，只能由用户调用 |
| `user-invocable: false` | 不出现在斜杠补全里，只能由模型调用 |
| `argument-hint` | 斜杠补全时显示的参数提示 |
| `arguments` | 具名参数，供下面的 `$name` 替换 |
| `license`、`compatibility`、`metadata` 以及其他未知字段 | 只在详情页展示 |

**加载正文时做的替换：**

- `$ARGUMENTS`、`$ARGUMENTS[N]`、`$N`、`$name`；
- `${NOCTURNE_SKILL_DIR}` 和兼容写法 `${CLAUDE_SKILL_DIR}`，替换为技能目录的绝对路径；
- `${CLAUDE_PROJECT_DIR}`，替换为 `workspaceRoot`；
- `${CLAUDE_SESSION_ID}`，替换为会话 id。

调用时带了参数、正文里却没有任何参数占位符的，在正文末尾追加一行 `ARGUMENTS: …`，与 Claude Code 的行为一致。

**识别但不执行的字段：** `allowed-tools`、`disallowed-tools`、`model`、`effort`、`context`、`agent`、`background`、`hooks`、`paths`、`shell`，以及正文里的 `` !`cmd` `` 和 ```` ```! ```` 块。

- 前言字段只在详情页列为「已忽略」，正文中的命令块按原文交给模型，不执行。
- 理由：放行工具、换模型、执行命令、注册钩子，都会绕过权限层或改变会话配置；一个从仓库里拉下来的文本文件不应具备这些能力。
- 需要执行脚本的技能照常工作：模型读了正文后用 `shell` 运行 `scripts/…`，走正常的权限确认。

### 2. 搜索位置与优先级

按优先级从高到低：

| 层 | 目录 |
|---|---|
| 用户 | `<NOCTURNE_HOME>/skills`、`~/.agents/skills`、`~/.claude/skills`，加上 `skills.extraDirs` 里列出的目录 |
| 项目 | 从 `cwd` 往上到 `workspaceRoot` 的每一级目录中的 `.nocturne/skills`、`.agents/skills`、`.claude/skills`；离 `cwd` 越近优先级越高 |

- **重名时高优先级胜出。** 用户层压过项目层，与 Claude Code 一致，目的是不让一个仓库悄悄替换掉用户自己的技能。同一层内，`.nocturne` 高于 `.agents`，`.agents` 高于 `.claude`。被压掉的技能在列表里显示「被 … 覆盖」，不会静默消失。
- **跟随符号链接，按真实路径去重。** 同一个技能目录从几个入口进来（例如本机的 `~/.claude/skills/x` 和 `~/.codex/skills/x`），只算一个，来源记为优先级最高的那个入口。
- **兼容开关**，写在用户配置 `config.json` 里：

  ```jsonc
  "skills": {
    "sources": { "agents": true, "claude": true },
    "extraDirs": ["~/.claude-coder/skills"]
  }
  ```

  关掉某个来源后，该来源在用户层和项目层的目录都不再扫描。`extraDirs` 用来覆盖其他工具改过的配置目录，例如设置了 `CLAUDE_CONFIG_DIR` 的情况。项目配置里的 `skills` 段忽略，不管项目是否被信任：搜索哪些目录属于用户自己的选择。
- **不支持 Claude Code 插件里的技能**（`~/.claude/plugins/…`），也不支持 Codex 的 `/etc/codex/skills`。
- **只读一层**：只扫描每个目录下一层子目录里的 `SKILL.md`，不递归。

### 3. 信任

项目技能的处理与项目 `AGENTS.md` 相同：不管项目是否被信任，都会加载。

理由：第 1 节已经去掉了所有会执行或放权的字段，技能只剩文本和需要经过权限层才能运行的脚本，风险等级和 `AGENTS.md` 一样，而 `AGENTS.md` 本来就不受信任限制（context.md 第 3 节）。项目技能在列表里标出来源，模型目录里也带上「项目」标记。

### 4. 模型侧：技能目录和 `skill` 工具

1. **目录**：在上下文组装的「项目指令」之后、「环境信息」之前新增一段「可用技能」，列出名字和说明，说明中用一句话告诉模型：需要时调用 `skill` 工具读取正文。
   - 每条说明最多 250 字符，超出部分截断并加省略号。
   - 整段的上限是当前模型上下文窗口的 2%，最多 8000 token。超出时，按「项目层优先、再按名字排序」的顺序保留完整条目，其余只列名字；连名字都放不下时，写「另有 N 个技能未列出」。截断情况记入 `ContextReport`。
   - 目录在会话打开时生成一次，会话内保持不变，以保住提示缓存前缀。磁盘上技能文件的增删改，要到下一个会话或下一次重载配置时才生效；设置页的启用/停用按第 6 节在 Turn 边界生效。
   - 目录为空时，不注入这一段，也不暴露 `skill` 工具。
2. **`skill` 工具**：
   - 输入 `{ name, arguments? }`。
   - 返回替换后的正文、技能目录的绝对路径，以及目录第一层的文件清单（最多 50 项）。
   - 不 mutating，可以并发；正文过长时按现有的结果预算截断。
   - 名字不在目录里时报错，并列出最接近的三个名字。
   - 同一会话里重复加载同一个技能、且内容没有变化时，只返回「已加载，见前文」。
3. **读取支持文件**：模型读技能目录里的 `references/…` 时走普通的 `read` 工具。技能目录多半在工作区之外，按现有预设外部读取要确认，用起来会很烦。所以由预设为本会话已发现的技能根目录生成 `read allow` 规则；规则在权限层求值，与 `nocturneHome` 路径规则同一机制。写入和执行不放宽。
4. **压缩**：`skill` 工具的结果不参与 L1 修剪，通过工具声明里的一个新特性 `pinResult` 表达，Agent Loop 不按工具名写分支。L2 摘要的固定指令要求在摘要里列出已加载的技能名，以便摘要之后模型知道可以重新加载。
5. **子代理**：`skill` 进入子代理的可选工具池；`explore` 和通用预设都默认包含它。子会话用父会话的目录快照。

### 5. 用户侧：斜杠调用

- TUI、CLI 和桌面端的斜杠补全，在「命令」组之后显示「技能」组：名字、`argument-hint` 和截断后的说明。
- **调用方式**：输入 `/<技能名> 参数` 并发送，Core 的 `submit` 接收 `skill: { name, arguments }`。
  - 按第 1 节渲染正文，把它固定在这条 `message.user` 上：用户原文后面附一个 `<skill name=…>` 文本块。做法与 `@文件` 引用的快照相同，恢复会话时用日志里的内容。
  - 用户调用不受 `disable-model-invocation` 限制，但受 `user-invocable: false` 限制。
- **与内置命令重名**：内置命令优先（如 `/compact`、`/mcp`、`/model`）。重名的技能在列表里显示警告，用户不能用斜杠调用它，模型仍然可以调用。
- TUI 和 CLI 新增 `/skills`，只读列出当前会话的技能、来源、是否被覆盖，以及是否进入了模型目录。

### 6. 桌面端「设置 › 技能」页

- **入口**：设置导航中，「MCP」之后加「技能」。
- **列表**：按「用户」「项目」分组，每行显示名字、来源标签（`.nocturne` / `.agents` / `.claude` / 额外目录）、启用开关，以及状态（被覆盖、缺说明、只限用户调用、只限模型调用）。项目分组显示设置页当前选中的工作区，规则同 MCP 页传给探测接口的工作区。
- **详情**：
  - 说明全文、真实路径（带「在资源管理器中打开」）、已解析的字段、「已忽略」字段及原因、正文前 40 行预览；
  - 说明被截断时，标出在模型目录里实际显示的长度。
- **开关**：停用的技能既不进模型目录，也不出现在斜杠补全里。状态写进 `settings.json` 的 `skills.disabled: string[]`（按名字记录），用已有的写入队列；对已打开的会话，在 Turn 边界重建目录，机制同 ADR-0047 第 4a 节。停用对所有层里同名的技能都生效。
- **不做**：在界面里新建、编辑或安装技能。详情页提供「在资源管理器中打开」，编辑交给外部编辑器。
- **Runtime 新增两个方法**，RPC 一一映射为 `skills.*`：
  - `describeSkills { workspaceRoot? }`，返回 `{ skills: SkillOverview[]; warnings }`；
  - `setSkillEnabled { name, enabled }`。
- 视觉细节以单独的界面稿为准，界面稿经维护者确认后再实现。

### 7. 文档

- 新增 `docs/architecture/skills.md` 作为主文档。
- context.md 第 3 节：组装顺序；
- tools.md：`skill` 工具；
- tool-api.md：`pinResult` 特性；
- permissions.md 第 6 节：技能根目录的读规则；
- config.md：`skills` 段；
- rpc.md：`skills.*`；
- desktop.md、cli.md、tui.md：斜杠调用和设置页；
- README：一句面向用户的说明。

## 后果

- 本机已有的技能不用迁移就能用。同一套目录同时服务 Claude Code、Codex 和 Nocturne。
- 依赖 `allowed-tools`、`context: fork`、`` !`cmd` `` 的技能，在 Nocturne 里的行为会和在 Claude Code 里不同：要么多出权限确认，要么少了预先注入的命令输出。详情页会明确标出这一点。
- 每次请求多出一段受预算约束的目录。技能很多时，大部分只露名字，模型可能因此不知道该用哪个。补救办法是停用不常用的技能。
- 新增工具特性 `pinResult`，新增预设规则来源（技能根目录）。

## 备选方案

- **只认 `<NOCTURNE_HOME>/skills`**：规则最简单，但用户得把 110 个技能再复制或链接一遍。维护者已决定要兼容。不采用。
- **项目层压过用户层**：Codex 是越近越优先。但这样仓库可以悄悄换掉用户信任的同名技能。不采用。
- **项目技能需要信任才加载**：更保守，但和 `AGENTS.md` 的处理不一致；而且去掉执行字段之后，技能已经没有比 `AGENTS.md` 更高的风险。维护者选择照常加载（「已拍板」第 2 条）。不采用。
- **支持 `allowed-tools`**：违背「权限判定只在权限层」。如果以后要支持，应该把它翻译成会话级规则并由用户确认，而不是由技能自己放权。不采用。
- **`context: fork` 映射到 `task` 子代理**：可行，但需要新增「技能驱动子代理」的入口，范围扩大了。以后单独评估。

## 实施顺序

1. Core：发现、解析、去重、优先级、替换、预算目录、`skill` 工具、`pinResult`、技能根目录读规则、`submit` 的 `skill` 字段、`describeSkills` / `setSkillEnabled`、热更新；RPC `skills.*`；离线测试。
2. TUI / CLI：斜杠补全中的技能组、`/skills`。
3. 界面稿（交维护者确认）。
4. 桌面端：「设置 › 技能」页、斜杠技能组、GUI 实测。
5. 文档同步。

## 已拍板

1. **优先级**：用户层高于项目层（第 2 节）。
2. **未信任项目的技能**：照常加载，与 `AGENTS.md` 一致（第 3 节）。
3. **技能目录的外部读取**：由预设自动放行读取，写入和执行不放宽（第 4 节第 3 条）。
4. **目录预算**：每条说明 250 字符，整段不超过上下文窗口的 2%，封顶 8000 token（第 4 节第 1 条）。

## 修订

### 2026-10-07：桌面端导入技能

维护者根据桌面端问题报告（U-08）拍板，在「设置 › 技能」页加入导入：

- **来源**：只支持本地文件夹。选中的文件夹本身含 `SKILL.md` 时作为单个技能；否则扫描其下一层子目录，每个含 `SKILL.md` 的子目录算一个技能。zip、Git 地址不做。
- **目标**：用户级 `<NOCTURNE_HOME>/skills/` 或当前工作区的 `.nocturne/skills/`，二选一，默认用户级。项目目标只在设置页选中了工作区时可选。
- **校验**：逐项按第 1 节的格式规则检查（frontmatter、名字格式、说明），不合格的列出原因并不可勾选。只复制文件，不执行其中任何脚本；跳过符号链接，单个技能总大小设上限（实现时定，写入 skills.md）。
- **重名**：目标目录已有同名技能时逐项选择「改名」（默认，自动加 `-2` 等后缀，同时改写 `SKILL.md` 的 `name`）、「覆盖」或「跳过」。覆盖先复制到临时目录，成功后再替换，失败时原技能保持不变。同名技能只存在于其他目录或层时不算冲突，但照第 2 节标出结果（「将被 … 覆盖」或「将覆盖 …」），让用户知道导入后哪个生效。
- **启用**：沿用第 6 节规则，放进目录即启用（停用靠 `skills.disabled`）。结果页逐项显示成功或跳过原因，成功项给「停用」按钮。已打开的会话照第 4 节在下一个会话或重载配置后看到新技能。
- **接口**：RPC 新增 `skills.importSkills`（预检返回候选与冲突，执行时带逐项决定），签名和错误码照 `skills.*` 现有风格；写入经 Core，客户端不直接写技能目录。
- **范围**：只做桌面端入口；TUI/CLI 不加导入命令。
- **文档**：skills.md（如无则写在第 6 节对应的主文档）、rpc.md、desktop.md 同步。
