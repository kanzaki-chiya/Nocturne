# ADR-0121：托管工作树的保留、清理与恢复

- 状态：提议（补记 0.67.0 实现，待维护者确认长期策略）
- 日期：2026-11-26
- 实现基线：`28df1600`，对应桌面端「设置 → 工作树」。

## 背景

[ADR-0075 §6](ADR-0075-worktree-isolation.md#6-保留与清理) 规定子代理结束后如何交付副本，以及无改动、已并回等情况下如何清理。[ADR-0085](ADR-0085-new-session-branch-picker.md) 又允许顶层会话使用工作树。两种入口创建的副本会跨会话累积。工作目录即使干净，分支上也可能还有唯一一份提交；同一文件在 Git 暂存区和磁盘上也可能有两个需要保留的版本。

0.67.0 增加了桌面端的托管清单和按数量清理的策略。这份记录说明这条新增清理路径的所有权和恢复条件；子代理创建时的基线快照、任务交付和并回仍按 ADR-0075 处理。

## 决定（实现现状，提请确认）

1. **以登记证明归属。** 清单汇集本机 Nocturne 登记的新会话和子代理工作树，兼容旧子代理登记。`git worktree list` 用来核对仓库和路径；主检出和用户自行创建的副本排除在清理范围外。仅当登记表明分支由 Nocturne 创建、当前分支名和提交仍匹配且无其他检出时，才按旧 SHA 原子删除引用。用户后来切换的分支和目录旁的普通同名 JSON 文件要保留。
2. **按最后使用时间选候选。** 默认开启自动清理，保留最近使用的 15 份候选副本。置顶和使用中的副本不参与计数。清单按项目展示；清理名额按本机托管清单计算。进入候选后仍要逐份复查 Git 锁、活动状态和可恢复性，因此保留数可以暂时超过设定值。手动删除前的询问默认开启，关闭询问只影响交互步骤。
3. **先证明能恢复，再执行清理。** 自动清理必须保存并核验恢复快照；手动清理有独有提交或本地改动的副本也要保存快照。快照记录提交、暂存区补丁、工作区补丁和未跟踪文件。分别保存两个补丁，才能在恢复后同时找回已暂存的 A 和后来修改的 B。删除前再次比对状态；发生变化则保留原件。恢复时校验内容，原路径或分支名已被使用就另选名称。
4. **无法完整捕获时保留原件。** 遇到被忽略的本地文件、脏子模块、进行中的 Git 操作等，清理须给出跳过原因。遇 Git 锁或 Git 拒绝移除，保留工作树并报告。这里的代价是含构建产物的旧副本也可能需要用户手动整理。这样可以避免丢失目录里的本地数据，也避免把被忽略的私有文件复制进恢复快照。

配置默认值与登记位置见[配置架构](../architecture/config.md)，接口及结果见 [RPC 契约](../protocols/rpc.md)。恢复索引与工作区、锁定副本、改名或移动分支、相邻文件归属等场景的可运行依据见[专项测试](../../packages/core/test/git-worktree-settings.test.ts)。

## 待维护者决定

| 事项 | 选择与影响 | 建议 |
|---|---|---|
| 自动清理是否长期默认开启？ | 保持现有默认可减少遗留副本；改为显式开启，可避免用户首次使用就看到旧目录被回收。 | 保持默认开启、保留 15 份，将置顶、活动状态、快照核验及跳过条件作为承诺。用户可以关闭自动清理。 |
| 遇到被忽略文件，是否允许按名称白名单自动删除？ | 放行常见构建目录能释放更多空间，但名称不能证明内容可以再生。 | 保持整棵跳过。清理结果指出阻塞路径，由用户决定如何处理。 |
| 恢复快照是否跟随工作树数量自动淘汰？ | 自动淘汰可限制磁盘占用，却可能消除已移除副本的最后一份可恢复内容。工作树保留数与快照保存期限是两种承诺。 | 本轮维持快照独立保存。若需要回收快照，另提带容量与内容预览的管理方案，由用户明确选择。 |
