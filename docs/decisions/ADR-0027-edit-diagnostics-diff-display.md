# ADR-0027：edit 未命中诊断与带行号的 diff 显示

- 状态：已接受（维护者 2026-09-29 确认）
- 日期：2026-09-29

## 背景

`edit` 要求 `old` 与已读取文件中的文本精确匹配。现在未命中只返回「未出现」，模型通常还要重新 `grep`、`read` 才知道差异。`edit` 和覆盖式 `write` 已在 `output.diff` 中返回行级差异，但头部只有路径，没有行号；CLI 与 TUI 也都不显示行号。TUI 折叠到头 6 行、尾 4 行，长行截断，较大的修改难以核对。[路线图](../roadmap/roadmap.md)要求一并改善这些反馈。

现有 `ToolResult.modelContent` 返回给模型，结构化 `output` 供客户端展示；`tool.completed` 将二者写入会话。`output` 超过 100,000 字符时会整项省略。全屏 TUI 的鼠标单击目前只清除选区，拖动会复制；普通屏幕模式把历史打印到终端，无法回改已打印的条目。这些约束决定了诊断、展开和降级方式。

## 决定

### 1. 未命中时只给建议，不自动修改

保留 `edit` 的精确匹配、先读后写、唯一匹配及权限规则。只有通过路径和已读状态检查后、确认 `old` 未出现时，才从本次已读的文件文本生成提示；错误码仍为 `no_match`，提示写入现有 `error.message` / `modelContent`，不新增工具或事件字段。

- 先比较仅统一换行符后的文本；若能匹配，明确提示换行符不同。再比较忽略行首缩进后的文本；若能匹配，明确提示缩进不同。最后比较忽略空白字符后的文本；若能匹配，明确提示空白不同。提示带实际位置的、从 1 开始的行号，并要求模型据此提供精确的 `old`；诊断绝不把近似匹配当作写入依据。
- 上述比较仍未命中时，从文件中选最接近 `old` 的连续片段，最多返回一处、至多 5 行，逐行附 1 起始行号。候选评分须确定、对单行和多行 `old` 有效；若没有可信候选，直说找不到相近片段，不输出无关文本。提示长度、候选搜索量均设上限，较大的文件或 `old` 退化为原有的简短错误。完整文件内容不进入错误文本。
- `not_unique`、`not_read`、`resource_changed` 等错误行为不变。诊断不增加文件读取或权限请求，尤其不探查目标文件以外的路径。

### 2. `output.diff` 保持字符串，头部带旧、新文件行号

沿用 `packages/core/src/tools/builtin/diff.ts` 生成行级 diff，沿用 `output.diff` 字符串字段，不新增依赖或提高事件格式版本。新生成的差异块使用 `@@ -旧起始行,旧行数 +新起始行,新行数 @@` 头部；行数包含上下文，内容行仍以空格、`-`、`+` 开头。路径继续由 `output.path` 提供。无变化时仍为空 diff。行号按实际文件从 1 开始，纯插入或纯删除遵循 unified diff 的零行数位置约定。

新建文件的 `write` 也生成从空文件到新内容的 `output.diff`，让 CLI 和 TUI 走同一路径；旧会话中只有 `created: true` 而没有 diff 的结果，TUI 继续按输入内容合成新增行。客户端遇到旧式 `@@ 路径 @@` 头部或没有头部的旧结果时照常显示，只是不臆造行号。

摘要从真实增删行数计算，统一显示「新增 N 行，删除 M 行」；上下文不计数。行尾 `CRLF` / `LF` 与文件末尾有无换行也算文本变化：前者按变更行计数，后者须用明确标记或整行替换表达，不能出现有修改却报告 0/0 的情况。`edit` / `write` 的模型可见结果仍说明操作和路径，用户界面的摘要紧随其后显示增删数。计数与行号由 Core 的 diff 事实提供，客户端仅解析和呈现，不重新比较文件，也不把整份 diff 塞进 `modelContent`。

### 3. 客户端显示与展开

CLI 显示旧、新两侧行号及 `+`/`-` 标记，输出完整已保留的 diff；无颜色时依靠标记区分。TUI 每个 diff 源码行显示旧、新行号和标记，源码文字保留正文颜色；新增、删除行在可用颜色的终端铺满整条视觉行的暗绿、暗红背景，行号与标记也在背景内。长行按可用宽度折行，续行对齐内容列，不能静默截断；选中复制时，同一源码行的自动折行应能拼回。`NO_COLOR`、ASCII 或终端不支持背景色时，以行号和标记降级显示。

全屏 TUI 默认显示前 20 行和后 20 行，超出时中间显示「… 还有 N 行」；头部不计入 40 行阈值。单击该行展开当前工具结果的完整**已保留** diff，再次单击可收起；拖动选中文字的既有行为不变，展开后视口与布局缓存正确更新。普通屏幕 TUI 无法交互修改已打印的历史，因此直接打印完整 diff；CLI 也不折叠。两条 TUI 渲染路径应保持行号、折行和颜色降级一致。

结构化 `output` 超过现有上限而被省略时，客户端没有可展开的 diff；此时显示已有的结构化输出省略提示，不假称可以查看完整内容。本决策不改变工具输出预算和溢出落盘规则。

## 验收

- `edit` 对换行符、缩进、一般空白及实质文字不同时返回对应提示；未命中绝不写文件。先读后写、重复匹配和大文件退化均有覆盖。
- `edit`、覆盖式 `write`、新建 `write` 的插入、删除、替换、文件首尾与 CRLF 场景有正确的头部、逐行行号及增删摘要；旧式会话 diff 仍可渲染。
- CLI、全屏 TUI、普通屏幕 TUI 的有色、`NO_COLOR`、ASCII、窄终端与长行显示均检查；全屏折叠、单击展开/收起和拖动复制互不干扰。UI 结果在 Windows Terminal 实际查看；会抢前台的自动化测试事先询问维护者。
- 实现时同步 [工具设计](../architecture/tools.md)、[Tool API](../protocols/tool-api.md) 中涉及的结果契约，以及 [CLI](../apps/cli.md)、[TUI](../apps/tui.md) 的用户可见行为。运行仓库规定的离线检查，测试使用隔离的 `NOCTURNE_HOME`，不读取或写入用户真实配置。

## 后果与备选方案

诊断能减少重复探查，行号和折行能让修改结果直接核对；代价是 diff 输出与 TUI 布局代码会更复杂，极大 diff 仍受既有结构化输出上限约束。未采用模糊自动替换，因为它会在文本相似但不相同的地方改写文件；未为 diff 另造事件或引入外部 diff 库，因为现有 `output.diff` 已能承载所需位置，旧数据也可降级显示。
