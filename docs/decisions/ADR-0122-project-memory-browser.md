# ADR-0122：设置页按项目浏览记忆条目

- 状态：已接受（2026-11-26 维护者确认视觉原型）
- 日期：2026-11-26

## 背景

[ADR-0098](ADR-0098-memory.md) 的记忆总览返回全局与当前项目的条目摘要，其他项目只返回项目键、路径和数量。桌面端据此显示「其他项目」和「清空」。例如用户能看到 `Z:\nocturne` 有两条记忆，却无法打开它们。用户希望在设置页直接按项目查看正文，无须先切换项目会话。

## 决定

1. 「其他项目 · N」是静态分组标题。进入总览直接展示项目，每个项目占一行，采用「工作区」设置的两行排版：第一行显示项目名（目录末段），第二行以弱色等宽字体显示完整路径，右侧显示条数、独立的「清空」和进入箭头。同名项目按路径区分。点击项目行进入独立列表子页，再点条目查看详情；逐级返回时恢复原位置与焦点。
2. `describeMemoryStore` 在统计各项目条数时已经取得 `entries`。建议在 `OtherProjectMemory` 的总览结果中附带这些摘要，沿用现有 RPC。只有打开条目时才用 `readMemory({ scope: "project", key, name })` 读取正文。选中态和刷新校验同时使用项目键与条目名，避免不同项目的同名条目串读。以键寻址也允许在原仓库移动后浏览留存的记忆。
3. 浏览行为只发生在桌面设置页，不改变会话工作区、记忆开关、写入范围或模型可见的记忆。已存在的当前项目仍只出现一次。

4. 详情支持逐条删除。确认框显示项目路径和条目名；确认时调用 `deleteMemory({ scope: "project", key, name })`。取消后留在原详情，成功后回到项目列表并更新数量；若删掉最后一条，显示项目空态，返回总览后该项目按既有空项目规则移除。失败时保留条目并允许重试。

## 视觉交付顺序

维护者已确认总览、项目子页、正文及逐条删除确认四种状态的可交互原型。实现和验收以该版为参照，特别是总览首次进入就显示所有项目，并以项目名和完整路径分两行展示。

## 验收

桌面测试在默认工作区列出两个各有同名记忆的项目，分别进入并打开。核对读取、删除均作用于所选项目，取消后两边数据完整，确认后另一项目的同名条目仍在。覆盖键盘访问、逐级返回、快速切换时旧请求迟到、删最后一条、删除失败和点「清空」后取消。另测当前项目去重；用隔离数据实际渲染原型约定的四种状态。Runtime/RPC 测试核对总览只返回摘要，读删使用对应键。
