# ADR-0116：选中对话文字引用回复

- 状态：已接受（2026-11-24）
- 相关：[ADR-0113](ADR-0113-page-comments.md)（`message.user` 快照字段与给模型的块）、[ADR-0070](ADR-0070-steer-and-queue-input.md)（待发队列）
- 效果图：桌面选中浮出「回复」按钮、输入框顶部引用列表与已发消息气泡内引用及跳回高亮设计稿（第 ①、②、③ 节）

## 背景

用户常要针对模型回答里的某一句提意见。现在只能手动复制那句话、粘进输入框再加引号说明，模型也不知道这句出自哪条回答；长回答里来回滚动找原文也麻烦。

用户已定（2026-11-24）：只做桌面端；手机上选中文字不方便，也会和系统自带的选中菜单冲突。

## 决定

### 1. 范围

- 桌面端会话视图里，助手回答和用户消息（含其中的代码块）可以选中引用。工具卡片、思考内容、子代理只读视图不做。
- 手机网页、安卓、TUI、CLI 不提供选中引用；它们只按第 5 节显示已有引用。

### 2. 选中与「回复」按钮

- 在**一条**消息内选中非空文字后，选区上方浮出按钮「回复」（回复图标加文字），水平居中于选区，贴近选区首行上方；上方空间不够时放到选区下方。
- 选区跨消息、选区为空、点空白处、按 Esc、滚动使选区离开视口时按钮消失。
- 浏览器原生选中、复制、右键菜单不受影响。

### 3. 输入框里的引用

- 点「回复」后，选中原文（保留换行，首尾空白去掉）作为一段引用放进输入框顶部，光标移入输入框，选区清除。
- 可以连续引用多段，按添加顺序排列；同一段原文重复引用时不重复添加。
- 每段引用：左侧强调色竖线、弱一档的文字，超过两行截断，悬停显示全文，右侧 `×` 移除。
- 引用属于输入框草稿：与附件、页面评论标签同时存在；切换会话时随草稿保留；发送后清空。
- 只有引用、正文为空时也可以发送。

### 4. 协议与给模型的块

- `message.user` 与提交输入新增可选字段 `quotes?: { text: string; seq?: number }[]`，`seq` 为来源消息的持久事件序号（用户消息为其 `message.user`，助手回答为其 `message.assistant`）。沿用非 `.strict()` 写法，不提升 `formatVersion`；旧版本忽略未知字段。
- Core 在提交时把引用写成一个放在 `content` **最前面**的文本块：每段引用逐行加 `> ` 前缀，段与段之间空一行，块末空一行。块内容只在 Core 生成。
- `userEntryText` 在 `quotes` 存在时去掉这个首块，客户端显示、复制、重发、搜索只看用户亲自输入的正文。
- 待发队列（`enqueueInput`）、回放、回退、分叉原样保留 `quotes`；回退把消息放回输入框时，引用一起放回。

### 5. 显示

- 已发出的用户消息气泡里，引用在正文上方：左侧细竖线、弱一档文字，最多三行。
- 桌面端点引用：滚动到来源消息并短暂高亮整条消息（能定位到原文就高亮原文）；来源消息已被回退撤掉或不在当前视图时点击无反应。
- 手机网页与安卓复用同一显示，只读，不响应点击跳转以外的操作。
- TUI 与 CLI 在用户消息上方以弱色 `> ` 行显示引用，每段最多两行。
- 除「回复」与 `aria-label`、`title` 外不加任何说明文字。

## 不做的事

- 不做手机端选中引用。
- 不引用工具卡片、思考内容、页面内容（页面用 ADR-0113 / ADR-0115 的评论）。
- 不做引用后自动生成提问文字。
