# ADR-0040：模型角色：子代理、看图与标题

- 状态：已接受
- 日期：2026-10-02

## 背景

[路线图](../roadmap/roadmap.md) v0.5 的最后一项是「模型角色」：按用途给模型分工，未配置的角色回落到主对话模型。现状有三处不便：

- **子代理**只能继承父会话模型（[subagent.md](../architecture/subagent.md) 第 9 节「子代理独立模型选择」列为不做）。探索类任务用便宜快速的模型就够，现在只能和主对话一样贵。
- **当前模型不能看图时**，图片附件只能被拒绝（用户输入）或投影成一行占位文字（工具结果，[ADR-0023](ADR-0023-image-input.md) 第 4 节）。DeepSeek 等主力模型不看图，截图类任务只能换模型。
- **会话标题**取首条消息原文首行（[ADR-0038](ADR-0038-transcript-polish.md) 修订），长粘贴或寒暄开头时标题没有信息量。

omp 的 `modelRoles` 有 default、smol、slow、vision、plan、commit、tiny、task、advisor 九种。Nocturne 目前只有三种用途真正需要，其余等出现具体需求再加。安全审查模型已由 [ADR-0036](ADR-0036-smart-permissions.md) 单独配置，不属于模型角色。

## 决定

### 1. 角色集与配置

- 新增三个角色：
  - `task`：子代理；
  - `vision`：替不能看图的模型描述图片；
  - `smol`：生成会话标题等轻量工作。
- 主对话模型仍是现有的 `model`（默认模型）与会话内 `/model` 切换，不另设 `default` 角色。
- 配置字段 `modelRoles`，值为 `"provider/model"` 字符串：

  ```json
  { "modelRoles": { "task": "deepseek/deepseek-v4.1-flash", "vision": "openrouter/google/gemini-3.8-flash", "smol": "deepseek/deepseek-v4.1-flash" } }
  ```

- 加入 `settings.json` 白名单，与 `config.json`、可信项目配置按通用分层合并，高层覆盖低层，逐角色合并。不可信项目忽略此字段（它会把数据发往另一家服务商）。
- 引用的服务商或模型在注册表里找不到时，启动不失败：发一条 `runtime.warning`，该角色按未配置处理。
- 角色不带思考档位：
  - `task` 继承父会话档位，按子模型可用档位就近降档（沿用 subagent.md 第 9 节的规则）；
  - `vision` 与 `smol` 的请求不带 `reasoningEffort`，与压缩摘要请求一致。

### 2. task：子代理模型

- 配置了 `task` 时，子会话的 `session.created.model` 写 task 模型。未配置时继承父会话当前模型，与现在一致。
- 子会话的预算、压缩与图片投影按子模型自己的能力计算，机制不需要例外。
- `task` 工具结果的 `output` 增加 `model` 字段（`provider/model`），TUI 的工具行摘要显示子代理实际用的模型。
- subagent.md 第 9 节「子代理独立模型选择」从「不做」改为「由 `task` 角色决定」。

### 3. vision：替当前模型看图

- **触发**：构建模型请求前，如果当前模型的 `imageInput` 为否、`vision` 角色可用，Core 对投影窗口里尚无描述的图片附件逐个调用 vision 模型生成描述。用户附件和工具结果附件（`read` 读图、MCP 图片）都适用。
  - 每张图只描述一次。描述写入新的持久事件 `attachment.described`，以后重放、恢复、切换模型都直接复用，不再请求。
  - 中途从能看图的模型换到不能看图的模型时，在下一次构建请求前补描述，规则相同。
- **请求**：单轮请求，内容为图片加一段固定指令，要求如实转写图中文字、代码、报错和界面元素，再概括与任务相关的内容。
  - 用户附件附带同一条消息的文字作为上下文；工具附件附带工具名和路径。
  - 最大输出 1000 token，不带工具定义。
- **投影**（修订 ADR-0023 第 4 节）：当前模型不能看图时，有描述的附件投影为文字块 `[图片 #n 描述（由 <vision 模型> 生成）]\n<描述>`；没有描述时仍是现有占位文字。当前模型能看图时照常发图片，忽略描述。
- **失败与中断**：
  - 单张图描述失败（请求错误、超时、空响应）时，发 `runtime.warning`，该图沿用占位文字，Turn 继续；下一次构建请求时不重试同一张图，避免每步重复失败。
  - Esc 中断 Turn 时一并取消进行中的描述请求，已完成的描述保留。
- **用户输入入口**：当前模型不能看图但 `vision` 可用时，TUI 不再拒绝附加图片，改为在输入框下方提示「当前模型不支持图片，将由 <vision 模型> 描述后发送」。`vision` 不可用时维持现有提示与拒绝规则。客户端通过会话 API 查询 vision 是否可用，不自行判断模型能力。
- **显示**：描述进行中状态栏显示「描述图片中」。完成后在对应消息或工具行下方显示一行灰色 `图片 #n 已由 <模型> 描述（N 字）`；全屏下单击可展开描述全文，复用 ADR-0038 的折叠规则。

### 4. smol：会话标题

- **触发**：会话写入第一条 `message.user` 后，Core 在后台发一次标题请求，不阻塞 Turn。请求用 `smol` 角色的模型；`smol` 未配置或不可用时，用发出首条消息时的会话模型。
  - 请求内容是首条用户消息的文字（截取前 2000 字符）和固定指令：用与用户相同的语言，生成不超过 20 个字的标题，只输出标题。
  - 结果去掉引号、换行和首尾空白，截到 40 个显示宽度后，写入新的持久事件 `session.titled`。
- **只生成一次**：会话已有 `session.titled` 时不再生成。旧会话恢复时不补生成。子会话不生成标题。
- **失败**：静默放弃，记诊断日志，不发 `runtime.warning`（标题不影响任务）。标题请求在会话关闭时取消。
- **使用**：
  - `SessionView.title` 优先取 `session.titled`，没有时回落到 ADR-0038 的首行规则；
  - TUI 输入框标题、`/resume` 列表都用它；
  - `/resume` 列表读日志时同时识别 `session.titled`。
- 标题请求只有一次、输入很短、输出不超过 20 字，即使回落到主对话模型，花费也可以忽略。

### 5. 事件与接口

- 新增两个持久事件（兼容变更，不提升 `formatVersion`）：
  - `attachment.described`：`attachmentRef`（指向 `message.user` 或 `tool.completed` 中的附件，含所在事件 seq 与附件序号）、`model`、`text`、`usage?`；
  - `session.titled`：`title`、`model`、`usage?`。
- 角色调用的用量记在各自事件里。状态栏的缓存命中率和速度只统计主对话模型，不混入角色用量；将来 `/cost` 再汇总。
- `Runtime` 新增：
  - `describeModelRoles()`：返回三个角色的配置值、生效模型、来源与是否可用；
  - `setModelRole(role, ref | null)`：写 `settings.json`，`null` 清除。
- 会话新增 `visionInfo()`：返回当前模型能否看图、vision 是否可用及其模型名，供输入入口提示使用。
- `SettingItem` 增加三个角色条目，来源标注与其他设置一致。

### 6. 设置界面

- `/settings` 新增「模型角色」组，三行：
  - `子代理模型：跟随当前模型`
  - `看图模型：未设置`
  - `标题模型：跟随当前模型`
- Enter 打开现有 `/model` 选择页（与审查器的小模型选择相同的复用方式），列表顶部加一项「跟随当前模型」（task、smol）或「不使用」（vision），选定后返回设置页，仍要按底部「保存」才落盘。
- 看图模型选择页只列 `imageInput` 为是的模型；选了不能看图的模型时，保存前提示。
- `/model` 页的「设为默认」只管主对话模型，不涉及角色。

## 后果

- 子代理可以用便宜模型跑探索任务，主对话保持强模型。
- 不能看图的主力模型也能处理截图：描述持久化，同一张图只花一次钱，切换模型时历史投影仍然正确。
- 标题从「首行原文」升级为「概括」，`/resume` 列表更好找会话；不配置 `smol` 时用会话模型生成，每个会话多一次很小的请求。
- 新增两个持久事件和少量 Runtime 接口，需要同步 events.md、view.md、config.md、context.md、subagent.md、tui.md。
- 描述是有损的：vision 模型漏看的细节，主模型无从得知。界面上会标明「由 <模型> 描述」，用户可以据此判断是否换成能看图的模型。

## 备选方案

- **提供一个 `look_at_image` 工具让主模型按需看图**（omp 的做法之一）：主模型可以针对问题追问，信息更准；但每次追问都是一次 vision 请求，且主模型不知道图里有什么时很难问对问题。先做自动描述，以后有需要再加工具，两者可以共存。
- **未配置的角色一律回落到主对话模型**（路线图原文）：`task` 与 `smol` 采用（标题请求极小，回落代价可以忽略）；`vision` 回落没有意义，主模型本来就不能看图。
- **角色配置带思考档位**：多一个维度，界面和校验都更复杂，目前没有明确需求，不做。
- **一次性加入 slow、plan、commit 等角色**：Nocturne 目前没有对应的功能入口，配置了也用不上，不做。
