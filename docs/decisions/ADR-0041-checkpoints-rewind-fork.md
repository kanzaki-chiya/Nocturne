# ADR-0041：检查点、回退与会话分叉

- 状态：已接受
- 日期：2026-10-02

## 背景

[路线图](../roadmap/roadmap.md) v0.6 要求：模型改坏了文件或走错了方向时，能退回到某一轮之前，同时恢复对话与文件；也能从某一轮岔出新会话尝试另一种做法。[sessions.md](../architecture/sessions.md) 第 9 节把分叉与回退列为「可以在事件日志模型上实现，届时单独写设计」，本文即该设计。

`/cost` 与检查点无关，且需要先扩充价格数据，拆到单独的 ADR。

现状中可以直接利用的机制：

- 会话日志只追加、状态由折叠得到（sessions.md 第 2 节），回退可以表示为一个新事件，不需要改写历史。
- 文件改动工具在 `permissionSubjects` 里声明 `edit` 主体（`edit`、`write`、`apply_patch` 都如此，[tool-api.md](../protocols/tool-api.md) 第 1 节）。执行器在权限允许后、调用 `execute` 前已经拿到解析后的路径，按这个声明记录检查点，不需要按工具名分支。
- `traits.mutates` 标出可能改变外部状态的工具，可以用来提示「有未追踪的改动」。

## 决定

### 1. 检查点：记录每轮被改动文件的原始内容

- **单位是轮**：一轮从一条持久化 `message.user` 开始，到下一条 `message.user` 之前结束（包括其中的全部 Turn 重试与工具调用）。
- **何时记录**：执行器在一次工具调用通过权限、即将调用 `execute` 时，取该调用解析后的全部 `edit` 主体路径；对本轮内**第一次**被触碰的路径，读取当前内容作为该轮的原始内容。同一轮里之后再改同一文件不再记录。
  - 文件不存在时记为「原本不存在」，回退时删除。
  - 目录、超过 10 MB 的文件、读取失败的文件记为「未追踪」并附原因，发 `runtime.warning`（`checkpoint_untracked`），工具照常执行。
- **何时记录改动后状态**：工具调用结束（无论成功失败）后，对同一批路径计算一次内容哈希，写入改动后状态，供回退时判断文件是否在 Nocturne 之外又被改过。
- **子代理**：子会话与父会话共享工作区，子会话里的文件改动记到**根会话**当前这一轮，事件写在根会话日志里并带 `sessionId` 标明来源。子会话自己的日志不记录检查点。
- **存储**：原始内容按 sha256 去重保存到 `<sessionsDir>/checkpoints/<sessionId>/<sha256>`，与落盘附件同样由用户管理，运行时不自动清理。会话数据不写入被操作的仓库。
- **不追踪的改动**：`shell`、MCP 工具和其他没有声明 `edit` 主体的工具造成的文件改动无法追踪。回退预览里如实列出这一轮之后有几次这类调用（按 `traits.mutates` 为真且没有 `edit` 主体统计），不尝试猜测它们改了什么。

### 2. 回退

- **入口**：
  - `/rewind` 命令；
  - 空闲、输入框为空、没有弹层或补全列表时，600ms 内连按两次 Esc。Turn 进行中 Esc 仍是中断，不触发回退。
- **轮次列表**：全屏页面，列出当前有效对话中的全部用户消息，最新的在最上面。每行显示用户消息首行、相对时间，以及「改动 N 个文件」（按下文的文件还原规则统计），之后有未追踪调用时加「含 shell」。↑↓ 选择，Enter 打开操作对话框，Esc 返回。全屏下单击行选中、单击已选中的行等同 Enter，沿用 [ADR-0039](ADR-0039-welcome-provider-dialogs.md) 的列表点击规则；`--inline` 只用键盘。
- **操作对话框**（[ADR-0030](ADR-0030-dialog-settings-pages.md) 的 `DialogFrame`），标题「回退到这一轮之前」，按钮竖排：
  1. `对话和文件一起回退`
  2. `只回退对话`
  3. `只还原文件`
  4. `从这里分叉新会话`（见第 3 节）
  5. `取消`

  按文件还原规则没有可还原的文件时，1、3 两项灰显，并在下方说明「这一轮之后没有可还原的文件」。
- **预览与确认**：选定 1–3 项后进入确认对话框，列出将发生的事：
  - 每个文件一行：`还原`、`删除`（原本不存在）、`无法还原（<原因>）`（未追踪）；当前内容与最后记录的改动后状态不同时，加标记「已在外部修改」，确认后仍会被覆盖；
  - 有未追踪调用时加一行说明「这一轮之后有 N 次 shell/MCP 调用，它们造成的改动不会被还原」；
  - 只回退对话时说明「文件保持当前状态」。

  按钮 `[ 取消 ] [ 回退 ]`，默认焦点在「取消」。
- **文件还原规则**：取日志中 `seq` 大于目标消息的全部 `phase: "before"` 检查点（包括此前「只回退对话」去掉的轮次，因为那些改动仍留在磁盘上），每个路径取最早的一条原始内容作为还原目标：
  - 原始内容存在 → 按保存的字节写回；
  - 原本不存在 → 删除该文件（文件已不存在则跳过）；
  - 未追踪 → 不动，计为失败项。

  单个文件失败不中断其余文件，结果逐个写入事件并显示。还原文件是用户发起的操作，不经过权限层；它只会写回检查点里记录过的路径，而这些路径当初都已经通过了权限判定。
- **对话回退规则**：对话回退到目标用户消息之前，即这条消息及其后的全部对话从模型历史和界面上去掉。
  - 会话配置（模型、权限预设、思考档位、shell）保持当前值，不随回退改变。
  - 累计用量不减少，已花的钱不会因为回退而退回。
  - 任务清单、生成标题、图片描述按回退后的事件重新得出：任务清单恢复到目标消息之前的状态；标题保留。
  - 回退后把目标消息的文字放回输入框，方便修改后重发；图片附件不放回，输入框下方提示一次「原消息的图片未放回」。
- **只还原文件或只回退对话时，告诉模型**：
  - 只还原文件：在历史中追加一条 `note`：「用户把以下文件还原到了某一轮之前的状态：<路径列表>」，避免模型以为改动还在。
  - 只回退对话：在回退点追加 `note`：「对话已回退，但文件保持回退前的状态，可能包含已撤销对话中的改动」。
  - 两者一起回退时不需要 note。
- **只能在空闲时回退**：Turn 进行中、压缩进行中，`/rewind` 提示「请先等待或按 Esc 中断」。
- **回退后的显示**：
  - 全屏模式按回退后的视图重排对话，在末尾显示一行通知 `已回退到「<目标消息首行>」之前 • 还原 N 个文件`（失败时加 `• M 个失败`）。
  - `--inline` 已写入回滚区的内容无法撤回，只打印同样的通知行，之后的对话从回退点接续。
- **多次回退**：每次回退都基于当前有效时间线。回退之后的新对话可以再次回退，回退到更早的轮次也可以；被回退掉的轮次不再出现在轮次列表里。本 ADR 不提供「撤销回退」，日志里的原始事件仍完整保留。

### 3. 会话分叉

- **入口**：
  - 回退操作对话框的「从这里分叉新会话」：新会话的对话停在目标消息之前，目标消息文字放进新会话的输入框；
  - `/fork`：从当前位置分叉，新会话包含当前全部对话。
- **实现**：复制原会话日志里的全部持久化事件，第一行换成新的 `session.created`（新 id，增加 `forkedFrom: { sessionId, seq }`），其余事件的 `seq` 与内容保持不变，这样图片描述、压缩边界、回退点等按 `seq` 的引用全部有效。从中间某一轮分叉时，再在末尾追加一条只回退对话的 `session.rewound`。
  - 落盘附件与检查点目录一并复制到新会话 id 下。
  - 子会话日志不复制，新会话里已完成的 `task` 结果照常显示，但不能再按子会话 id 恢复到新会话下。
- **文件**：分叉不改动任何文件，两个会话共享同一个工作区。从中间某一轮分叉时，确认对话框说明「文件保持当前状态；需要文件也回到那一轮，可在新会话里再执行只还原文件的回退」。
- **切换**：分叉成功后当前客户端切换到新会话，切换语义与 `/resume` 相同（[tui.md](../apps/tui.md) 第 6 节）；原会话关闭并释放锁，不受影响，可以随时 `/resume` 回去。
- **标题**：新会话沿用复制来的标题。`/resume` 列表在分叉会话的行上加「分叉」标记；不为分叉重新生成标题。

### 4. 事件与接口

- 新增两个持久事件：
  - `checkpoint.file`：`callId`、`path`（绝对路径）、`phase: "before" | "after"`、`sessionId?`（来自子会话时）。
    - `phase: "before"` 时带 `before: { sha256, size } | null | { untracked: string }`（`null` 表示原本不存在；`untracked` 是原因）；
    - `phase: "after"` 时带 `sha256: string | null`（`null` 表示调用后文件不存在）。
  - `session.rewound`：`targetSeq`（目标 `message.user` 的 seq）、`mode: "both" | "conversation" | "files"`、`files: { path, result: "restored" | "deleted" | "skipped" | "failed", reason? }[]`。
- `session.created` 增加可选字段 `forkedFrom: { sessionId, seq }`。
- 旧版本遇到不认识的持久化事件类型会拒绝恢复（[events.md](../protocols/events.md) 第 8 节），不会把回退过的日志读成错误的对话，因此不提升 `formatVersion`。
- **折叠**：`foldEvents` 与客户端视图归约器按同一规则处理，重放结果与在线一致：
  - `session.rewound` 的 `mode` 含对话时，把有效历史截到 `seq < targetSeq` 的条目，任务清单、图片描述等派生状态按截断后的事件重新计算；之后追加的事件继续接在截断后的历史上；
  - `mode` 为对话或文件之一时，按第 2 节插入 `note` 历史条目；
  - `checkpoint.file` 不进入模型历史，也不出现在对话视图里。
- **Session API**：
  - `rewindTargets()`：返回当前有效对话中的用户消息列表，每项带 seq、首行、时间、将还原的文件及状态、未追踪调用数；
  - `rewind(targetSeq, mode)`：执行回退，返回逐文件结果。非空闲时返回 `session_busy`；目标不是当前有效对话中的用户消息时返回 `invalid_command`。
- **Runtime API**：`forkSession(sessionId, { targetSeq? })`：生成新会话并返回其 id；客户端随后按 `/resume` 的流程打开它。
- 命令表新增 `/rewind`、`/fork`，`/help` 与斜杠补全同步。

## 后果

- 模型改坏文件时可以一步退回，不依赖 git；回退和分叉都只追加事件或复制日志，原始记录始终完整保留。
- `edit`、`write`、`apply_patch` 以及以后新增的、声明了 `edit` 主体的工具自动获得检查点，执行器与 Agent Loop 不按工具名分支。
- shell 改动无法还原，只能如实提示；习惯用 shell 改文件的模型（例如用 `sed` 编辑）在回退时会留下未还原的改动。
- 每轮第一次改动一个文件时多一次读文件和一次哈希，检查点目录会随会话增长；大文件超过 10 MB 不追踪。
- 需要同步 sessions.md（第 2、3、9 节）、events.md、view.md、tools.md（执行器流程）、context.md（note 条目）、tui.md（命令表、Esc 规则、轮次列表与对话框）和 cli.md（逐行 REPL 的 `/rewind` 与 `/fork`）。

## 备选方案

- **用 git 做检查点**（每轮自动提交或 stash）：能顺带覆盖 shell 改动，但会污染用户的仓库历史与暂存区，非 git 目录也用不了；会话数据不写入被操作仓库的原则也不允许。不采用。
- **回退时改写日志、截掉后面的事件**：实现直观，但破坏「只追加」的保证，崩溃时可能丢数据，也无法再查看被回退的内容。不采用。
- **分叉时重新编号 `seq`**：日志更紧凑，但图片描述、压缩边界等按 `seq` 的引用都要改写，容易出错。复制原 `seq` 只多存一些被回退掉的事件，可以接受。
- **每次工具调用都完整快照工作区**：能追踪 shell 改动，但大仓库下代价不可接受。
- **回退只提供「对话和文件一起」一种方式**：实现更简单，但想保留改动只重聊、或只撤销文件改动时做不到。按维护者决定提供三种方式。

## 修订

- 2026-10-03：第 3 节「文件」一条的提示与第 2 节冲突：从中间某一轮分叉后，目标消息已不在新会话的有效对话里，无法在新会话里对它执行「只还原文件」。提示改为「文件保持当前状态；需要文件也回到那一轮，可在原会话里对同一轮执行「只还原文件」」。两个会话共享工作区，在原会话里还原效果相同；回退目标仍限于当前有效对话中的用户消息，规则不变。
- 2026-10-07：桌面端消息操作入口（问题报告 U-01）。会话正文里每条用户消息在悬停时显示「复制」「编辑并重发」「重发」三个按钮。「复制」随时可用，复制消息原文。另外两个只在空闲时可用，忙时置灰并提示「请先等待或按 Esc 中断」：「编辑并重发」把消息变成原位编辑框，「重发」直接用原文；两者都在发送时先调用 `rewind(targetSeq, mode)` 回退到这条消息之前，再 `submit` 新内容。编辑框内列出将撤回的回复轮数和将还原的文件（取自 `rewindTargets()`），提供「对话和文件」（默认，对应 TUI 对话框第 1 项）与「仅对话」两个选项；没有可还原的文件时不显示选项。编辑期间旧回复变暗，发送成功后才移除；回退失败时保留编辑内容并显示错误。「只还原文件」和「分叉新会话」暂不进入桌面端，`/rewind`、`/fork` 在桌面端的提示不变。附件、`@文件` 快照和技能/委派快照不随「重发」复用：重发只取消息文本，编辑框同样只编辑文本。
- 2026-10-08：桌面端本轮文件更改汇总。检查点在工具调用结束后也保存改动后的文件字节（同一目录，按 sha256 去重，`checkpoint.file` 字段不变），用于计算每轮的净 diff；旧会话没有这份字节，相应文件只列路径不显示计数。桌面端在每轮回复末尾显示该轮改动文件与增删行数，最新一轮提供「撤销」，确认后执行 `rewind(本轮用户消息, "files")`，即第 2 节的「只还原文件」，对话保留并按第 2 节给模型追加 note。较早的轮不提供撤销，因为还原会连带撤销之后各轮的改动。逐文件撤销不在本次范围。接口见 sessions.md「每轮文件改动」。
