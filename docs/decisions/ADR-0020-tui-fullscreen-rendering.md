# ADR-0020：TUI 全屏渲染模型

- 状态：已接受（2026-09-26 验收，随 0.3.0 发布）
- 日期：2026-09-26

## 背景

v0.3 第一版的主界面把已完结条目写入终端 scrollback（ADR-0010 的 `<Static>`），模型选择页与服务商页再逐页进出备用屏幕（ADR-0017，ADR-0019 把范围扩到两个页面）。用户希望启动即进入备用屏幕，由 TUI 自己管理对话滚动和底部输入/状态区，页面切换不再切屏。

约束不变：Windows Terminal 与 conhost 都要能用；中文与输入法是一等公民；渲染层仍可替换，Core 不依赖 UI。

## 决定

**主界面启动即使用 Ink 自带的备用屏幕，增量渲染，帧高始终为终端行数减 1。** 这取代 ADR-0010 里「`<Static>` 写入主屏 scrollback」的渲染模型，以及 ADR-0017 的逐页备用屏幕方案。Ink + React 的技术选型不变（ADR-0010 的选型部分仍然有效）。

- `render` 选项为 `incrementalRendering: true` 与 `alternateScreen: true`。进入备用屏幕用 Ink 自己的选项，不手写 `?1049h`。
- 帧高等于 `rows - 1`。帧高一旦大于或等于终端行数，Ink 会整屏清空，造成闪烁。
- 对话区只布局、只渲染可见行。欢迎区是对话的第一项，随滚动离开。不再用 `<Static>` 往主屏 scrollback 写内容。
- 不开启鼠标上报，保留终端原生选中复制。滚轮暂不处理。
- 模型选择页、服务商页（含配置向导）、`/resume`、`/context` 等是同一全屏里的页面或浮层，不再逐页进出备用屏幕。打开和关闭浮层不清除输入框里已有的文字。
- 退出（`/exit`、Ctrl+D、空闲时 Ctrl+C、未捕获异常）先恢复主屏幕，再打印「会话 \<id\> 已保存，nctrn -c 继续」。异常路径也恢复，不把用户留在备用屏幕里。
- 硬件光标放在当前有焦点输入行已输入文字的末尾；主输入、模型搜索、服务商过滤及向导表单复用显示宽度定位（中文占 2 列）。输入法预编辑和候选窗跟着硬件光标，不跟着 Ink 默认画在输出下方的位置。光标不走 Ink 的 `useCursor`：它只在调用组件重渲染的那一帧生效，父组件后提交会覆盖浮层坐标，其他组件单独刷新时光标会被藏到帧底。改为输入框登记坐标，`runTui` 包装传给 Ink 的 stdout，每次写完后保存 Ink 的光标位置（DECSC）、移到登记坐标并显示，下次写之前恢复（DECRC）；退出备用屏幕后不再干预。翻阅提示的状态文案见 [tui.md](../apps/tui.md) 第 2 节。

交互、状态栏与补全的规格见 [tui.md](../apps/tui.md)。逐行 REPL 的补全与退出提示见 [cli.md](../apps/cli.md)。

## 第 0 步实测

独立原型以 1000 条模拟事件、可见窗口、20 Hz 状态刷新和自动滚动，对比默认渲染与增量渲染。统计的是每帧写入字节数和逐行擦除（`ESC[2K`）次数。运行期间没有出现 `ESC[2J`。conhost 不支持 `?2026` 同步输出，Ink 仍会发出这个序列，属于正常现象。

| 终端 | 模式 | 平均字节/帧 | 平均逐行擦除/帧 |
|---|---|---:|---:|
| conhost 80×25 | 默认 | 1303 | 33.24 |
| conhost 80×25 | 增量 | 408 | 7.88 |
| Windows Terminal 120×30 | 默认 | 1700 | 39.47 |
| Windows Terminal 120×30 | 增量 | 526 | 9.61 |

人工验收：conhost 不闪烁，翻页与缩放窗口正常。中文输入法最初失败，原因是拼音预编辑落在输入框下方；把硬件光标放到 `›` 后输入文字的末尾之后复测通过。后来发现 `/model` 搜索框里候选窗仍落在主输入行，原因是 `useCursor` 的父子提交顺序，改为上述登记加补位后，在 Windows Terminal 与 conhost 用微软拼音实测主输入、`/model` 搜索、`/provider` 过滤三处，候选窗都紧贴输入位置。

## 后果

- ADR-0010 的 `<Static>` scrollback 模型、ADR-0017 的逐页切屏不再是当前客户端行为。两篇正文不改，索引标明部分被本 ADR 取代。
- 不再需要 `suspendTerminal` 切屏，也不再需要 Windows stdin 饿死补丁。
- 长会话的成本取决于可见行，而不是历史条目总数。
- 备用屏幕内没有终端 scrollback；复制靠终端原生选中。退出后主屏只留下恢复提示。
- 浮层里的输入法光标也须按显示宽度放置；所有文本输入共用定位辅助，不更换渲染方案。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| Ink 增量渲染 + 自带备用屏幕 + 帧高 `rows - 1` | **采用** | 第 0 步在两种终端上字节与擦除都明显下降，且没有整屏清除；输入法靠硬件光标定位复测通过 |
| 继续 `<Static>` scrollback，只给少数页面切备用屏 | 否决 | 页面切换要进出备用屏幕；长会话把历史全部交给终端，和「TUI 管理滚动」的目标相反 |
| 自研行级 diff ANSI | 保留为退路 | 第 0 步没有出现不可接受的清屏或闪烁，不必换渲染方案 |
