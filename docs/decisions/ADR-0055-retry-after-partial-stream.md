# ADR-0055：流式输出中途失败时丢弃部分输出并重发

- 状态：已接受
- 日期：2026-10-12

## 背景

维护者使用 ChatGPT 账号（`chatgpt` / `gpt-6.1-sol`，Responses 协议）执行长任务时，偶发响应流中断并结束整个 Turn。按维护者已核对的会话日志：

- `202610120101-e2ffec07.jsonl` 第 267–268 行：第 52 步，TTFT 5.5 秒，收到 456 字推理摘要后静默约 156 秒断流；部分消息以 `finishReason: "aborted"` 保存，只有 reasoning、没有工具调用，Turn 以 `error` 结束。
- `202610090613-db9ef703.jsonl` 第 366 行：第 54 步，请求发出 20 秒后报同样的流中断错误，没有保存部分消息。

Responses 适配器要求收到 `response.completed` 才算完成，缺失时抛可重试的 network 错误是正确的。旧的 Agent Loop 规则却只在尚未产生输出时重发：原意是避免重复文字与工具调用，[ADR-0014](ADR-0014-stream-timeout-empty-response.md) 也沿用了这个限制，导致已有几十步进展的任务只能由用户手动发送「继续」。连接已开始响应却仍提示「服务地址不通」和 `nctrn setup`，也会误导排障。

## 决定

普通 Step 的可重试 `ProviderError` 无论是否已产生输出，都受同一 `retryLimit` 和指数退避规则控制。每次重发丢弃本次尝试的全部内容、usage、计时和工具参数累积；保留同一 `messageId`，新尝试从空开始，工具 `callId` 重新分配。不按服务商、模型或工具名判断。

这在当前生命周期下是安全的：assistant 的增量仅是临时事件，完整消息在流收束后才持久化；工具只有完整响应落盘后才执行。丢弃失败尝试不会重复持久化消息、也不会重复执行工具。用户中断、不可重试错误及空响应处理保持原规则；重试耗尽时保存最后一次尝试的部分输出，以 `error` 结束 Turn。

`provider.retry` 增加兼容可选字段 `discarded?: { messageId: string; callIds: string[] }`，仅在可重试 Provider 错误已有输出并丢弃时出现。`callIds` 是该次尝试已通过 `tool.input.delta` 发布的调用 ID。Core view 收到后移除对应 live assistant 和 tools。若客户端漏掉该临时事件，后续增量暂时会接到旧文本上，但 `message.assistant` 落盘时移除同 ID 的 live 条目，以持久 `content` 为准；Turn 收尾还会清空 live。无需提升日志格式版本，精确契约见 [events.md](../protocols/events.md) 和 [view.md](../protocols/view.md)。

TUI 的流式内容只留在可重绘的 live 区，`--inline` 不再提前把已完成的 Markdown 块写进 Static；落盘后才写回滚区。丢弃时提示「响应流中断，已丢弃部分输出，第 N/M 次重试」。CLI 已写出的文本无法撤回，另起一行说明「已丢弃上面的部分输出」及等待时间、次数。桌面端复用 Core view，无需单独改动。

最终 network / timeout 失败且本次尝试已产生输出时，提示「服务商响应流中途断开，已重试 N 次仍失败：<原因>。可发送「继续」接着做」，保留原错误码；连接阶段失败仍用旧提示。`provider.error` 诊断增加 `producedOutput`，区分本次尝试的阶段。

据维护者提供的对照，Codex CLI 对同类服务也会在断流后丢弃部分输出并重连重发，默认最多重试 5 次；本项目沿用自己的既有次数配置，不引入新的配置项。

## 后果

- 长任务可自动恢复偶发断流，之前已完成的 Step 不受影响。
- 重发会再花一次输入 token；缓存命中时输入代价较小，但失败尝试仍可能被上游计费。会话用量仍只统计落盘消息，不宣称涵盖失败尝试的账单。
- 已显示的文字会被撤回；CLI 的作废文字仍留在终端，只能通过提示澄清。
- `--inline` 长回复在完成前只有活动区尾部可见，不能提前通过终端回滚区查看流式前缀；这是保证可撤回的必要取舍。
- 该安全性依赖工具执行和消息持久化时机；未来如加入边流边执行，必须重新评估，不能直接沿用本决定。

## 备选方案

- 保持「已有输出不重发」：避免撤回显示，但将可恢复的网络故障变成整轮失败，不采用。
- 把失败尝试持久化后再重发：污染模型上下文且增加重复调用风险，不采用。
- 仅针对 ChatGPT / Responses 重试：协议差异应由适配器归一化，不在 Agent Loop 加服务商分支。
