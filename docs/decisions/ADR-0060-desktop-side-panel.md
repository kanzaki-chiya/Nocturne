# ADR-0060：桌面端右侧面板——变更、文件、终端、内置浏览器

- 状态：已接受
- 日期：2026-10-17
- 修订：[ADR-0046](ADR-0046-desktop-tauri.md) 2026-10-08「文件引用改为左键打开」中预留的内置编辑器与内置浏览器，在本 ADR 落地

## 背景

路线图「之后」一节列了桌面端侧边栏面板（内置编辑器、终端、内置浏览器），ADR-0046 也把文件引用的侧边预览留给它。维护者 2026-10-17 给出参照：Codex 桌面端的右侧面板。它的要点如下：

- 主窗口右侧有一个可开关的面板，顶部是标签栏，「＋」新建标签；
- 新标签页本身就是浏览器：上方是地址栏（「搜索或输入网址」），下方列出工具入口，包括「变更」（Ctrl+Shift+G）、「文件」（Ctrl+P）、「终端」（Ctrl+`）；
- 点开工具会在新标签里打开对应视图。

维护者明确：要浏览器、文件、终端，以及 Codex 里的「变更」；「侧边聊天」暂时不需要。Codex 标题栏还有一个会话概览浮层（项目名、本会话变更总数、运行中的子代理），维护者要求照做；Claude 桌面端那种常驻右侧栏不做，因为上下文、MCP 等信息已经在底部状态栏。

现状可以复用的部分：会话的本轮改动（`session.turnChanges` / `turnChangeDiff`）和 `TurnChangesCard` 的 diff 渲染；文件索引（`session.fileIndex`，`@` 引用在用）；路径解析（`session.resolveFiles`）；Shell 设置（`listShells`，pwsh / Git Bash / cmd）；外部编辑器打开（`open_in_editor`）。

## 决定

### 1. 面板与标签

- 标题栏右侧加一个面板开关按钮（Ctrl+B）。面板在对话区右边，中间的分隔条可以拖动调宽，宽度和开关状态存在应用数据里，不进 `settings.json`。主区太窄时（对话区小于 480px）面板改为盖在对话区上方，不再挤压。
- 面板顶部是标签栏：标签可关闭、可拖动排序，「＋」新建标签（Ctrl+T）。
- **新标签页**和 Codex 一样：上面是地址栏，输入网址或本地路径后，这个标签就变成浏览器；下面是「工具」列表，第一版只有「变更」「文件」「终端」三项，每项显示快捷键。不做「推荐」网站列表，也不做「更多工具」。
- **标签和上下文的关系**：
  - 「变更」跟随当前打开的会话，切换会话时内容跟着换；
  - 「文件」和「终端」在创建时绑定当时会话的工作区，标签上显示项目名，切换会话不影响它们；
  - 浏览器不绑定会话。
- **会话概览浮层**：标题栏面板开关左边加一个概览按钮，点开是一个小浮层（照 Codex），内容自上而下见下面各条。**浮层不遮挡对话文字**：面板关着时，浮层停在对话区右侧的空白里，一直开着，直到再点按钮或按 Esc；窗口不够宽时，对话列和输入框往左让出浮层的位置（缩窄也行，但不和浮层重叠）。面板开着时，对话区右边没有空白，浮层盖在对话区上。不管哪种情况，浮层都只由按钮和 Esc 开关：开关面板、点浮层里的项目都不关它。开关状态记在本机偏好里。内容自上而下：
  - 第一行是项目名（会话工作区的目录名，悬停显示完整路径）；
  - 「变更」一行，行尾是本会话累计的 +N −M，点击在面板里打开「变更」标签；本会话还没有改动时这一行置灰；
  - 「子代理」分组，列出本会话正在运行的子代理（档位、任务摘要、已运行时间），点击在面板里打开它的「子代理」标签（见第 6 节）；没有运行中的子代理时不显示这一组。这一组在第 4 轮实现。
  - 不放上下文、MCP、模型这些底部状态栏已有的信息，也不做 Codex 的「来源」。
- 标签存在应用数据里（不进 `settings.json`）。重启后恢复「文件」和浏览器标签，重新打开同样的文件和网址；文件已不存在时标签显示「文件已不存在」。「变更」标签按当前会话恢复。终端标签不恢复，进程随应用退出已经结束。

### 2. 变更

- 汇总当前会话所有轮次的文件改动，布局照 Codex：左边是 diff，右边是按目录折叠的文件树，标出每个文件的增减行数，树上方有筛选框；面板太窄时文件树改到 diff 上方。点文件后 diff 滚到那个文件。数据来自现有的 `turnChanges` / `turnChangeDiff`，diff 复用 `TurnChangesCard` 的渲染组件。
- 本轮改动卡片的标题行加一个「查看变更」按钮（Codex 同款），在面板里打开这个标签并定位到那一轮；卡片里单个文件的 diff 展开方式不变。
- 只读，不在这里撤销。撤销仍然用卡片上的「↶ 撤销」，避免多一个入口带来不一致。

### 3. 文件

- Ctrl+P 打开快速搜索，复用 `fileIndex`；选中后在「文件」标签里打开。
- 第一版是**只读查看器**：带语法高亮和行号，能定位到指定行并高亮，支持搜索（Ctrl+F）。图片直接显示；二进制文件和超过大小上限的文件只给「在外部编辑器打开」和「在资源管理器中显示」。
- 读取文件新增只读 RPC `session.readFile { path }`：按会话工作区解析路径（规则同 `resolveFiles`），只允许读工作区内的文件，返回文本或图片，有大小上限（暂定 2 MB）。这个接口是给用户看自己的文件用的，不是 agent 工具，不经过权限层。
- **不在远程白名单里**：手机端暂时不开放（ADR-0052 的远程能力白名单不变），以后另议。
- 回答里的文件引用照 ADR-0046 2026-10-08 的修订：工作区内的引用，左键在面板里打开并定位行号（HTML 在浏览器里打开，其余文件在「文件」标签打开）；外部程序和「在资源管理器中显示」放在右键菜单。「设置 › 常规 › 打开文件用」增加一个选项「Nocturne 面板」，设为默认值；升级时已有的选择也统一改成它（左键默认就在面板里打开，不需要右键），习惯用 VS Code 的人可以在设置里改回去。内置浏览器做好之前，HTML 引用左键在「文件」标签里看源码。
- 第一版不能编辑。要编辑就得处理和 agent 同时改同一个文件的冲突，以及保存后对接「变更」，工作量和风险都明显变大；以后需要时另行设计。

### 4. 终端

- 前端用 xterm.js。终端进程（pty）放在 **Tauri 外壳（Rust）**，用 `portable-pty`（Windows 上走 ConPTY）实现，不放在 Node 后台：后台随附的是官方 Node，引入 `node-pty` 这类原生模块，打包和升级都更麻烦；终端本来也只服务电脑前的用户。代价是手机以后要用终端，需要另行设计。
- Shell 沿用「设置 › 常规 › Shell」（pwsh / Git Bash / cmd），工作目录是标签绑定的工作区。
- 一个标签一个终端进程，关闭标签就结束进程；应用退出时结束所有进程。
- 终端是用户自己的终端，**agent 看不到也操作不了**，和 agent 的 `shell` 工具完全分开，不经过权限层。以后如果要「把终端输出发给 agent」，另行设计。

### 5. 内置浏览器

- 用 Tauri 的**子 webview**（`Window::add_child`）嵌在面板标签的位置上；Windows 上就是 WebView2。窗口大小、面板宽度和标签切换变化时，同步调整它的位置和尺寸；切到别的标签时隐藏。
- `add_child` 在 Tauri 2.12 里需要开 `unstable` 特性（已在 `tauri-2.12.0/Cargo.toml` 和 `src/webview/mod.rs` 核实），所以**第 3 轮先做探针**，确认以下几项后再实现：位置跟随、DPI 缩放、焦点和键盘快捷键、中文输入法、弹窗和下载、开关面板时没有闪烁。探针不通过的备选方案是单独开一个浏览器窗口（普通的 Tauri 窗口，稳定 API）。
- **已知限制**：原生 webview 会盖住同一位置的网页内容，所以主界面的下拉菜单、对话框一旦伸进面板区域，就会被浏览器挡住。对策是：打开这类浮层时，临时把浏览器换成一张截图占位；或者让浮层避开面板区域。这一点由探针确认用哪种。
- **隔离**：浏览器 webview 不注入任何 Tauri IPC，也不授予任何 capability，网页代码调不到外壳命令。它的 cookie 和存储放在独立的数据目录，和主界面分开。
- 工具栏：后退、前进、刷新、地址栏、在系统浏览器中打开、开发者工具。本地 HTML 用 `file://` 打开；工作区内的 HTML 引用左键就在这里打开。
- 下载走系统的另存为对话框，不自动保存。

### 6. 子代理标签

- 概览浮层里点运行中的子代理，或者点对话里子代理工具行上的「在面板中查看」，在面板里打开这个子代理的标签，实时显示它的过程：思考、工具调用、输出，渲染方式和主对话一致，只读，不能在这里给子代理发消息。
- 标签名是档位加任务摘要；子代理结束后标签保留，显示最终结果和耗时，直到用户关闭。
- 数据来自子会话自己的事件流。现在桌面端只在父会话的工具行里看到子代理的汇总，需要一个只读的订阅子会话事件的接口；具体接口在这一轮开始前补设计，写进 `protocols/rpc.md`。
- 不在远程白名单里，手机端以后另议。

### 7. agent 操作浏览器（单列一轮）

维护者的日常验收靠 BrowserOS 和无头 Chrome 截图；如果 agent 能直接操作面板里的浏览器，用户可以实时看着它打开页面、截图、点击，这是这个面板最大的增值。方案草案如下：

- Core 不能依赖 UI（AGENTS.md 硬性约束），所以不在 Core 里加浏览器工具。由桌面外壳在本机起一个 **MCP 服务器**，经 WebView2 的 DevTools 协议提供 `open`、`screenshot`、`click`、`type`、`read` 等工具；Nocturne 把它当成一个内置的 MCP 服务器接入。
- 这样权限就走现有的 `mcp` 规则和 `smart` 审查，不需要新增权限类别；截图、读取这类工具声明 `readOnlyHint`。
- 只有桌面端可用；子会话的权限照常收敛。

这一轮要做，排在最后，时间不急；进入这一轮前先补一份细化设计。

### 8. 不做

- 侧边聊天；
- Claude 桌面端那种常驻的会话信息栏，以及 Codex 概览浮层里的「来源」；
- 「推荐」网站列表和「更多工具」；
- 第一版的文件编辑；
- 手机端的面板。

## 实现计划

每一轮独立验收，截图要有：桌面宽窗口、窄窗口（面板盖在对话区上）、深浅两种主题。

1. **面板框架 + 变更 + 文件**：面板开关和宽度记忆、标签栏、新标签页、会话概览浮层（项目名和「变更」行）、变更标签、文件标签（只读）、Ctrl+P、`session.readFile`、文件引用左键在面板打开、「打开文件用」新增选项。新标签页的地址栏这一轮先占位，输入网址时用系统浏览器打开。
2. **终端**：Rust 侧 pty 命令与事件、xterm.js 标签、Shell 设置、进程生命周期。
3. **浏览器**：先做第 5 节的探针并写结论，再实现子 webview（或备选的独立窗口）、工具栏、浮层遮挡对策、HTML 引用打开。
4. **子代理标签**：第 6 节，先补订阅子会话事件的接口设计；概览浮层加「子代理」分组，子代理工具行加「在面板中查看」。
5. **agent 操作浏览器**：第 7 节，进入这一轮前先补一份细化设计。

## 维护者确认（2026-10-17）

- 重启后恢复「文件」和浏览器标签，终端不恢复（第 1 节）。
- 第一版文件只读（第 3 节）。
- agent 操作浏览器要做，排在最后（第 7 节）。
- 照 Codex 加会话概览浮层，不做常驻信息栏；运行中的子代理在浮层里列出，点开在面板里看过程（第 1、6 节）。

## 备选方案

- **终端放在 Node 后台（node-pty）**：好处是以后手机也能用；但随附 Node 要带原生模块，每次升级 Node 都要重新编译，打包和自动更新都更脆弱。不采用，手机终端以后单独设计。
- **浏览器用 iframe**：实现最简单，但大部分外部网站禁止被嵌入（`X-Frame-Options` / CSP `frame-ancestors`），只能看本地 HTML，达不到「像 Codex 那样打开网页」的目标。不采用。
- **浏览器直接用独立窗口**：API 稳定，但体验和「面板里的标签」差很多。保留为第 3 轮探针不通过时的备选方案。
- **编辑器用 Monaco**：功能最全，但体积大（几 MB），只读查看用不上它的大部分能力。第一版倾向用 CodeMirror 6（按需加载语言包），具体在第 1 轮实现时确定，写进 `docs/apps/desktop.md`。

## 修订

### 2026-10-18：工作区外的文件也在面板打开，读取改为 runtime 级

维护者实测第 1 轮时发现，回答里引用工作区外的文件（例如兄弟目录里的报告）左键只能开菜单，看不了内容。面板是只读查看器，不会运行文件，ADR-0046 防止误点可执行文件的顾虑对它不成立；第 1 轮报告也指出没有打开会话时「文件」标签读不了文件。因此修订第 3 节：

- **工作区外的文件也能在面板打开**：「打开文件用」是「Nocturne 面板」时，工作区外存在的文件左键同样在「文件」标签只读打开，标签显示所在目录名而不是项目名；右键菜单保持现状并加上「打开」。选「系统默认」时，工作区外的文件仍然只开菜单，ADR-0046 防误运行的规则不变；选 VS Code / Cursor 时照常交给编辑器。
- **读取改为 `runtime.readFile { path }`，取代 `session.readFile`**（后者未发布，直接替换）：只接受绝对路径，不依赖会话，所以没有打开会话也能读；「文件」标签内部存绝对路径。可读范围放宽为本机任意存在的普通文件，其余限制不变：词法检查（控制字符、备用数据流、设备名）、按真实路径判断类型、2 MB 上限整份拒绝、二进制不显示。**拒绝网络路径**（`\\server\share`、`\\?\UNC\...` 等 UNC 形式）：回答内容来自模型，点击 UNC 路径会让系统向那台主机发起 SMB 连接并带上 Windows 凭据，属于外泄风险。前端对网络路径的引用也不链接化。
- **仍然只给本机**：不进远程白名单，手机读不到；不是 agent 工具，不经过权限层。理由是它只把内容显示给电脑前的用户，用户本来就能读这些文件，agent 拿不到内容。
- 「变更」标签的文件列表改为一个文件一行（汇总所有轮次的增减行数），展开后按轮次列出各自的 diff，不再同一文件按轮重复出现。
- 第 4 节写的「Shell 沿用设置 › 常规 › Shell」与现状不符：设置里没有全局 Shell 项，Shell 是会话级的（状态栏 Shell pill）。终端默认用 `runtime.listShells` 按 `auto` 规则选出的第一个可用 shell，终端标签头部给一个 Shell 下拉，可以换成 pwsh / Git Bash / cmd 中已安装的一种，换了就结束旧进程、在同一标签里开新进程。
