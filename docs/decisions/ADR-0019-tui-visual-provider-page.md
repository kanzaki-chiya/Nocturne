# ADR-0019：TUI 视觉风格与服务商页重构

- 状态：提议
- 日期：2026-09-25

## 背景

v0.2 的 TUI 功能齐备但视觉朴素：没有品牌元素与启动摘要，状态栏是一行灰字，`/provider` 复用模型选择页（配置服务商要穿过模型列表），向导把"配置服务商"与"选择模型"两步耦合在一个流程里。参考对象 oh-my-pi 证明同类终端界面可以做到欢迎屏、全屏服务商管理页、彩色分段状态栏——本阶段借鉴它的交互与布局思路（不照搬 Logo、配色常量与文案），把 TUI 视觉与服务商管理重构为 v0.3。

同时 v0.2 遗留一个交互分裂：`nctrn` 进逐行 REPL、`nctrn --tui` 才进 TUI。TUI 已是成熟交互面，交互终端下应默认进入。

## 决定

### 1. `/provider` 与 `/model` 职责分离

`/provider` 只管理服务商（列表、添加、密钥、刷新、思考档位、删除），不再承担模型选择；模型选择只在 `/model` 打开的模型选择页进行（ADR-0017）。`/provider add|key|refresh|thinking|remove` 子命令保留为快捷方式，与页面操作走同一套 Core 编排，效果一致。

### 2. 服务商页：第二个备用屏幕页面

备用屏幕（alternate screen）的使用范围从"仅模型选择页"扩展为"**模型选择页与服务商页**"。这是对 ADR-0017 决定范围的修订：ADR-0017 已接受、正文不改，其中"且只有这一个页面"由本 ADR 扩展为两个同类页面；进出序列、`Ctrl+C` 恢复主屏、Windows 控制台 stdin 保护等实测约束完全沿用（见 ADR-0017「可行性验证」）。

页面规格（详见 [tui.md](../apps/tui.md) 第 8 节）：

- 顶部 Nocturne 像素 Logo（原创）+ 标题 + 副标题（说明可选择多个服务商配置、完成后按 Esc）；首次配置流程中显示"第 N 步，共 2 步"；
- 列表 = 5 个预设 + `providers.json` 及其他层已有的服务商条目；已配置显示绿色 `● 已配置` 与密钥来源（凭据后端 / 环境变量名 / 缺失）；
- `↑`/`↓` 移动、直接打字过滤、长列表滚动条、`Enter` 选中；
- 未配置预设：`Enter` 后**在同一页就地展开**配置步骤——（仅自定义预设）名称、服务地址 → 密钥（掩码输入；直接回车走环境变量路径并保留该选择）→ `GET /models`（只拉列表与限额，不发模型请求）→ 上游未声明思考能力时档位勾选（ADR-0018）→ 保存后回列表，底部一行结果显示（如"已保存 command，12 个模型"）；
- 已配置条目：`Enter` 后显示操作菜单——换密钥 / 刷新模型列表 / 调整思考档位 / 删除；删除需确认，当前会话正在使用的服务商拒绝删除，手写配置层的条目只读并提示去对应文件修改；
- 底部按键提示行；`Ctrl+C` 先恢复主屏再退出，不把终端留在备用屏幕。

### 3. 向导不再选择模型

`runProviderSetupWizard`（Core 编排，CLI 逐行向导与 TUI 共用）去掉"模型编号选择"与"设为默认模型？"两步：仍执行 `GET /models` 并把上游声明写回条目 `models`（ADR-0016），上游未声明思考能力时仍问档位勾选；保存即结束。`WizardResult` 不再含 `model`/`setDefault`，改为携带 `modelCount` 供结果行显示。模型选择统一由 `/model` 承担——服务商配置后用户的下一步是 `/model`。

逐行 CLI 向导在配置完第一个服务商后提示"用 /model 选择模型"；`/provider add` 会话内流程不再询问"切换当前会话到该模型？"。

### 4. 首次配置：服务商页 → 模型页的两步流程

- `nctrn setup` 在 TTY 下直接打开服务商页（第 1 步）；`Esc` 完成后若没有默认模型，自动进入模型选择页（第 2 步）设默认；两页头部都显示"第 N 步，共 2 步"。`nctrn setup` 仍是独立命令：流程结束即退出，不进入会话。
- 交互终端下运行 `nctrn` 而**没有任何已配置服务商**时，走同一两步流程——第 1 步完成后若无默认模型自动进第 2 步；选完模型即按该模型创建会话进入主界面。有服务商但没有可解析的默认模型时，直接进入第 2 步。`Esc` 放弃时退出并提示。
- `-c`/`--resume`/`--sessions`/`trust`/`untrust`/`-p` 不触发该流程（恢复与只读路径的失败语义不变）。
- 非 TTY 的一切入口保持逐行语义：`nctrn setup` 非 TTY 仍退出码 2 并提示手写配置；`--cli`（见第 6 条）的 `/provider add` 逐行向导按第 3 条裁剪。
- 流程中服务商页与模型页都在备用屏幕内运行；会话在流程结束后才创建（模型未定时会话无从建立），因此 TUI 的挂载形态扩展为"可选的延迟会话"：`runTui` 接受无会话启动形态，客户端注入 `openSession` 回调在拿到模型后完成装配（CLI 打开逻辑仍只有一份）。

### 5. 视觉系统

- **主题常量集中定义**（`theme.ts`）：语义角色（accent、muted、success、warning、error、选中态、状态栏各段色）集中在一处，组件不直接写死色值；`NO_COLOR`/`NOCTURNE_ASCII` 沿用 env 探测。
- **启动欢迎框**（主屏 `<Static>` 区，只画一次）：左栏像素 Logo + "欢迎回来" + 当前模型与服务商；右栏三块——操作提示（`/` 命令、Shift+Tab 思考档位、Ctrl+C 中断等）、MCP 服务器（名称与状态，失败标红附简短原因）、最近会话（最多 3 条：id 前缀、时间、首句摘要）。宽度 <80 列降级为单栏，<40 列不显示。
- **启动警告与通知**渲染在欢迎框下方、输入框上方，用醒目颜色分块（原来是提示区的 `!` 行）。
- **输入框**上下各加一条横线（替代原来裸露的单行提示符区域）。
- **状态栏**改为彩色分段、`·` 分隔：模型 · 思考档位 · 权限预设 · 目录 · 上下文占用（`已用/上下文长度`，上下文长度按 ADR-0016 的声明值，未声明时只显示已用量）；移除会话 id（欢迎框与 `/resume` 中可见）；Turn 进行中切档时思考段显示 `旧档→新档` 并变色，不再显示"（下一轮生效）"文字。
- **图标**只用 conhost 与 Windows Terminal 都实测可显示的字符；emoji 与 Nerd Font 未经双端实测不采用，先退回普通字符（沿用 `●`/`○`/`✓`/`✗`/`◇`/`›` 既有集合与新加像素块字符 `█`）。

### 6. 交互终端默认 TUI

- `nctrn`（含 `-c`、`--resume`）在 **stdin 与 stdout 均为 TTY** 时默认启动 TUI；新增 `--cli` 进入逐行 REPL；`--tui` 保留为兼容参数，与 `--cli` 互斥（同给出用法错误，退出码 2）。
- stdin 或 stdout 任一端**非 TTY** 时自动使用逐行模式——默认选择 TUI 不再导致退出码 2；显式 `--tui` 在非 TTY 下保持原语义（退出码 2 + 提示），`--cli` 与 `-p` 行为不变。
- `nctrn setup` 依同样的端点判定：TTY → 服务商页流程；非 TTY → 退出码 2。

## 后果

- `WizardResult` 形状变化：`model`/`setDefault` 移除，`modelCount` 新增；`saveSetupProvider` 的 `opts.defaultModel` 保留（`/provider add` 之外的调用方与手写路径仍可能用），向导不再传它。调用方（CLI setup、TUI wizard-io、model-picker）同步修改。
- `runTui` 签名扩展为可无会话启动（setup 形态）；CLI 启动路径在"无已配置服务商 / 无可解析默认模型"时改为延迟打开会话。这是 v0.3 最大的装配变化，错误路径（Esc 放弃）以退出码与提示兜底。
- `SessionSummary` 增加 `firstText?`（欢迎框"首句摘要"的数据源）；列表实现本就读取日志文件，提取首条 `message.user` 文本成本可忽略。
- 状态栏移除会话 id：会话标识迁移到欢迎框与 `/resume` 列表。
- 管道/重定向场景行为变化：`nctrn < input`、`nctrn | tee` 自动逐行而非报错——这正是本决定想要的（脚本场景不被 TUI 默认卡死），已记录为有意行为。
- 向导不写 `defaultModel` 后，"服务商已配置但无默认模型"成为常态；首次配置流程的第 2 步与 `/model` 的"设为默认"覆盖了该路径。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 服务商页留在活动区弹层 | 否决 | 与 ADR-0017 否决理由相同：列表 + 就地步骤 + 操作菜单需要整屏高度，弹层高度被对话内容挤占 |
| 向导保留选模型步骤 | 否决 | `/model` 已是统一选择入口；两处设默认造成路径分裂，且"配 5 个预设"的场景被迫重复选模型 |
| 主界面整体进备用屏幕 | 否决 | 推翻 ADR-0010：回放区交给终端 scrollback 是基本交互 |
| 默认 TUI 只对无参 `nctrn` 生效 | 否决 | `-c`/`--resume` 同样面向交互用户，分裂的默认行为更困惑 |
| 欢迎框每次启动重画 + 配置开关 | 暂缓 | 已在 `<Static>` 中只写一次；关闭开关等真实需求出现再加 |
| emoji/Nerd Font 图标 | 否决（本轮） | 未经 conhost 与 Windows Terminal 双端实测；像素块字符与普通字符已能表达全部状态 |
