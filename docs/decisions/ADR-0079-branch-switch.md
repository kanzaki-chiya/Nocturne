# ADR-0079：桌面端状态栏切换分支

- 状态：已接受
- 日期：2026-11-03
- 修订：[desktop.md](../apps/desktop.md)、[rpc.md](../protocols/rpc.md)、[events.md](../protocols/events.md)、[context.md](../architecture/context.md)

## 背景

桌面端不显示当前分支，切换分支要打开终端或让模型执行。模型读写的文件取决于当前分支，用户在界面上看不到它，也就容易在错误的分支上开始一轮工作。

切换分支会改动工作目录里的文件，同一目录的所有会话都受影响，所以它不只是一个显示问题：要规定什么时候能切、切不了怎么办、模型怎么知道分支变了。

## 决定

### 1. 界面

- 状态栏右侧、MCP 左边显示当前分支。工作目录不是 git 仓库或读不到分支时不显示。
- 不在任何分支上时显示提交号的前 8 位。
- 点开是分支菜单：搜索框加本地分支列表，当前分支打勾。输入不存在的名字时，列表末尾出现「新建分支 <名字>」，选中后从当前提交创建并切过去。
- 被其他工作树占用的分支禁用，悬停显示工作树路径。
- 切换成功后菜单关闭，只有状态栏上的分支名变化，不弹提示。
- 除上面的文字外不写说明，搜索框不写占位文字。

只有桌面端有这个入口。手机端和 TUI 不做，远程通道也不开放这些方法（第 2 节）。

### 2. 接口

Core 公开两个方法，经 RPC 映射，切换和列分支都在后台进程执行：

- `workspace.branches({ workspace })`：返回当前分支或提交号，以及本地分支列表和占用它们的工作树路径。不是 git 仓库时返回空结果，不算错误。
- `workspace.switchBranch({ workspace, branch, create })`：切换或新建并切换。

git 直接以参数数组调用，不经过 shell。分支名由用户输入，要用 `git check-ref-format --branch` 校验，并用 `git switch` 的 `--` 或等效方式防止名字被当成选项。

这两个方法是用户的直接操作，不是模型工具，不经过权限层。模型要切分支仍然走 `shell` 和现有的权限规则。

### 3. 什么时候能切

- 这个目录下有任何活动时不能切：任何会话的 Turn、压缩、回退正在进行，或有只读后台子代理在跑。判断放在 Core 的 `switchBranch` 内，界面上的禁用只是提前反映，不能作为唯一的防线。报错码沿用 `session_busy`。
- 按目录判断，因为同一目录的会话共用一份文件。工作树隔离的后台子代理在自己的副本里，不阻止切换。
- 有未提交改动时交给 `git switch`：能带过去就切，有冲突就失败。不自动 stash。
- 失败时菜单不关，在列表下方显示 git 的原始 stderr，不翻译。

### 4. 显示何时刷新

打开会话、打开菜单、Turn 结束、窗口重新获得焦点时重新读取。这样用户在终端或由模型切了分支，界面也能跟上。不监听 `.git/HEAD`，不轮询。

### 5. 模型怎么知道

每个 Turn 开始前读取当前分支，和会话上一次记录的值比较：

- 第一次读到时只记录，不写说明。
- 不同时写 `session.config_changed` 记录新分支，并追加一条持久 `note`，沿用 shell、MCP 环境说明的投影、修剪与压缩规则（[context.md](../architecture/context.md) 第 5 项、[ADR-0071](ADR-0071-mcp-availability-notes.md)）。内容只写从哪个分支切到哪个分支、之前读到的文件内容可能已过时。
- 不是 git 仓库或读不到时不记录也不说明，读取失败不能影响 Turn。

选择在 Turn 开始时比较，而不是在切换时广播：这样不论分支是从界面、终端还是模型切的都能发现，还没加载的会话下次恢复时也能发现。写文件仍由 `guard.ts` 的 `stale_file` 检查兜底，所以这条说明只负责让模型知道，不负责防止误写。

会话历史不记录每轮的分支，只记录变化。回退和分叉沿用 `config_changed` 现有的折叠规则。

## 不做

删除、合并、变基、提交、推送、拉取、远程分支、stash 管理。这些操作风险更高或已经可以交给模型，第一版的入口只解决看见和切换。

## 后果

- 每个 Turn 开始前多一次 `git` 调用。要实测耗时，并给它设超时，超时按读取失败处理。
- 状态栏多一个常驻项，窄窗口下要确认不会挤掉现有内容。
- 模型自己切分支后，下一轮也会收到这条说明。内容是真实的，不需要排除。

## 备选方案

- **切换前自动 stash**：用户的改动被悄悄藏起来，切回来容易忘，不采用。
- **切换时向同目录会话广播说明**：只覆盖从界面切的情况，也管不到没加载的会话，不采用。
- **只显示分支、不能切换**：用户还是要去终端，不解决原来的问题。
- **运行中也允许切**：模型正在读写的文件会被换掉，产生难以解释的结果，不采用。

## 修订
