# ADR-0085：新会话页选择分支与工作树

- 状态：已接受
- 日期：2026-11-10
- 修订：[ADR-0079](ADR-0079-branch-switch.md)、[ADR-0081](ADR-0081-session-worktree-switch.md)、[sessions.md](../architecture/sessions.md)、[rpc.md](../protocols/rpc.md)、[desktop.md](../apps/desktop.md)

## 背景

现在新会话只能在项目目录当前所在的分支上开始；状态栏的分支菜单（[ADR-0079](ADR-0079-branch-switch.md)）直接切换整个项目目录的分支，同一目录有会话运行时全部变灰。用户并行打开多个窗口或多个会话时，要么互相把主目录切走，要么只能先在主目录建会话再让模型自己建工作树并调用 `switch_worktree`（[ADR-0081](ADR-0081-session-worktree-switch.md)）。

## 决定

### 1. 新会话页分支选择框

- 桌面端新会话页输入框下方托盘（`.tray`）在权限选择框右边增加一个分支选择框：分支图标 + 分支名 + 下拉箭头，外观与左边两个 `.chip` 一致。
- 当前所选目录不是 Git 仓库（含普通对话）时显示分支图标 + `-`，禁用，不显示下拉箭头。
- 默认值是项目目录当前所在的分支。
- 展开后顶部为搜索框，下方列出全部本地分支，当前选中的分支打勾，复用状态栏 `BranchMenu` 的外观与键盘操作。
- **所有本地分支都可选**，包括已在其他工作树检出的分支，也不因同目录有会话正在运行而禁用。已在工作树检出的分支仅在悬停 `title` 显示工作树路径，不附加其他说明文字。
- 搜索词不匹配任何现有分支、是合法分支名且仓库能确定新建分支基准（见第 2 节）时，列表出现「新建分支 <名字>」。
- 选择框只在新会话页出现；已有会话的状态栏分支菜单行为保持不变（ADR-0079）。界面不增加任何说明文字、提示或新标签。

### 2. 选中后的目录与工作树规则（项目目录始终不切换分支）

分支和工作树只在用户发出第一条消息、真正调用 `createSession` 创建会话时才解析或创建；只选不发不在磁盘或仓库里留下任何痕迹。

- **选项目目录当前所在的分支**：不创建工作树，新会话直接在项目目录开始，与原先一致。
- **选已在某个工作树检出的分支**：新会话的当前执行目录（ADR-0081 第 2 节）直接使用该工作树。项目目录是仓库子目录时映射到该工作树里对应的子目录，规则与 `switch_worktree` 相同（目标工作树缺少对应子目录时报错）。
- **选其他已有本地分支**：在 `<仓库根目录的父目录>/<仓库根目录名>-wt/<分支目录名>` 创建工作树并检出该分支（`git worktree add <路径> <分支>`），例如仓库为 `Z:/nocturne`、分支为 `r1110a-floating-jump` 时建在 `Z:/nocturne-wt/r1110a-floating-jump`。新会话的当前执行目录为该工作树（含子目录映射）。
- **新建分支**：从基准分支创建新分支并在上述位置建工作树（`git worktree add -b <分支> <路径> <基准>`）。
- **目录名与冲突保护**：分支名中的 `/` 在工作树目录名里替换为 `-`（并通过 `git check-ref-format --branch` 校验分支名，拒绝 `..` 等非法名字）。目标目录已存在且不是检出该分支的同仓库工作树时直接报错，不覆盖、不删除已有目录。
- **基准分支规则（无 `main` 时的确定性本地回退）**：新建分支的基准只使用确定的本地 Git 信息，按以下顺序选取第一个存在的提交引用：
  1. 本地分支 `refs/heads/main`（即 `main`）；
  2. 本地 `refs/remotes/origin/HEAD` 符号引用所指向的分支（若存在同名本地分支 `refs/heads/<name>` 则优先用本地分支，否则用 `refs/remotes/origin/<name>`）；
  3. 本地分支 `refs/heads/master`（即 `master`）。
  以上均不存在时无法确定新建基准：`workspace.branches` 返回 `defaultBranch: null`，前端不展示「新建分支 <名字>」，Core 收到 `create: true` 时拒绝创建并报错。

### 3. 接口、会话记录与权限边界

- `CreateSessionOptions` 与 RPC `runtime.createSession` 增加可选字段 `branch?: { name: string; create?: boolean }`；`WorkspaceBranches` 增加可选字段 `defaultBranch?: string | null` 供新会话页判断是否允许新建分支。客户端只传递意图，不在前端直接调用 Git。
- 会话记录沿用 ADR-0081：`session.created` 的 `cwd`、`workspaceRoot` 仍然是所选项目目录（侧栏分组、项目配置、信任与项目 Grant 都跟随项目目录）。当解析或创建出的目标工作树目录不等于项目目录时，会话创建后立即写入一条带 `worktree`（及 `branch`）字段的 `session.config_changed`，与 `switch_worktree` 产生的事件一致，恢复、回退、分叉均复用 ADR-0081 现有规则。
- 这是用户在桌面界面上的直接操作，按 ADR-0079 分支切换的先例走运行时命令（`runtime.createSession`），不经过模型工具和工具权限审批层。
- 创建失败时会话不创建，前端输入框保留草稿，错误显示在现有的 `composer-error` 位置。
- 远程连接（手机）与外部 agent 连接这一轮不支持 `branch` 字段：远程调用 `runtime.createSession` 携带 `branch` 时返回 `remote_not_allowed`；手机界面不改。

## 后果

- 用户可以在同一个项目上并行开启多个不同分支的新会话，项目主目录始终保持原分支不变，各会话在独立工作树中互不干扰。
- 新会话的工作树直接落在 `<仓库>-wt/<分支>`，路径可预测，且会话在侧栏中仍归入原项目分组。
- 创建会话失败时不产生空会话日志，草稿保留在输入框中便于直接重试。

## 备选方案

- **在客户端先调 Git 建工作树再把新路径作为 `cwd` 传给 `createSession`**：会导致 `session.created.cwd` 变成工作树路径，侧栏按工作树拆成多个新项目，且项目配置与信任无法跟随原项目目录，不采用。
- **选分支时立即建工作树**：用户只是点开看看或选错分支就会在磁盘上留下多余工作树和分支，不采用。
- **没有 `main` 时回退到当前 `HEAD`**：若主目录正好停在某个临时特性分支上，新建出的分支会意外带上特性分支的未合并提交；只按 `main` → `origin/HEAD` → `master` 取确定的主干基准更稳妥。
