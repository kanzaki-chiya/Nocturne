# ADR-0038：界面打磨第一批——点击展开、对话节奏与会话标题、速度与用量条

- 状态：已接受
- 日期：2026-10-02

## 背景

[路线图](../roadmap/roadmap.md) v0.5「界面打磨」剩余条目中，以下三项每天都看得到，而且不依赖新的 Core 设计：

- **点击展开折叠块**：思考段只能用 Ctrl+O 整体展开；工具行只显示输出末尾 4 行，看不到完整输出。diff 已有单击「… 还有 N 行」展开（[ADR-0027](ADR-0027-edit-diagnostics-diff-display.md)），点击判定方案已在 [ADR-0030](ADR-0030-dialog-settings-pages.md) 定好。
- **对话节奏与会话标题**：长对话里用户消息有 `›` 前缀，助手回答没有任何标记，与工具行、提示行混在一起不好分辨。输入框上方只有一条横线，看不出当前是哪个会话。
- **底部信息**：状态栏没有生成速度。上下文只有「百分比 / 长度」文字，不够直观。

估算费用需要价格数据（models.dev 价格按服务商给出，现有 pricing 只有 input/output），留给 v0.6 的 `/cost`，本 ADR 不做。服务商页推广成对话框另行处理。

## 决定

### 1. 点击展开折叠块（仅全屏）

点击判定原样复用 ADR-0030：只认左键，松开时判定；按下后收到过任何移动事件，就按拖选处理；一次按下最多执行一个动作。`--inline` 不开鼠标上报，行为不变。

- **思考段**：单击某段的计时标题行（「∴ 思考了 Ns」），展开或收起这一段，展开形态与 Ctrl+O 相同。全屏下标题提示改为「（单击或 Ctrl+O 展开）」，`--inline` 保持「（Ctrl+O 展开）」。
  - 展开状态按段记录，本次运行内有效。
  - Ctrl+O 仍为全部展开/收起，并清除各段单独的状态。
  - 状态栏的「思考已展开」提示只在 Ctrl+O 全部展开时显示。
- **工具行**：单击工具标题行，展开或收起这一条。
  - 无 diff 的工具：收起时显示现有的末尾 4 行（默认形态不变）；展开后显示完整的 `modelContent`。完整内容已受工具输出预算限制，不另设行数上限。
  - 有 diff 的工具（`edit`/`write`/`apply_patch`）：单击标题行与单击「… 还有 N 行」共用同一个展开状态。
  - 被预算省略的结构化输出只显示省略提示，无展开入口（与 ADR-0027 一致）。
  - 正在运行的工具不可展开（实时输出仍是末尾 3 行）。
- **锚点**：展开或收起时，被点的标题行保持在屏幕原位，其后内容推移；被点行原本在视口顶部之上时，以它为新的顶部。跟随底部状态下展开，如果被点行仍可见，就保持跟随。
- 命中框为标题行的可见文字范围（含折行续行），按最终帧重算。
- 展开状态按条目 key 记录，宽度变化重排后保留。

### 2. 对话节奏：助手回答加 `●`

- 助手正文每一段（一条 assistant 消息的文本部分）首行以 `● ` 开头，`●` 在第 0 列，首行本身不另加缩进；后续行与折行续行缩进 2 列，与首行文字对齐。思考段、工具行、提示行不加。
- 用户消息保留现有 `›` 前缀，与输入行一致，不改为 `❯`（路线图原写 `❯`，以本条为准）。
- `●` 用主题主色，不加粗。ASCII 模式为 `o`（`*` 已是思考段的 ASCII 标记，`>` 是用户前缀）；NO_COLOR 下仍保留符号。
- 退出时导出到主屏的纯文本同样带 `● ` 与缩进。
- `--inline` 同样适用。

### 3. 会话标题

- **来源**：会话第一条用户消息的首行，去掉首尾空白；粘贴与图片占位按显示文本（`[Paste #n …]`、`[Image #n]`）计。与 `/resume` 列表的首句共用同一个函数。
- **位置**：输入框上方的横线改为 `── <标题> ─────…`，标题用中性弱化色，超出可用宽度（终端宽度减 8）时以 `…` 截断。尚无用户消息时仍是一条横线。
- 不新增事件、不写入会话，标题从重放后的视图派生；`/resume`、`/new` 后随会话变化。
- 终端太矮、横线被省略时，标题一起省略。
- 以后模型角色接入 `smol` 后，可以改为自动生成标题（另行设计），本条的位置与截断规则不变。

### 4. 状态栏：生成速度

- 新增段 `N tok/s`，放在状态栏末尾，紧跟上下文段与用量条之后。
- **流式期间**：以本步收到的正文与思考增量按 Core 的估算函数（CJK 1 字 1 token，其余 4 字符 1 token）估算，除以自首个增量以来的时长，显示为 `~N tok/s`，每秒最多刷新一次。
- **本步结束后**：用该步 `message.assistant` 的 `usage.outputTokens`（含推理 token）除以首个增量到消息完成的时长，显示为 `N tok/s`，保留到下一步开始。
- 没有用量（服务商未返回）时保留估算值并带 `~`。时长不足 0.5 秒时不显示，避免极端值。
- 恢复会话、切换会话后在首次生成前不显示（历史事件没有流式时序）。
- 宽度不足时最先隐藏此段（先于目录段）。

### 5. 状态栏：上下文用量条

- 在现有上下文段 `21% / 500K` 后面加一个 8 格小条，例如 `21% / 500K ██░░░░░░`。格数按百分比四舍五入，大于 0 时至少 1 格。
- 已用格为中性色，未用格为弱化色；百分比 ≥ 80% 时整条改为警告色。
- ASCII 模式为 `[##------]`。NO_COLOR 下保留字符形状。
- 上下文长度未知（只显示已用量）时不显示用量条。
- 宽度不足时，用量条在速度段之后、目录段之前隐藏；上下文文字本身仍按现有优先级保留。

## 界面示意

全屏，宽 80 列，默认收起：

```text
› 帮我看看压缩阈值为什么没生效

∴ 思考了 6s（单击或 Ctrl+O 展开）
● 先看一下配置加载和预算计算的位置。
✓ read packages/core/src/config/settings.ts
  …
  120 │   threshold: parseCompactionThreshold(raw.threshold),
  121 │ };
✓ shell pnpm test compaction  23 passed
  …
  Test Files  4 passed (4)
       Tests  23 passed (23)
● 阈值在恢复会话时会重新读取设置，所以对旧会话也生效。问题在于
  你设的 300k 超过了预算 255k，按规则被视为不做预防性压缩。

── 帮我看看压缩阈值为什么没生效 ─────────────────────────────────
› _
────────────────────────────────────────────────────────────────
就绪 • gpt-5.5 • 思考:高 • smart • Z:
octurne • 缓存 92% • 21% / 272K ██░░░░░░ • 48 tok/s
```

单击 `✓ shell pnpm test compaction` 这一行后，该工具行展开为完整输出，标题行不动，后续内容下移；再次单击收起。

窄终端（约 60 列）按隐藏顺序先去掉速度段，再去掉用量条：

```text
就绪 • gpt-5.5 • 思考:高 • smart • 缓存 92% • 21% / 272K
```

ASCII 模式：

```text
* 思考了 6s（单击或 Ctrl+O 展开）
o 先看一下配置加载和预算计算的位置。
-- 帮我看看压缩阈值为什么没生效 -------------------------------
... - 21% / 272K [##------] - 48 tok/s
```

## 后果

- 工具输出与单段思考可以就地展开查看，不必整体 Ctrl+O 或去翻日志。
- 助手回答除首行外缩进 2 列，正文可用宽度少 2 列。代码块与表格按新宽度排版。
- 状态栏多出两段，窄终端靠隐藏顺序保证核心信息不被挤掉。
- 不新增 Core 事件与接口；速度在客户端按事件时序计算，CLI 不显示。

## 备选方案

- **工具行默认改为一行摘要、点击才看输出**（路线图原文）：会改变用户已认可的默认显示（diff 直接可见），这一轮只做展开，不改默认。
- **用量条标出压缩阈值位置**：阈值可以是绝对 token，与窗口百分比不在同一刻度，标出来容易误读，不做。
- **速度只在结束后显示**：长回答期间看不到，体验差。流式估算带 `~` 区分。

## 修订

### 2026-10-02：标题来源与估算函数

- **第 3 节标题来源**：TUI 提交前会把粘贴占位展开，日志里只有原文，重放无法还原 `[Paste #n …]`。标题改为取持久化的首条用户消息中第一个文本块的首行（去首尾空白），与 `/resume` 列表的现有规则一致；两处共用同一个纯函数。粘贴内容很长时，靠宽度截断兜底。
- **第 4 节估算函数**：把 Core 现有的 `estimateTokens` 纯函数从公开入口导出，供 TUI 复用。它只是已有函数的重新导出，不涉及 Runtime、命令与事件，不算新增接口。
