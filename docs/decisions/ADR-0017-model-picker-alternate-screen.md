# ADR-0017：模型选择页使用终端备用屏幕

- 状态：提议
- 日期：2026-09-25

## 背景

v0.2 新增的模型选择页（[tui.md](../apps/tui.md) 第 7 节）是双栏布局：左栏范围与服务商，右栏搜索框 + 模型列表 + 详情行，底部按键提示。OpenRouter 这类服务有数百个模型，列表需要整屏高度才够用。

这与 ADR-0010 定下的 TUI 渲染模型冲突：主界面是"<Static> 回放区（append-only，交给终端 scrollback）+ 限高活动区"，任何面板都只能在活动区高度内渲染，且**不进入终端备用屏幕**（tui.md 第 10 节原本把 alternate screen 列为不做项）。模型选择页在活动区限高渲染时：

- 可用行数被对话内容与状态栏挤占，几百个模型的列表只剩几行可视，翻页导航基本不可用；
- 活动区随 `view.revision` 整区重绘，大列表每帧重排在 conhost 上残影更明显（conhost 无 Synchronized Update，ADR-0010 已记录）；
- 面板关闭后主界面要"补画"被盖住的内容，与 <Static> 的 append-only 模型不匹配。

## 决定

**模型选择页——且只有这一个页面——在打开时进入终端备用屏幕（`smcup`/`?1049h`），关闭时退出（`rmcup`/`?1049l`）。**

- 范围只限 `/model` 与不带参数的 `/provider` 打开的这个页面；`/resume`、`/mcp`、`/context` 等面板与权限对话框维持活动区内渲染，主界面渲染模型不变。
- 备用屏幕内仍由 Ink 渲染（同一份组件树的一部分），不进 `<Static>`，关闭后 Ink 继续输出到主屏幕，对话回放完整保留。
- 打开/关闭都发生在会话空闲边界（与 `setModel` 前置条件一致），不与活动区重绘并发。
- `Ctrl+C` 退出路径保证发出 `?1049l`：组件卸载清理 + 进程退出钩子双保险，不把终端留在备用屏幕。
- 宽度 < 80 列时页面降级为单栏（隐藏左栏），< 40 列沿用既有降级规则——备用屏幕不改变降级规则本身。

## 后果

正面：

- 数百个模型的列表获得整屏高度，搜索/分页/双栏导航可用；双栏与详情行是选择页的核心交互（tui.md 第 7 节）。
- 打开/关闭是离散动作，不挤占活动区的每帧重绘；conhost 上残影风险反而比"活动区内限高大列表"低。
- 备用屏幕序列由终端处理（conhost 忽略未知序列时会退化为普通全屏重绘，最坏结果是行为退回主屏重绘，不会损坏输出）。

负面与约束：

- ADR-0010"不用 alternate screen"的表述被局部修订：决定范围从"整个 TUI"收窄为"主界面渲染模型"，tui.md 第 10 节的对应条目已改写。
- 备用屏幕内的渲染帧不进 scrollback——这正是本页想要的（临时页面不留痕迹），但意味着截图核对与 `ink-testing-library` 断言要覆盖进出序列与页面帧两种状态。
- 需要测试覆盖：打开/关闭序列、resize 跟随、连续开关无残影、`Ctrl+C` 恢复主屏。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| **备用屏幕只给这一个页面** | **采用** | 列表高度与双栏是硬需求；离散进出动作对 Ink 渲染模型的侵入最小 |
| 活动区内限高渲染 | 否决 | 高度不够（几百个模型只剩几行可视）；每帧整区重绘在 conhost 上残影更明显；关闭后要补画主界面，与 <Static> append-only 冲突 |
| 主界面整体改备用屏幕 | 否决 | 推翻 ADR-0010 的核心决定：已完结条目进 scrollback、交给终端原生滚动是回放区的基本交互，收益不足以交换 |
| 分页式行内列表（不双栏） | 否决 | CLI 已采用此形态（编号表格 + 关键词过滤，cli.md 第 4 节）；TUI 若同样退化为行内列表，则丧失双栏/详情的交互价值，与"为 TUI 专门做全屏页"的设计目标相悖 |
