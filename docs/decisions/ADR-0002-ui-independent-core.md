# ADR-0002：Core 与 UI 解耦：命令进、事件出

- 状态：已接受（2026-09-23）
- 日期：2026-09-23

## 背景

Nocturne 先做 CLI，之后要支持 TUI、RPC，以及更远的 Web / Desktop / IDE。如果 Agent 逻辑与某个界面耦合，每新增一个客户端都要复制或改写 Agent 行为。ZCode 的 TUI 在进程内直接订阅原始会话事件，而 Desktop 通过另一套 v4 协议消费服务端投影的"会话行"，两条消费路径各有一份投影逻辑。

## 决定

1. `packages/core` 不依赖任何 UI、终端或客户端代码。
2. 客户端与 Runtime 之间只有两种交互：**命令**（submit、interrupt、respondPermission、setModel、compact）与**事件**（见 [events.md](../protocols/events.md)）。
3. 需要用户参与的流程（目前是权限确认）也表达为"事件请求 + 命令回复"，而不是 Core 调用客户端回调。
4. 进程内客户端通过 `@nocturne/core` 的公开 API 使用这组命令与事件；将来的 RPC 序列化的是同一组语义，不另起一套。
5. 客户端需要的派生视图（例如 TUI 的会话视图）由 `protocol` 中的纯函数 reducer 提供，所有客户端共享，禁止各自在客户端重写投影逻辑。

## 后果

- CLI、TUI、RPC 服务可以驱动同一套 Runtime，行为一致。
- 事件模型必须足够完整，客户端才能在不访问 Core 内部状态的情况下渲染；这提高了事件设计的要求。
- 权限确认等交互天然支持非交互环境（无人回复时按配置处理）与远程客户端。

## 备选方案

- **客户端回调接口**（Core 调用 `prompter.ask()`）：进程内实现简单，但远程化时需要重写，并诱导 Core 依赖客户端能力。
- **每个客户端各自消费原始事件并自行投影**：短期快，长期导致各客户端显示不一致（ZCode 的情况）。
