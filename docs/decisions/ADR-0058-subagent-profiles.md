# ADR-0058：子代理档位

- 状态：已接受（维护者 2026-10-13 确认）
- 日期：2026-10-13

## 背景

模型能选择工具集和外部 agent，但内置子代理的模型和思考强度固定，不能按任务成本与难度挑选。

## 决定

- 仅 `default` 始终存在，模型即 `modelRoles.task`，不迁移设置。自定义档位存在 `subagents.profiles`，包含何时用、可选模型、强度、工具集上限、默认超时和启用状态。
- 不自带具体档位。添加提供空白、quick（explore/low）、deep（general/high）模板，模型均留空。
- 外部 agent 并入 `task.profile` 的同一张选择表；`agent` 保留一个版本作为兼容别名，同时给两字段报错。
- `reason` 可选，一句话，显示最多 200 字，不参与判断。模型选择最便宜的够用档位，拿不准用 default。
- 解析在配置层，launcher 使用解析后的模型、强度和工具集；Agent Loop 不认识档位。工具集只能收窄，强度按子模型就近降档，超时可覆盖且封顶 3600 秒。
- 权限主体、非交互策略与外部 agent 边界不变。未知、停用或模型不可用档位报错并列出可选值，不回退。
- 用户层与可信项目层逐档位覆盖，不可信项目整段忽略；名称只含小写字母、数字、`-`，最长 32，default 保留，与外部 agent 不区分大小写唯一。
- 桌面「外部 agent」页改为「子代理」；TUI 只读列出自定义档位。用量按档位分组留到第二步。
- 不新增事件字段。维护者额外确认可选 `task.output.reasoningEffort`，记录实际强度，避免客户端用变化后的配置推算；运行期间用既有 `tool.progress` 显示。

## 备选方案

- 直接开放 `model`、`effort` 给模型：不采用，用户无法控制成本。
- Codex V2 式加密任务内容：不采用，子代理收到的任务原文必须对用户可见。
- 仿 omp 增加 plan、slow、commit 等角色：不采用。模型角色只保留程序自己发起的后台调用（vision、smol）；模型自己判断「交给谁做」的，都用档位，不新增角色。

## 后果

用户定义成本边界，模型在已启用且可用的执行者之间选择。配置和运行规则以 [subagent.md](../architecture/subagent.md) 为主。
