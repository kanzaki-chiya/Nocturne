# ADR-0080：会话归档

- 状态：已接受
- 日期：2026-11-04
- 修订：[sessions.md](../architecture/sessions.md)、[rpc.md](../protocols/rpc.md)、[desktop.md](../apps/desktop.md)、[ADR-0078](ADR-0078-browser-settings.md) 第 1 节的导航位置

## 背景

会话只增不减，侧栏越来越长。用户需要把不再关注的会话移出侧栏，又不想丢掉它们。目前没有归档，也没有删除。

## 决定

### 1. 状态存放

归档状态存在日志旁的 `<NOCTURNE_HOME>/sessions/<sessionId>.archive.json`，内容是 `{ "archivedAt": "<ISO 时间>" }`，用临时文件加重命名写入。文件存在即已归档，恢复时删除。内容损坏时按未归档处理并记诊断。

不写事件日志。侧栏和 `/resume` 都按日志文件的修改时间排序，追加事件会让恢复的会话跳到最上面。归档也不影响对话内容、上下文和用量，不需要进入重放；分叉不复制这个文件，所以新会话不带归档状态，回退也不受影响。

### 2. 接口

- `Runtime.archiveSession(id)`、`Runtime.unarchiveSession(id)`，RPC 为 `runtime.archiveSession`、`runtime.unarchiveSession`，参数 `{ sessionId }`，结果 `null`，成功后通知会话列表变化。
- `listSessions` 增加 `includeArchived?: boolean`，缺省 `false`。`searchSessions` 的选项同样增加，缺省 `false`。`SessionSummary` 增加 `archivedAt?: string`。
- 远程连接不能调用这两个方法，`includeArchived` 对远程连接一律按 `false` 处理。这两个方法也不开放给 agent host 和对外 MCP，模型不能归档会话。
- 判定目录是否用过等内部逻辑不能因为归档改变结果，要显式包含已归档的会话。

### 3. 什么时候能归档

- 只有根会话能归档或恢复。子会话返回 `invalid_command`。
- 归档时，以下情况返回 `session_busy`：Turn、压缩、回退进行中，会话正在关闭，有后台子代理，有待发输入，或被其他进程持有锁。
- 恢复（`unarchiveSession`）不受上述忙与锁条件限制：打开和未打开的会话都只校验 ID 和根会话，然后删除旁路文件；不判断 Turn、压缩、后台子代理、待发输入，也不取会话锁；旁路文件本来就不存在时视为成功。
- 判断放在 Core，界面上的禁用只是提前反映。

### 4. 自动恢复

已归档的会话在开始新一轮（`startTurns` 首个输入准备之前，涵盖 `submit`、`enqueueInput` 空闲路径与压缩结束后路径、`pumpQueue` 含「继续发送」、继续目标 `resumeGoal`、批准计划 `approvePlan`）时，Core 先删除归档文件，再准备输入并开始本轮；实际删除了归档文件才通知列表变化，同一 `startTurns` 内接续的下一轮不重复处理。删除失败只记诊断，不挡住这一轮。打开、查看、压缩、回退、分叉都不改变归档状态。

### 5. 桌面端主界面

- 侧栏会话的右键菜单和「…」菜单在「重命名」后面加「归档」，点击立即归档，不确认，不弹提示。运行中的会话这一项禁用。
- 归档时从 `pinned` 里移除，恢复后不再置顶。
- 归档当前打开的会话时，按顺序取：
  1. 同项目侧栏顺序里的下一条，包括折叠没显示的。
  2. 同项目的上一条。
  3. 侧栏第一条。
  4. 都没有就回到新会话页。
  不显示在项目行里的置顶会话，沿用同项目第一条。
- 项目下的会话全部归档后，项目仍留在侧栏。项目的排序与「还有 N 个」只计未归档的会话。
- `Ctrl+K` 有查询时能搜到已归档的会话，结果行不加标记；空查询的「最近使用」不显示。打开后侧栏没有选中行，发消息后自动恢复。

### 6. 设置页

- 新增「已归档的会话」页，图标 `archive`。
- 页面从上到下是标题、搜索框、按项目分组的列表。项目分组用侧栏同样的归属与名称，被隐藏的项目也列出。分组按其中最新的归档时间降序，组内按归档时间降序。
- 每行是标题、归档时间、「恢复」。标题放不下省略，悬停用 `title` 显示全文。
- 搜索框只有放大镜图标，没有占位文字，只按标题即时过滤，不分大小写，没有匹配项的分组一起隐藏。
- 点标题打开会话并离开设置区。点「恢复」后这一行直接消失，不弹提示。会话回到侧栏原项目下，位置由原来的修改时间决定；项目被隐藏时取消隐藏。
- 页面只有这些文字：标题「已归档的会话」、「恢复」、一条都没有时的「没有已归档的会话」、搜索无结果时的「没有匹配的会话」。没有已归档的会话时不显示搜索框。

### 7. 设置导航顺序

常规、外观、服务商、模型、子代理、技能、MCP、浏览器、授权、远程、已归档的会话、用量、后台日志。

### 8. 其他客户端

手机网页、安卓、TUI、CLI 没有归档和恢复入口。它们的会话列表、`/resume`、`--sessions`、`--continue` 和对外 MCP 的会话列表都不显示已归档的会话。按 ID 恢复仍然可用，发消息时同样自动恢复。

## 不做

永久删除、批量归档与恢复、自动归档、归档时清理工作树。

## 后果

- `SessionSummary` 多读一个旁路文件，每个会话多一次存在检查。
- 归档状态不随日志复制。只拷走 `.jsonl` 时，会话回到未归档状态。

## 备选方案

- **写进事件日志（`session.archived`）：** 符合“日志是唯一事实来源”，但会改变修改时间，导致恢复后排序跳动；要改写修改时间才能避免，反而更绕。还要处理分叉和回退。
- **存桌面端 prefs（和置顶一样）：** 手机、TUI 和对外 MCP 读不到，做不到各端一致地隐藏。
- **侧栏底部放折叠区：** 侧栏仍要留位置，设置页更干净（用户确定）。

## 修订

- 2026-11-04：
  1. **第 4 节自动恢复时机**：原实现只在 `submit` 里删除归档旁路，导致 `enqueueInput`（空闲路径与压缩结束后路径）、`pumpQueue`（含「继续发送」）、继续目标（`resumeGoal`）和批准计划（`approvePlan`）直接调用 `startTurns` 启动新一轮后会话仍处于已归档。改为在 `startTurns` 首个输入准备之前统一恢复，仅在实际删除旁路文件时通知列表变化，接续的下一轮不重复处理；打开、查看、压缩、回退、分叉仍不改变归档状态。
  2. **第 3 节恢复不受忙状态限制**：原实现让 `unarchiveSession` 与归档共用忙状态与会话锁检查，导致已归档会话打开后处于忙状态时点击「恢复」无反应。改为恢复只校验会话 ID 与根会话（子会话仍返回 `invalid_command`）并直接删除旁路文件，不判断 Turn、压缩、后台子代理、待发输入，也不取会话锁；文件本来不存在时视为成功。
  3. **第 5 节归档当前会话后的跳转顺序**：原实现在归档项目内显示的最后一行时直接跳出该项目。改为依次取：同项目侧栏顺序里的下一条（包括折叠没显示的）、同项目的上一条、侧栏第一条、新会话页；不显示在项目行里的置顶会话沿用同项目第一条。
