# ADR-0069：用户改名与会话标题旁路文件

- 状态：已接受
- 日期：2026-10-28
- 修订：[sessions.md](../architecture/sessions.md)、[events.md](../protocols/events.md)、[view.md](../protocols/view.md)、[rpc.md](../protocols/rpc.md)

## 背景

标题此前由首条用户消息或后台模型生成。用户不能纠正标题；列表只扫日志开头 64 KiB，后续改名事件可能落在中段，不能可靠地给未打开的会话展示。会话日志仍须是持久状态的事实来源，不能因为列表性能改为可覆盖的标题文件。

## 决定

### 1. 标题事实与优先级

用户通过 `Runtime.renameSession(sessionId, title)` 改名，开放到 RPC；对打开的会话沿用其写入队列，对未打开的会话由 Runtime 离线取得排他锁，校验日志后用最小的 `Session` 只写事件。`session.titled` 增加可选 `source: "user" | "generated"`；旧事件缺省为 `generated`。`model` 改为可选：模型生成时仍写入，用户改名不填；`usage?` 仍只用于模型角色请求。用户标题清理后为空串表示清除用户覆盖，写入 `session.titled { title: "", source: "user" }`，不删除已有事件。清空不是请求重生成标题。

折叠时分别保存最近的用户标题、生成标题和首条用户消息首句，展示优先级为**非空用户标题 > 生成标题 > 首句**。用户清空覆盖后回到已有生成标题，否则回到首句。回退只影响有效对话历史，不撤销标题事件；标题按原始持久日志折叠，分叉继承。

后台自动标题在启动请求前检查是否已有任何 `session.titled`，并在请求完成、进入共享写入队列后、实际落盘前再检查一次；已有人改名或清空则丢弃结果。已写过标题（包括空的用户标题）的会话不再自动生成；旧会话恢复、子会话仍不启动生成。这样慢模型请求不能覆盖竞态中的用户操作，写入成功仍遵循连续 seq、先写后发。

### 2. 列表旁路缓存

在 `<sessionsDir>/<sessionId>.title.json` 存 `{ title, seq }`，只缓存**最近一条用户标题事件**的非空值及其事件序号；用户清空时删除文件。先写日志，再写临时文件并 rename 为旁路文件，最后发布事件；旁路写入不是标题事实，失败不能回滚日志。列表只读，旁路文件读取成功且结构有效时，`SessionSummary.firstText` 优先取其标题；否则沿用旧的头部 64 KiB 扫描：生成标题优先于首句，头部找不到首条用户消息时才读全文。损坏的旁路文件忽略并记诊断，不阻断其他会话。恢复取得锁并校验日志后按最后一条用户标题事件修复缺失、过期或损坏的旁路文件；没有有效非空用户标题时清掉遗留文件。

分叉复制标题事件，在新 id 下据复制后的日志重建旁路文件；分叉失败清理新日志、旁路及已复制数据，不留下可见的半成品。旁路不参与 `SessionView` 的归约或重放，视图仍只读事件。

### 3. 离线边界

未打开的会话改名不能先读日志再抢锁：与 `resume` 一样，先排他取得锁，按会话读取规则校验日志并处理损坏尾部，再追加标题事件。已有锁返回 `session_locked`；子会话拒绝改名。离线操作不为了改标题构建完整 Runtime 会话：不补齐未完成 Turn/工具调用，不解析当前模型是否可用，不启动 MCP，不进入交互式 `resume`。因此模型已删除的旧日志仍可改名；日志损坏或新版本日志仍按读取规则报错，不绕开校验。操作结束释放锁，写入与旁路修复失败不能遗留锁。

## 后果

- 用户改名在事件日志里可审计、可重放；旁路文件只解决列表读取成本，恢复时可重建，不改变 `formatVersion`。旧 Runtime 忽略 `session.titled` 的新可选字段，旧日志按生成标题处理。
- 列表与日志写入之间可能短暂不同步，且跨进程列表没有实时推送；重新列出或恢复修复后收敛。旁路损坏只降级标题显示，不损坏会话事实。
- 只有根会话能改名；回退不重置用户选择，清空覆盖也不会触发后台模型请求。

## 备选方案

- **列表读取日志尾部**：最后一条标题事件不一定在尾部；中段之后仍可积累超过 64 KiB 的对话，固定尾部窗口同样漏读，读全日志又失去有界列表成本。
- **全局标题索引**：需要处理跨进程写入与一致性、崩溃修复和并发更新；列表只需逐会话标题，不需要聚合索引。每会话可重建的旁路文件更简单。
- **直接覆盖标题文件或改写旧事件**：让缓存成为第二份事实，破坏只追加与恢复重放；不采用。
