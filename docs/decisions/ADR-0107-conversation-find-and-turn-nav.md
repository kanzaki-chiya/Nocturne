# ADR-0107：会话内搜索与按轮跳转

- 状态：已接受
- 日期：2026-11-21
- 修订：[desktop.md](../apps/desktop.md)、[roadmap.md](../roadmap/roadmap.md)

## 背景

长会话动辄数十轮，仅靠滚轮翻找前面某条消息或特定关键词成本高。跨会话搜索（[ADR-0077](ADR-0077-cross-session-search.md)）解决的是在全部历史会话中定位并跳进目标会话，但不会在当前会话内逐处高亮并前后切换，也没有按用户提问轮次快速浏览与跳转的入口。

此外，对话消息流已支持虚拟化（`virtualize`，全量数据在 `SessionView.entries`，DOM 只挂载可见窗口及常驻项），助手消息由 Markdown 渲染为多节点 DOM，桌面端内嵌在 WebView2 中且主窗口与右侧面板终端、代码查看器并存。本 ADR 确定桌面端主窗口会话内搜索与按轮跳转的范围、交互、高亮实现、快捷键边界与文案口径；手机网页与 TUI 留待后续。

## 决定

### 1. 搜索范围、匹配与高亮

- **范围**：只搜索当前会话的**用户消息正文**（`userEntryText(entry)`，保留插话 `steer`，排除子代理结果、后台任务结果、合奏帖子送达与组曲汇报）与**助手回复正文**（`entry.text`）。不搜思考内容（`reasoning`）、工具输入输出与通知。
- **匹配语义**：子串匹配、不区分大小写，与 [ADR-0077](ADR-0077-cross-session-search.md) 一致；空白查询视为空。命中列表从全量 `SessionView.entries` 计算，不依赖 DOM，保证在虚拟化模式下也能算出全部命中并跨窗口跳转。
- **导航单位**：以**条目**为单位，含有一处或多处命中的每条消息算一处；计数 `2/3` 表示「第 2 条命中，共 3 条」。
- **高亮方式**：使用 CSS Custom Highlight API（`CSS.highlights`、`::highlight(conv-find)` 与 `::highlight(conv-find-current)`），在已渲染正文节点（`.u-text` 与 `article.a > .conversation-markdown`，跳过 `.conversation-code-language` 代码块头部）的文本节点上建 `Range`，不改动 Markdown 渲染结果。当前命中条目内的全部命中用 `--cm-search-current`，其余已渲染条目内的命中用 `--cm-search`。条目滚进可见范围、视图重渲染或流式追加文本时重新计算；运行环境缺少 `CSS.highlights`（如 jsdom）时安全跳过注册。
- **数据命中但渲染文字不可见的兜底**：若某条消息在源文本中命中（例如关键词仅出现在 Markdown 链接地址中），渲染后的正文文本节点里找不到匹配，该条目仍计为一处；切到它时给整条消息加 `search-hit` 背景提示位置。
- **折叠条目展开**：切到支持 `searchExpand` 展开的命中条目时传入 `searchExpand`，与跨会话搜索复用同一机制。

### 2. 搜索栏与共用跳转

- **呼出与焦点边界**：焦点在桌面主窗口对话区或输入框时按 `Ctrl+F`（macOS 为 `Cmd+F`）打开，并必须 `preventDefault()` 以屏蔽 WebView2 原生查找栏。焦点在终端（`.xterm`）、右侧面板（`.side-panel` / `.sp-rail`）、设置页/其他全屏页（主区 `inert`）或弹窗（`role="dialog"` / `role="alertdialog"`）内时不接管。
- **预填与记忆**：打开时若对话区内有单行、非空且不超过 100 字的选中文字，直接预填并搜索；否则保留本会话上次的搜索词并全选。
- **界面布局**：浮于对话区右上角，只包含搜索图标、无占位文字的输入框、计数（无命中显示 `0/0`）、「上一处」「下一处」「关闭」三个图标按钮。
- **防抖与落点**：输入后 150ms 防抖重搜（在防抖期间按 `Enter` 立即生效）。首次落点取视口顶部及以下最近的一处命中；若全部命中均在视口上方，则取最后一处。`Enter` / 「下一处」向更新的消息移动，`Shift+Enter` / 「上一处」向更早的消息移动，到头循环。
- **共用跳转函数**：将原跨会话搜索（`searchTarget`）的虚拟化偏移估算、窗口扩展、`follow = false` 关闭粘底跟随与挂载后 `scrollIntoView({ block: "center" })` 逻辑抽出为共用跳转函数 `scrollToSessionSeq` 及组件内 `jumpToSeq`，由跨会话搜索、会话内搜索与轮次导航三处共同调用。跨会话搜索继续保留 1.8 秒后淡出的整条 `search-hit` 背景；会话内搜索不使用该淡出，高亮保持到关闭。
- **关闭与流式输出**：按 `Esc` 或点「关闭」关闭搜索栏、清空全部高亮并将焦点返回输入框；切换会话时自动关闭并清空高亮。流式输出期间搜索栏保持打开，新命中落盘后只更新计数，不自动跳走。

### 3. 轮次导航与快捷键

- **轮次定义**：一轮等于一条开启新 Turn 的用户消息，排除插话（`steer`）、子代理结果（`subagent`）、后台任务结果（`backgroundShell`）、合奏帖子送达（`ensemble`）、组曲汇报（`suiteReport`）以及 Runtime 写入的模式消息（`isRuntimeWorkMode(entry.workMode)`）。
- **显示条件与位置**：仅桌面主窗口启用，至少 3 轮且对话区宽度 ≥ 640px 时显示（窄窗口与手机网页不显示）。固定在对话区右边缘垂直居中，位于正文右侧留白内、滚动条左侧，并与两者保持间距互不遮挡。
- **短横线排布与当前轮**：每轮一条短横线，轮数少时等间距排布；轮数多到超出高度上限时，轨道总高不超过对话区高度的 60%，横线按比例分布。视口中线所在轮次的横线更长、颜色更深（`--a-text`）。
- **列表展开与跳转**：鼠标移入或键盘聚焦时在左侧展开列表，每轮一行显示该用户消息的第一行非空文字并单行省略；当前轮使用选中底色（`--a-sel`），展开时自动滚到当前轮；鼠标或焦点离开后 150ms 收起（按 `Esc` 立即收起）。点击某一行调用与第 2 节相同的共用跳转函数跳到该用户消息。
- **键盘跳转**：焦点在对话区或输入框且输入框补全列表（`.composer [role="listbox"]`）未打开时，`Alt+↑` / `Alt+↓` 跳到上一轮 / 下一轮（首尾夹紧不循环）。

### 4. 文案与无障碍

- 界面不加说明文字、占位文字、轮次编号、快捷键提示或悬停 tooltip；仅保留无障碍标签：输入框 `aria-label="搜索会话"`、按钮 `aria-label="上一处"` / `"下一处"` / `"关闭"`、轮次导航 `aria-label="轮次"`。

### 5. 手机网页与 TUI

- 手机网页与 TUI 不在本轮范围内，留待后续单独设计。

## 后果

- 命中计算与轮次提取均以 `SessionView.entries` 为单一事实来源，逻辑纯函数化且在虚拟化与非虚拟化模式下行为一致。
- CSS Custom Highlight API 零侵入 Markdown 渲染树，避免拆裂代码高亮与行内文件引用节点；在不支持该 API 的测试环境安全降级。
- 跨会话搜索、会话内搜索与轮次导航共用同一套跳转定位实现，维护点单一且保持粘底跟随（`follow`）语义一致。

## 备选方案

- **按 DOM 搜索**：在虚拟化长会话下，视口外的条目并未挂载到 DOM，按 DOM 扫描既拿不到准确总计数，也无法跳到未渲染的命中；同时会混入思考块、工具输出与操作按钮文字。因此改为从全量 `SessionView.entries` 计算命中，仅在已渲染正文节点上应用视觉高亮。
- **按出现次数计数**：Markdown 源文与渲染后文字并不一一对应（链接地址、反引号、强调符号、行内代码等都会造成源文出现次数与 DOM 文本节点出现次数偏差），导致进度计数与实际高亮处数互相打架。按条目计数既避免源文/渲染计数错位，也更符合长对话逐条浏览的节奏。
- **把轮次列表放进标题栏概览浮层**：概览浮层需要显式点击标题栏或按键打开，无法在滚动阅读时持续感知当前处于整段对话的哪一位置；右侧常驻轻量化横线导航不占正文空间，悬停即可就地展开并跳转，交互路径更短。
