# ADR-0081：会话切换工作树

- 状态：已接受
- 日期：2026-11-04
- 修订：[ADR-0075](ADR-0075-worktree-isolation.md)、[ADR-0079](ADR-0079-branch-switch.md)、[subagent.md](../architecture/subagent.md)、[tools.md](../architecture/tools.md)、[permissions.md](../architecture/permissions.md)、[events.md](../protocols/events.md)、[context.md](../architecture/context.md)

## 背景

会话的 `cwd` 和 `workspaceRoot` 在创建时定下，之后不变。窗口开在主目录、工作放在另一个工作树时，会出现三个问题：

- 模型要在每条命令和每次写入里写绝对路径，写错就进了主目录，权限层也看不出错。
- `task` 的隔离工作树从主目录起步，子代理看不到工作树里已有的改动。
- `apply_subagent_changes` 合回主目录，不合回工作树，并行时要由主会话手动搬差异。

这些都来自一件事：会话不知道工作在哪个目录。

## 决定

### 1. 工具 `switch_worktree`

- 输入 `{ path: string }`。只在主会话注册，子会话和外部 agent 没有。
- `path` 必须出现在项目所属仓库的 `git worktree list` 里，主工作树也算，切回去就传它的路径。其他路径报 `invalid_input`，并列出可用的工作树。比较前，传入的路径按当前目录解析并取真实路径，`git worktree list` 的结果也取真实路径，再用平台的路径比较规则（大小写、分隔符）比较。
- 拒绝 `<sessionsDir>/worktrees/` 下的副本：它们由 ADR-0075 的清理流程管理。
- 项目目录是仓库的子目录时，切换后的目录映射到目标工作树里对应的子目录。目标工作树里没有这个子目录时报 `invalid_input`，不回退到根目录。
- 不创建、不删除工作树。创建和删除由模型走 `shell`，用现有权限规则。
- `traits.mutates = true`、`concurrencySafe = false`。权限主体是目标目录，判定在权限层，沿用工作区外操作的规则。
- 立刻生效：下一个工具调用起使用新目录。已经开始的调用不受影响。

### 2. 项目目录和当前目录

`session.created` 里的 `cwd`、`workspaceRoot` 不变，称为项目目录。另外有一个可变的当前目录，默认等于项目目录。

| 跟随项目目录 | 跟随当前目录 |
|---|---|
| 项目配置、信任、项目 Grant | 工具的 `cwd`、相对路径解析 |
| 项目指令、技能发现 | `shell`、`runGit`、分支读取 |
| MCP 服务器（切换时不重启） | 权限策略的 `workspaceRoot` |
| 系统提示里的环境信息 | `task` 的起点、`apply_subagent_changes` 的目标 |
| 侧栏分组（`SessionSummary.cwd`） | Hook 的 `cwd`、外部 agent 的 `cwd` |
| | 文件面板、新开的终端 |

切换后项目目录对会话来说是工作区外。ADR-0075 第 3 节的 shell 隔离 `deny` 只属于子代理，不加到这里：主会话要能用 `git -C` 合并。

上下文里留着其他工作树的绝对路径，模型可能照抄。会话切换过工作树后，按下面处理落在同仓库其他工作树里的路径（当前目录所在的工作树除外）。工作树清单在每次切换时读取并保存，恢复会话时重新读取；从没切换过的会话不读清单，也不走这些规则：

- `edit` 主体：权限层直接 `deny`，不询问，不受预设和 Grant 放宽。拒绝说明写明路径所在的工作树和当前工作树，让模型改用相对路径；确实要改那边就先切回去。
- `read` 主体：不改判定，可以读，用于对比。工具结果追加一行英文，写明路径位于另一个工作树和当前工作树是哪个。
- `shell` 命令里的路径不检查，这和其他基于文本的检查一样不是沙箱。

切回项目目录后规则继续生效，因为上下文里还留着工作树的路径。回退到第一次切换之前时，规则随之失效。

### 3. 记录和告知模型

- `session.config_changed` 增加可选字段 `worktree: { current, previous, branch? }`。旧版本忽略，不提升日志版本。
- 同时追加一条持久 `note`，沿用 ADR-0079 第 5 节的投影、修剪与压缩规则。内容只写从哪个目录切到哪个目录、相对路径改按新目录解析、上文里旧目录的绝对路径要换成新目录、之前读到的内容可能已过时。
- 同一事件更新 ADR-0079 记录的分支，下一个 Turn 不再重复说明分支变化。
- 系统提示不变，保住缓存。

### 4. 回退、分叉、恢复

- 回退到切换之前：沿用 `config_changed` 的折叠规则，当前目录回到之前的值。检查点是文件级的（ADR-0041），记录解析后的路径和原始内容，不依赖 git，回退可以同时还原多个工作树里的文件。文件所在的工作树已删除时，按 ADR-0041 逐文件报告失败，不中断其余文件。
- 分叉：继承分叉点的当前目录。
- 恢复：当前目录已不存在时回到项目目录，写一条 `worktree` 事件和 `note`，不报错。项目目录也不存在时沿用 `workspace_missing`。

### 5. 与其他功能的关系

- `switchBranch` 的忙判定（ADR-0079 第 3 节）按会话的当前目录算。在工作树里运行的会话不挡主目录切分支，会挡这个工作树切分支。
- 切换时正在跑的后台子代理不受影响。它们的结果并回当前目录，能否应用由 `git apply --check` 决定。
- 会话的当前目录被其他会话占用时不禁止：与多个会话开在同一目录一样。

### 6. 界面

不加入口和说明文字。侧栏分组不变；状态栏分支、文件面板、新终端读 `view` 里的当前目录；已打开的终端不动。工具行显示「切换工作树 · <目录名>」。手机和 TUI 只显示工具行。

## 不做

- 工具内创建或删除工作树。
- 退出时询问保留或删除：工作树的去留和会话无关。
- `task` 单独指定工作树：会话切换后不再需要。
- 状态栏分支菜单里的切换入口：等用起来再看。

## 后果

- 编码窗口可以开在主目录，先切到工作树再工作，提示词不用再要求绝对路径。
- `/boost` 的子代理从工作树起步，改动用 `apply_subagent_changes` 直接合回工作树。
- `meta.cwd` 的使用点要逐个分到第 2 节的两列里，漏掉一处就会在错误的目录操作，这是实现的主要风险。

## 备选方案

- **切换时重建会话运行时**：工具调用发生在 Turn 中间，重建要先结束 Turn，下一步才生效，不采用。
- **新建会话时选择工作树**：可以不改运行时，但侧栏要另外归组，已经开始的会话也切不了，不采用。
- **`task` 增加工作树参数**：只解决子代理，主会话的绝对路径问题还在，不采用。
