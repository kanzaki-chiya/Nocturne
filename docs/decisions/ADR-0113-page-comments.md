# ADR-0113：面板页面上直接评论

- 状态：已接受
- 日期：2026-11-23

## 背景

[ADR-0109](ADR-0109-page-versions.md) 之后，模型用 `render_html` 生成的图、界面草图、看板、文档会打开在桌面右侧面板里，用户常需要反复修改几处细节。

现在只能回到对话输入框，用文字描述「第二排中间那个框太窄」「右上角图例换个色」——页面元素多了以后很难说清指的是哪一块，而且模型也不知道用户针对的是哪一版页面。

## 决定

桌面右侧面板打开的页面允许用户直接点页面上的元素写评论，随下一条消息发给模型。内嵌页面、全屏遮罩、手机网页、安卓 App 和命令行不提供。

### 1. 工具栏与交互

- 面板页面的顶部工具栏在下载按钮左边增加一个评论图标按钮（`aria-label="评论"`，`title="评论"`），有未发送评论时显示当前版本的条数。
- 点击进入评论模式（按钮激活态），再点退出。评论模式下点击页面任意位置或选中文字后点击，拦截页面本身的点击事件，在点击处放一个带编号的圆点并弹出评论输入框（按钮「取消」「添加」；编辑已有圆点时为「删除」「取消」「保存」），不向页面注入说明文案或占位提示。
- 点已有圆点可修改或删除；非评论模式下页面保持原样，但当前版本已有未发送评论的圆点仍保留可见并可点选编辑。
- 切换版本时只显示该版本的圆点。
- 未发送评论只保存在当前会话的内存状态里，不持久化；关闭页面标签或切换会话时丢弃。

### 2. 锚定信息与局部截图

每条评论记录：

- `path`：从 `body` 起的 CSS 路径（优先用 `#id`，其次标签名加 `:nth-of-type(n)`）。
- `text`：被点元素的可见文字（截断 200 字符）；选中文字时为选中原文；无可见文字元素为空串。
- `x`、`y`：点击点相对文档左上角的 CSS 像素坐标。
- `note`：用户写的评论。

评论层放在沙箱空壳（`apps/desktop/public-web/sandbox.html`，与 `apps/relay/public/sandbox.html` 保持同步）内，由空壳在 iframe 内命中元素、计算坐标与绘制圆点，经现有通信桥（`comment-mode`、`comment-pins`、`comment-pick`、`comment-pin-click`）与宿主交互；宿主不解析页面 DOM。圆点与悬停框均带 `data-nct-comment-ui="true"`，页面截图与下载时将其排除。

对 `<canvas>`、`<img>`、无文字 `<svg>` 图形等无可见文字的元素，若当前模型支持图片输入（`capabilities.imageInput === true`），客户端经空壳扩展的 `capture` 协议（带 `region`）截取点击处周围 `240 × 240` CSS 像素（以点击点为中心夹紧在文档范围内，2× 导出），随评论提交。Core 侧同样按「评论无可见文字且模型支持图片输入」做最终门控，满足时按现有图片附件流程落盘并随消息发送；模型不支持图片输入或元素有可见文字时不附截图。

### 3. 输入框、协议与持久化

- 有未发送评论时，输入框上方显示标签「`<页面标题> v<n> · <条数>`」，点 `×` 移除并清空对应评论。
- 用户可以补充说明文字，也可以直接发送（允许输入框正文为空）。发送后清空该版本的未发送评论与圆点。
- `message.user` 事件新增可选字段 `pageComments?: { page, version, title, comments: [{ path, text, x, y, note }] }`；兼容扩展，不提升 `formatVersion`，旧版本忽略未知字段并按普通用户消息读取。
- 发送时由 Core 在消息 `content` 末尾追加一个给模型看的英文 `<page-comments>` 文本块，列出页面 id、版本号、每条评论的 `path`、`text`、`x`、`y`、`note`（附带局部截图时标注 `screenshot: attached`），并提示模型通过 `render_html`（传 `page`）更新该页面。客户端通过 `userEntryText` 隐藏该尾部块，对话气泡里只展示用户正文与「`<页面标题> v<n> · <条数>`」标签。
- 历史回放、回退、分叉均原样保留 `pageComments` 与相关图片附件。

## 后果

- 用户无需用文字反复描述「第几排第几个框」，模型能凭元素路径、可见文字、坐标及（无文字时的）局部截图准确更新目标页面。
- 沙箱空壳承担评论命中、圆点渲染与局部区域截图，宿主不触碰页面 DOM，保持 ADR-0088 的安全边界；圆点不污染页面下载和截图。
- `message.user.pageComments` 为向后兼容的可选扩展，旧版客户端与旧日志无兼容性风险。

## 备选方案

- **由宿主解析页面 HTML 源码定位元素**：动态脚本渲染后的 DOM 与静态源码不一致，且违背沙箱隔离原则，不采用。
- **所有评论一律截整页或局部图**：大幅增加 token 消耗和延迟，对含文字元素已有 `path + text + (x, y)` 足够定位，因此仅在无可见文字且模型支持图片输入时截 `240 × 240` CSS px 局部图。
- **未发送评论跨重启持久化**：草稿评论绑定到具体页面版本的瞬态编辑上下文，增加持久化与清理复杂度，仅保留在当前会话内存状态内。
