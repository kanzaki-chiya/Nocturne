# ADR-0054：服务商与模型启停——停用即不可用、记在 settings.json、各处按不可用处理

- 状态：已接受（维护者 2026-10-11 确定：停用后完全不能用；桌面端与 TUI 一起做；效果图 `Z:\nocturne-mockups\provider-toggle-v1.html` 已确认）
- 日期：2026-10-11
- 修订：[ADR-0026](ADR-0026-per-model-protocol.md) §5 的 `ModelInfo.unavailable` 增加「已停用」这一来源；[ADR-0040](ADR-0040-model-roles.md) 角色指向不可用模型时按未配置处理，停用同样适用

## 背景

维护者配置了多个服务商，其中代理类服务商（如 ocx）一家就列出几十个模型，模型菜单很长，常用的只有几个。另外，有时需要暂时不走某个服务商（密钥额度用完、上游不稳定），但不想删除它：删除会丢掉地址、密钥、模型编辑，重新添加还要再走一遍向导。

现在只能删除服务商；单个模型无法从菜单里去掉。

## 决定

### 1. 语义：停用即不可用

停用一个服务商，等于停用它下面的全部模型。停用的模型：

- 不出现在任何模型选择列表里：状态栏模型菜单、空状态模型选择、换模型卡片、设置 › 模型的角色对话框、TUI `/model` 页，「最近使用」同样过滤。不是置灰，而是不列出。
- 不能被选中或使用：新建会话、`setModel`、恢复会话、命令行 `--model` 一律以 `invalid_model` 拒绝，原因写明「已停用」。
- 默认模型（`model`）和模型角色（`modelRoles.*`）指向停用模型时按未设置处理：`defaultModel()` 返回 `undefined`；角色走 ADR-0040 现有的「不可用按未配置」路径，并发出 `model_role_unavailable` 警告。设置值本身保留，不改写配置；重新启用后立即恢复生效。
- 正在进行的 Turn 不打断；打开中的会话下一次提交在发请求前以 `invalid_model` 结束（ADR-0026 §5 的现有路径）。
- 配置、凭据、`userModels` 编辑都保留；服务商页的「删除」规则不变。
- 用量页的历史统计不受影响。

不采用「只从菜单里隐藏、已在用的照常可用」：维护者明确要的是暂时不走某个服务商，隐藏而仍可调用达不到目的。

### 2. 保存位置：用户 settings.json

```jsonc
// <NOCTURNE_HOME>/settings.json
{
  "disabledProviders": ["grok"],                         // 服务商 id，区分大小写
  "disabledModels": ["ocx/gemini-3.8-flash-high"]        // "<服务商 id>/<模型 id>"
}
```

- 与技能启停（`skills.disabled`）同一个文件、同一个写队列，由专用接口读写，不进入 ADR-0034 的白名单通用合并。不使用 `providers` / `models` 作键，因为 config.json 同名字段是服务商与模型声明，共用 schema 时会混淆。
- 只有用户级，项目配置不能启停。手写在 config.json 或项目配置里的服务商也能停用，不改写那些文件。
- 服务商停用时，`disabledModels` 里它的条目保持原样；重新启用服务商后按原来的逐个设置恢复。
- 刷新模型列表时，上游新出现的模型默认启用；已列入 `disabledModels` 的 ID 刷新后仍停用。
- 删除向导服务商时，一并清除它在两个列表里的条目；之后同名重新添加从全部启用开始。指向已不存在的服务商或模型的条目无害，读取时忽略。

### 3. Core：停用在注册表里表达为不可用

- 构建服务商注册表时传入停用集合。`resolve()` 对停用的模型照常解析，但给结果盖上 `unavailable: { reason }` 和 `disabled: "provider" | "model"`（`ModelInfo` 新增可选字段），原因分别是「服务商 <id> 已停用」「模型 <id> 已停用」，并附「可在 设置 › 服务商 或 /provider 重新启用」。
- 停用的服务商**不从注册表移除**：会话级注册表重建时「已移除的服务商保留旧实例」的逻辑只针对删除，停用必须在重解析后拿到不可用标记，不能沿用旧解析继续发请求。
- `listModels()` 默认不返回停用模型；新增 `listModels({ includeDisabled: true })` 供服务商页使用，结果里每个模型带 `disabled`。`ProviderOverview` 新增 `enabled: boolean` 与已启用模型数。
- 恢复会话时，会话模型已停用与「未知模型」走同一条路：没有替代模型时以 `invalid_model` 拒绝，带替代模型时先写 `session.config_changed` 再打开（sessions.md 4.2）。拒绝信息要让客户端区分「已停用」与「已删除」，以便换模型卡片给出「重新启用」：在错误里携带结构化的 `disabled` 与模型引用（具体形状由实现选，写进 rpc.md）。
- 所有经注册表解析模型的地方（会话模型、角色、标题、图片描述、摘要、权限审查小模型、子代理）都要尊重 `unavailable`；实现时逐一核对。
- 新增接口：`setProviderEnabled({ provider, enabled })`、`setModelsEnabled({ provider, models: string[], enabled })`（批量，供「全部启用 / 停用」），写盘后与其他服务商变更一样触发 `runtime.providersChanged`；`describeToggleImpact({ provider, models? })` 返回会受影响的打开会话数、是否为默认模型、受影响的角色，供客户端决定是否先确认。

### 4. 桌面端

按效果图：

- 服务商详情标题行加「启用」开关，位置与 MCP 页一致；停用时信息卡上方出现「已停用」横幅和「重新启用」。
- 模型表第一列为逐个模型的开关；表头右侧「全部启用」「全部停用」，有搜索词时改为「启用筛选结果」「停用筛选结果」，只作用于筛选出的模型；有模型被停用时显示「已启用 N / 总数」。服务商停用时模型开关保留状态但不可点。
- 左侧列表：停用的服务商空心状态点、名字变淡、标「已停用」；部分模型停用时模型数写「N / 总数」。
- 停用对象正被使用时（`describeToggleImpact` 非空）先弹页内确认，列出受影响的会话数、默认模型和角色；没人在用时直接切换。
- 换模型卡片：原因是停用时标题为「这个会话用的模型已停用」，增加次按钮「重新启用 <服务商或模型>」；打开中的会话提交被拒绝时也显示这张卡片。
- 设置 › 模型：默认模型或角色指向停用模型时，值加删除线，下方用警告色写「已停用，按未设置处理」。

### 5. TUI

- 服务商页：`Space` 启用 / 停用选中的服务商，停用的行显示 `○` 与「已停用」，模型数写「N / 总数」；正被使用时先在页内确认（`y` / `n`）。
- 服务商的模型页：`[x]` / `[ ]` 列表，`Space` 切换，`a` 全部启用、`n` 全部停用（有搜索时只作用于筛选结果）。
- 命令：`/provider enable <name>`、`/provider disable <name>`、`/provider model <name> <模型> on|off`；补全同步。
- `/model` 页与「最近使用」不列停用模型；会话模型被停用后提交失败时，提示原因并建议 `/model` 或 `/provider enable`。

## 后果

- 正面：菜单可以只留常用模型；暂停一个服务商不必删除重配；停用状态与配置分开，重新启用即恢复。
- 正面：复用 ADR-0026 的 `unavailable` 路径，角色回退、提交前拦截、新建会话拒绝都已有实现。
- 负面：`unavailable` 现在有两种来源（协议不可识别、停用），客户端需要按 `disabled` 区分显示和操作。
- 负面：上游新增模型默认启用，「全部停用后只开几个」的用法在刷新后可能多出新模型，需要再关一次。暂不做「默认停用新模型」的选项，等实际需要再加。

## 备选方案

- **写进 providers.json 条目（`enabled`、`userModels.<id>.enabled`）**：只覆盖向导条目，手写在 config.json 里的服务商无法停用；`userModels` 是能力字段的合并层，混入启停会让「只由该层引入的清单外模型被丢弃」的规则变复杂。
- **只隐藏不拦截**：见第 1 节，维护者否决。
- **允许名单（只列启用的模型）**：适合「几十个只开几个」，但新加服务商时默认什么都看不到，与常见用法相反；需要时可在本 ADR 上加一个按服务商的「新模型默认停用」开关。
