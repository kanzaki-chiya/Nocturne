# ADR-0039：空会话欢迎区与服务商页对话框化

- 状态：已接受
- 日期：2026-10-02

## 背景

[路线图](../roadmap/roadmap.md) v0.5「界面打磨」剩下两项：

- **空会话欢迎区**：现在的欢迎区是对话视口的第一项，左边一个小弯月，右边四行文字（版本、模型与档位、目录、快捷键），有没有消息都长一样。路线图要求会话为空时显示大号标识，首条消息后不再绘制。
- **服务商页推广成对话框**：[ADR-0030](ADR-0030-dialog-settings-pages.md) 先拿模型编辑对话框做样板，`/settings`、压缩阈值、审查器都已沿用，并已在 WT 实看认可。服务商页里的操作菜单、删除确认、换密钥和配置向导仍是旧的整页内联样式，只能用键盘。

## 决定

### 1. 空会话欢迎区（仅全屏）

- **何时显示**：当前会话还没有用户消息、视口里也没有其他条目（启动通知除外）时，视口显示大号欢迎区，代替现在的小欢迎区。
  - 首条消息提交后不再绘制大号欢迎区，视口第一项换回现有的小欢迎区（弯月 + 四行文字）。它照常随对话滚动并在退出时导出，模型和目录信息仍留在对话开头。
  - `/new` 后重新出现。`/resume` 恢复有历史的会话时不出现，显示小欢迎区。
- **内容**：自上而下为
  1. `NOCTURNE` 像素字标（复用服务商页的 `LOGO_ROWS`，5 行高、47 列宽，左半主色、右半 `accentAlt`）；
  2. 空一行，`v0.x.y · <模型> · 思考:<档位>`（无可用档位时省去思考段）；
  3. 当前目录（过长时从左侧截断，保留末段）；
  4. 空一行，快捷键提示 `/ 帮助  Shift+Tab 档位  Alt+M 权限`（与现有小欢迎区一致）。

  整块水平居中，垂直方向放在视口中间偏上（上方留白取视口剩余高度的 2/5）。
- **退化**：
  - 像素字标需要视口宽度 ≥ 51 列、视口高度 ≥ 12 行（字标、文字与上下留白），不满足时去掉字标，只显示单行 `Nocturne v0.x.y` 加其余文字，仍居中。
  - 视口高度不足 4 行时，退回现有小欢迎区的文字形态。
  - ASCII 模式字标用 `#`；NO_COLOR 保留形状。
- **不写入回滚区，不导出**：退出导出时，空会话只打印小欢迎区的文字形态，与现在一致。
- 大号欢迎区不响应点击，可以被拖选复制（复制所得是屏幕文字）。
- `--inline` 不变，仍打印小欢迎区。

### 2. 服务商页对话框化

服务商列表和模型列表保持整页（与 ADR-0030 样板轮一致：列表是页，编辑是对话框）。以下四处改用 ADR-0030 的 `DialogFrame` 与控件，覆盖在列表上居中显示，下层列表冻结输入、保留选中项与过滤：

- **操作对话框**：已配置条目上 Enter，打开标题为「服务商 <名>」的对话框，按钮竖排：`换密钥`、`刷新模型列表`、`编辑模型`、`删除`、`取消`。↑↓/Tab 移动，Enter 执行，Esc 关闭。当前会话正在使用的服务商，「删除」灰显，下方说明「当前会话正在使用，先用 /model 切换」。
- **删除确认**：从操作对话框选「删除」，或在列表上按 Delete，打开确认对话框，正文写明「删除 <名> 的配置与已保存的密钥」，按钮 `[ 取消 ] [ 删除 ]`，默认焦点在「取消」。沿用现有 `ConfirmDiscard` 的交互。
- **换密钥**：掩码输入框（`*` 回显）加 `[ 取消 ] [ 保存 ]`。保存仍交系统凭据后端，失败时保留输入并显示原因。
- **配置向导**：未配置预设上 Enter，打开标题为「配置 <预设名>」的对话框。
  - 步骤编排仍由 Core `runProviderSetupWizard` 决定，TUI 只换画法：已完成步骤在对话框上部折叠为一行摘要（`名称 x • 地址 y • 密钥已保存`），当前步骤显示提问、灰色说明和输入框，底部按钮 `[ 取消 ] [ 下一步 ]`，最后一步为 `[ 取消 ] [ 保存 ]`。
  - 「API Key 留空回车走环境变量」的规则不变，说明行照常提示。
  - 拉取模型列表时显示进行中状态，Esc 取消请求并回到上一步；结果行与现在一致。
  - 首次配置流程（第 1 步，共 2 步）的页头标记保留在下层页面上。
- **鼠标（仅全屏）**：
  - 对话框内的按钮和输入框按 ADR-0030 的点击规则响应单击。
  - 服务商列表行单击选中该行；单击已选中的行等同 Enter（打开操作或向导对话框）。
  - 列表区域响应滚轮滚动；对话框打开时滚轮不做任何事。
  - 页面内拖动仍不产生选区（ADR-0030 修订 2026-09-30）。
- **底部提示**：列表页改为 `↑/↓ 选择 • Enter 操作 • Delete 删除 • Esc 返回`；四项操作名不再在底部重复列出，因为操作对话框里已经看得到。
- **不变的部分**：只读条目仍直接提示去哪个文件修改；向导对外只发 `GET /models`；全页没有打字回答的是非题；`/provider key|refresh|model|remove` 子命令行为不变。

## 后果

- 新会话第一眼更像一个产品的启动页；开始对话后回到紧凑布局，不占对话空间。
- 服务商页的全部操作都能用鼠标完成，交互和 `/settings` 一致。ADR-0030 定下的样板推广到此完成，tui.md §12「其余页内控件暂不开放」相应收窄。
- 向导的步骤逻辑仍在 Core，TUI 改动集中在渲染与输入；Core 不新增事件或接口。
- 测试量主要在 TUI：欢迎区的显示与退化条件、四个对话框的键鼠操作、列表单击与滚轮。

## 备选方案

- **大号欢迎区也保留到对话开头**：会占掉一屏的顶部，翻回开头时很突兀，不采用。
- **向导改成一次填完的表单**：要改 Core 的向导编排和 `/provider` 子命令共用的流程，范围过大，不采用。
- **服务商列表也画成对话框**：列表需要过滤和较大高度，做成对话框会挤；与模型列表的处理保持一致，仍为整页。
