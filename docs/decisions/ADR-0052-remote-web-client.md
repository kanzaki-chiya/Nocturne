# ADR-0052：远程网页客户端——同一后台多客户端、局域网 WebSocket、扫码配对

- 状态：提议
- 日期：2026-10-08
- 修订：[ADR-0044](ADR-0044-rpc-stdio.md) 第 2 节「一个服务端进程只有一个 Runtime、一个客户端」

## 背景

长任务交给 Nocturne 跑时，人常常不在电脑前。任务会停在权限确认或提问上，回到电脑前才能继续。需要在手机上查看会话进度，并完成这几件事：批准或拒绝权限确认、回答提问、追加消息、中断。

现有结构的限制：

- 桌面端只有一个 `nctrn rpc --stdio` 后台（ADR-0051），由 Tauri 外壳逐行转发。
- RPC 服务端一个进程只服务一个客户端（ADR-0044 第 2 节）。会话打开、事件订阅、权限回复都挂在这一个连接上。
- 同一会话跨进程由会话锁互斥（ADR-0009），所以手机不能另起一个后台去打开同一个会话。

维护者确认的范围（2026-10-08）：

- 只有维护者本人使用；
- 做网页，不做原生 App；
- 第一版只支持局域网，外加 Tailscale 等组网工具提供的地址；不自建中继。

## 决定

### 1. 同一个后台服务多个客户端

- RPC 服务端改为一个 Runtime 服务多个连接：桌面端走 stdio 连接，手机走 WebSocket 连接，两者共用同一个 Runtime 和同一批已打开的会话。
- **会话按 Runtime 共享，订阅按连接**：
  - 第一个连接 `resumeSession` 时真正打开会话；之后的连接再 `resumeSession` 同一会话，直接返回 `SessionOpened` 并附上 `lastSeq`，不再报 `session_already_open`。
  - 每个连接各自 `subscribe { afterSeq }`，事件分别推送。
  - 会话按引用计数关闭：连接 `close` 或断开只减计数，最后一个连接离开且会话空闲时才真正关闭。保持现有的「空闲才关」语义：运行中的 Turn 不因手机断开而停下。
- **命令谁先到算谁的，Core 不改**：
  - 两端同时 `submit`，后到的照常报 `session_busy`；
  - 权限确认和提问，任一端回复即生效。另一端稍后回复报 `unknown_request`，界面收到 `permission.resolved` / `question.resolved` 后关闭对应弹窗。这些事件现在已经存在。
  - `interrupt` 任一端都可以发。
- **Runtime 级通知广播给所有连接**：`runtime.providersChanged` 等推给每个连接。
- **`interactive`**：只要有一个已连接的客户端声明 `interactive`，就按交互模式处理。桌面端始终声明，所以实际行为与现在一致。
- 权限判定仍只在权限层。远程客户端只是又一个回复来源，不新增「远程自动批准」之类的规则。

### 2. 传输：后台自带 WebSocket 监听

- 由 Node 后台（`nctrn rpc`）监听，不放在 Tauri 外壳里。原因是多客户端的会话共享必须在 Runtime 所在进程里实现；放在外壳里，就得在 Rust 里重写一遍 JSON-RPC 的多路复用和会话去重。
- 新增参数：`nctrn rpc --stdio --listen <host:port> --web-root <dir>`。
  - stdio 仍是桌面端的主连接；
  - `--listen` 额外开一个 HTTP 服务：同一端口提供网页静态文件（`--web-root`）和 WebSocket 端点 `/rpc`；
  - WebSocket 上每条消息就是一条 JSON-RPC 报文，与按行协议的报文内容完全相同，只是换了分帧方式。
- 监听默认关闭，由桌面端设置项打开。打开或关闭监听时需要重启后台，或者提供 `remote.start` / `remote.stop` 方法在运行中切换；采用哪种在实现计划里确定，优先不重启。
- 只绑定用户选定的地址：局域网网卡地址，或 Tailscale 地址（`100.x`）。不默认绑定 `0.0.0.0`。端口默认固定一个高位端口，可在设置中修改。
- 桌面端退出或电脑休眠时，远程连接随之断开。第一版接受这一点，网页上要显示「电脑已离线」。

### 3. 配对与认证

- **扫码配对**：
  1. 桌面端调用 `remote.pair`，服务端生成一次性配对码（32 字节随机数，5 分钟有效，用一次即作废）。
  2. 二维码内容为 `http://<地址>:<端口>/#pair=<配对码>`。配对码放在 URL 片段里，不会出现在请求行和访问日志中。
  3. 网页读出配对码，用 `POST /pair` 换取**设备令牌**（32 字节随机数），存进浏览器的 localStorage。
  4. 服务端只保存令牌的哈希，连同设备名、配对时间、最近使用时间，写入 `~/.nocturne/remote-devices.json`。
- **连接认证**：
  - WebSocket 建立后，第一条报文必须是带令牌的 `initialize`，否则立即断开。令牌不放进 URL。
  - 令牌无效时返回统一的错误，不区分「不存在」与「已吊销」。
  - 配对和认证失败都要限流，例如同一来源每分钟最多 10 次。
- **设备管理**：桌面端「设置 › 远程」列出已配对设备，可以吊销。吊销后立即断开该设备的连接。
- **不做账号体系**，不接入第三方登录。

### 4. 传输安全（第一版的取舍）

- 局域网第一版使用明文 HTTP 和 WebSocket，没有 TLS。在家庭 Wi-Fi 下，单人使用可以接受；在公共 Wi-Fi 下，令牌可能被窃听。设置页要写明这一点，并建议出门在外时用 Tailscale：Tailscale 的链路本身是加密的。
- 明文 HTTP 不是浏览器的「安全上下文」，因此：
  - 网页不能作为真正的 PWA 安装，只能加书签或添加到主屏幕快捷方式；
  - 剪贴板写入 API 不可用，复制改用选中文本的回退方式。
- 以后的改进方向，不在第一版：用 Tailscale 的 HTTPS 证书（`tailscale cert`）提供正规 HTTPS；或者使用自签证书，并在配对时固定证书指纹。

### 5. 网页客户端

- 复用桌面端前端：在 `apps/desktop` 中新增网页入口，用 `WebHost` 实现现有的 `DesktopHost` 接口，传输层使用 WebSocket 版的 `LineTransport`。打开文件、在资源管理器中显示、更新等宿主能力，在网页里不可用或降级为复制路径。
- 如果之后要拆出共享 UI 包，另行决定，第一版不拆。依赖方向以 modules.md 为准，网页入口不得引入 Tauri API。capabilities 测试只覆盖桌面入口。
- 网页静态文件随桌面端安装包一起分发（Tauri 资源目录），后台启动时由外壳通过 `--web-root` 传入。命令行版第一版不提供网页。
- **手机端第一版的功能范围**：
  - 会话列表（普通对话与项目分组，只读排序）；
  - 打开会话、查看消息流和工具调用（折叠显示）；
  - 发送文字消息（不含图片附件）、中断；
  - 回复权限确认与提问；
  - 在已有项目或普通对话工作区里新建会话。
- **第一版不做**：设置页、服务商与 MCP 管理、附件、回退与分叉、技能导入、文件打开。
- 布局按手机竖屏设计：单栏，会话列表与会话页之间导航切换；权限确认和提问以底部弹出的面板显示。

### 6. 不变的部分

- Core 不改：多客户端完全在 `packages/rpc` 的服务端实现。
- 会话日志、会话锁、权限层、事件协议不改。
- 桌面端的 stdio 连接与现有行为不变；监听关闭时，后台与今天完全一样。

## 后果

- RPC 服务端从「单连接」变为「多连接共享 Runtime」，这是本 ADR 最主要的工作量和风险：会话引用计数、断线清理、通知广播、以及连接各自的 `afterSeq` 续接都要重新测试。
- 远程连接相当于在手机上远程执行代码。安全边界就是：配对码一次性、令牌可吊销、默认关闭、只绑定选定地址。
- 局域网明文传输是有意识的取舍，依赖使用环境（家庭网络或 Tailscale）。
- 网页与桌面共用前端，桌面界面的改动会影响网页端，需要在测试中覆盖网页入口。

## 备选方案

- **原生 App**：推送通知和后台常驻更好，但要分别适配 iOS 和 Android，上架和签名的成本高，单人使用不值得。以后需要推送时，可以用同一套前端套壳。
- **自建中继**（像 zcode 那样外网直连）：需要服务器或 NAS 常驻、中继本身的认证与加密、运维。单人使用时，Tailscale 已经能解决外网访问。
- **由 Tauri 外壳监听并多路复用**：避免改 RPC 服务端，但要在 Rust 里重写 JSON-RPC id 映射和会话去重，而且命令行版无法复用。否决。
- **手机另起后台打开同一会话**：受会话锁限制，且两个 Runtime 的状态无法同步。否决。
- **Bot 通道（微信、Telegram）**：适合只看通知、简单回复的场景，排在网页之后另行设计。

## 实现计划（建议分轮）

1. **RPC 多连接**：服务端支持多个连接共享 Runtime、会话引用计数、通知广播。只用内存传输测试，不涉及网络。
2. **WebSocket 监听与配对**：`--listen`、静态文件服务、配对码与设备令牌、限流、设备文件。在 RPC 中新增 `remote.*` 方法，并同步 rpc.md。
3. **桌面端设置页**：「设置 › 远程」开关、地址选择、二维码、设备列表与吊销。
4. **网页入口与手机布局**：`WebHost`、WebSocket 传输、单栏布局、底部权限面板，并在真机上验收。

每轮完成后都可以独立验收；第 1 轮也为将来的 IDE 插件等多客户端场景打基础。
