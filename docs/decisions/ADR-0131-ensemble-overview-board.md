# ADR-0131 合奏概览、常驻搜索与留言筛选

- 状态：已接受
- 日期：2026-11-27

## 背景

ADR-0089 的合奏只有留言板与成员页：用户要跟进一个多小时的合奏时，只能逐条翻帖子推断「拆成了哪几摊、每摊进行到哪、谁在等谁」。`SessionView.ensemble` 已提供标题、成员任务书、活动、收发帖与结束摘要，但缺少属于这一场合奏的目标、检查点、有序工作线和任务状态。

同时，留言板原有的整排成员筛选标签与需点击展开的搜索在长合奏里可用性差：筛选占一整行、搜索不常驻、收件人按当前名册回算（成员增删会改写旧帖的历史收件人）。

本文补充 ADR-0089。视觉基准为 `nocturne-mockups` 仓库 `ensemble-overview/index.html` 与三张效果图，原型数据仅作验收样本。

## 决定

### 1. 概览数据契约与维护方式

`SessionView.ensemble` 新增 `overview`（`EnsembleOverview`）：目标（可选）、检查点列表、有序工作线与修订号。每条工作线有稳定 ID、名称、负责人、可选的本场来源帖号、可选的进展短句（可再带帖号与「等待」标记）；任务有稳定 ID、所属工作线、标题、负责人及四态（待开始 `todo`、进行中 `work`、等待 `wait`、已完成 `done`）与可选来源帖号。负责人引用本场身份：`"maestro"` 或成员名（含已被移除的成员，显示历史负责人）。任务移交、改名、重开或跨线移动后仍是同一项。

概览由指挥显式维护，不从自然语言、成员空闲、权限等待、普通 `todo_write` 或会话 `/goal` 推算。新增指挥专用工具 `ensemble_overview`：输入为增量（`goal`、`checkpoints`、按 ID 的工作线/任务 upsert 与 `removeLines`/`removeTasks`），全部校验通过后追加**单条**持久事件 `ensemble.overview_updated`，控制器与 `SessionView` 归约共用同一个纯函数应用增量：

- 校验全部在一个函数里收集：负责人必须是 `"maestro"` 或本场名册中的成员；帖号引用必须指向已存在的帖子；新建线/任务的必填字段（名称、负责人、任务状态）；`before` 插入位与 `line` 归属必须可解析。任一错误即整体拒绝，工具结果一次列出全部错误，失败不留下部分写入。
- `base` 必填：必须等于 `ensemble_read` 返回的当前修订号。不匹配时拒绝并给出当前修订号，要求指挥重读后基于最新状态重写——旧更新因此不能覆盖已接受的新进展。
- 幂等：每次成功更新把规范化输入的 SHA-256 指纹写进事件。修订号已推进时，唯一豁免是输入与最后一次成功更新**完全相同**（重试场景），此时不重复追加事件、直接报告当前修订号。指纹在事件 payload 中，重启与恢复后仍然有效。
- 修订号从 1 起单调递增，不做相等性去重（无变化的重写也是一次新提交）。

`ensemble_read` 的输出附带概览全文与修订号，模型文本里追加结构化的概览段；指挥提示词要求在搭好骨架、派单、收到进展/阻塞与验收时同步概览。帖号引用在渲染端容错：帖子缺失时省略引用标记而不是报错。

### 2. 兼容、结束与边界

`ensemble_init` 的调用契约不变。旧日志无需迁移：没有概览数据的合奏在概览页降级显示已有的标题、结束摘要与成员入口。部分建立的概览按已知字段逐步呈现。结束后 `ensemble_overview` 拒绝写入，最后一次接受的快照保持只读；`ensemble.overview_updated` 不提升 `formatVersion`——新增事件类型本身已使旧版本拒绝读取该日志（沿用 ADR-0089 的先例）。分叉、回退与新一场合奏边界遵循 ADR-0089 §9：概览随派生视图一起回退，新一场合奏从空概览开始。

### 3. 界面：三页签与概览页

桌面右栏与手机全屏共用同一份「概览｜留言板｜成员」结构。从合奏标题、会话中的合奏行等通用入口进入时落在概览；`/ensemble board` 始终直达留言板（包括面板已经打开时）；点击具体成员仍打开该成员会话。普通实时刷新保留页签、工作线展开项、留言草稿与阅读位置；这些界面状态按合奏实例（`createdSeq`）隔离。

概览页自上而下：可验收的目标、一行检查点、`任务 n/m 已完成` 与总进度条，再按序列出工作线。每条线收起时保留名称、完成分数、负责人、最新进展与可用的 `#帖号`；等待中的线用警告色并显示 time 图标。任务在展开线内按 待开始→进行中→等待→已完成 排列，四态都有可访问名称。默认展开首条有进行中任务的工作线，没有则首条未完成线；全部完成时初始收起。用户手动折叠后，收到更新不会强制展开。任务仅归属一条线计数。

### 4. 留言板：常驻搜索、筛选与跟随

页签行下常驻「搜索留言」输入框，右侧 `settings_6` 筛选按钮（徽标计数 0–2，只统计作者与收件人两个条件，0 时省略数字）；移除原来的整排成员筛选标签。关键词搜索沿用正文/作者/任务书三路不区分大小写按字面匹配，命中在正文与代码中以 `<mark>` 高亮且保留原文大小写，不改变 Markdown、链接与文本选择。收窄时计数显示 `命中/总数`，无结果显示空态。

筛选展开时并列「来自」「发给」两个单选选择器（默认「全部」，指挥显示为「指挥」，含已移除成员的历史参与者）：`来自` 匹配作者身份；`发给` 匹配发帖当时已持久化的实际收件人（`recipients`）加上显式任务书归属（`charterOf`），不回算 mentions、不随成员增删改写历史。关键词、作者、收件人取交集。收起面板后条件以可单独移除的标签显示；「清除筛选」一次清掉两个人员条件，保留搜索词与跟随状态。「跟随最新」是独立开关：关闭后新帖不抢阅读位置，开启时贴底跟随。

### 5. 范围

合奏共享运行时（Core 协议、控制器、提示词）、桌面/手机合奏面板与对应文档。TUI 保留已有入口和行为。

## 后果

- 指挥每轮维护概览有额外开销，换来用户可实时跟进的一屏状态；不维护时界面按既有降级路径显示，不会出错。
- 乐观并发以「重读重写」为冲突解决路径：同一时刻只有指挥一个写者，冲突只会来自重试或基于过期状态的写入，成本可接受。
- 客户端不新增 RPC：概览随 `SessionView` 同步，桌面与手机共用同一份归约结果。
- 原型效果图为视觉基准但不逐像素约束：面板宽度、字号与令牌沿用 DESIGN.md。

## 备选方案

- **从帖子与活动自动推算概览**：试过在原型阶段讨论，推断规则无法区分「任务完成」与「成员空闲」等歧义，且无法表达检查点与工作线顺序；放弃。
- **全量快照式更新**：每次写入整棵概览。更简单但旧快照重试会整树覆盖新进展，与「旧更新不能覆盖新进展」直接冲突；放弃，改为按 ID 增量。
- **独立的概览读写工具对**（`ensemble_overview_read` / `ensemble_overview_write`）：与既有 `ensemble_read` 合一更符合「读板即得全貌」的使用路径；放弃。
- **提升 `formatVersion` 承载新事件**：新事件类型已天然拒绝旧版本读取，不需要额外版本门槛；放弃。
