# ADR-0030：TUI 对话框式设置页

- 状态：已接受（维护者 2026-09-30 确认）
- 日期：2026-09-30

## 背景

[v0.5 界面打磨](../roadmap/roadmap.md)要求把设置类页面画成对话框，并让服务商操作更容易发现。当前模型编辑是服务商页的整页子视图：七个字段以文本行显示，`←`/`→` 循环选项，底部已有保存/取消；[ADR-0024](ADR-0024-model-settings-editor.md)及 [ADR-0025](ADR-0025-per-model-reasoning.md)已确定字段、来源、只读、三态与保存语义。[ADR-0029](ADR-0029-tui-themes.md)确定深浅主题只给局部区块涂底色，不涂满终端；TUI 已有 `overlayBg`，但没有专门的输入框底色角色。全屏已有鼠标拖选复制，`--inline` 不开启鼠标上报，单击控件不能破坏选区。

## 决定

### 1. 范围、顺序与验收

先只把**模型编辑子视图**改为通用对话框控件的样板；模型列表、服务商列表和向导继续用现有布局。实现后由维护者在 WT 中实际查看深浅主题、正常及窄终端并认可，再另轮推广到服务商页。`/settings` 页尚未实现；将来沿用同一套对话框和控件，本 ADR 不定义其字段、存储或交付时间。「服务商页操作的可发现性」可在样板轮独立完成：改列表底部提示和 Delete 入口，不要求此轮重画服务商页。折叠块点击另轮实现，只复用本 ADR 的点击判定。

样板轮验收：在全屏模式和 `--inline` 临时备用屏幕中，模型编辑七字段、来源、只读、校验与保存结果和旧页一致；键盘可完成全部操作，鼠标单击可在全屏模式操作可见控件且拖选复制不误触；深浅主题、ASCII、NO_COLOR、终端缩放及极小尺寸有可读退化。保存仍经现有 Core patch；保存失败保留草稿。离线组件/交互测试覆盖焦点、三态、非法值、只读、鼠标按拖判定和保存失败；维护者在 WT 实看并认可后，才开始推广。此处“认可”是后续推广的门槛，与本 ADR 的接受分开。

### 2. 对话框位置、尺寸与主题

模型编辑打开时冻结其下的页面输入，将服务商/模型列表或主内容作为背景，在**同一全屏帧**里组合对话框；不另进备用屏、不写入对话历史。全屏输出层继续输出完整帧，鼠标命中使用组合后的最终帧坐标。`--inline` 只在现有模型/服务商页使用的临时备用屏幕内显示同一对话框；退出回原普通屏幕，原回滚区不改色。

可用区域为终端宽度和 `rows - 1` 帧高，避开状态行/保留行；对话框水平和垂直居中，宽度为 `min(72, 列数 - 4)`、高度为 `min(所需行数, 帧高 - 2)`，外侧至少留 2 列、上下各 1 行。所需行数包括标题、可见字段、来源、预留的错误行、按钮和边框；字段过多时只滚动字段区，标题、错误与按钮固定。布局按实际显示宽度和行数判断：保留外边距与边框后，若放不下标题、至少一个当前字段及其来源、错误行和按钮，或放不下当前字段标签与其控件的最窄画法，就去框去外边距，改为占满可用帧的整页，字段仍可滚动；不使用固定的列数或行数阈值。整页仍放不下时缩短标签、来源路径、提示与选项文案，再每次只显示当前字段和「取消 / 保存」及必要错误，`Tab`/方向键仍能遍历全部字段。宽度不足以容纳一行两个按钮时按钮上下排列。再小到无法显示一个字段和一个按钮时只显示「终端太小，请放大」及 `Esc` 返回，不提供不可见的保存命中区。

外框用圆角边框，框内局部底色取 ADR-0029 的 `overlayBg`（深色比常用深底稍亮；浅色与浅底保持可辨层次）。新增主题角色 `inputBg`：数字、文本输入框的局部底色，在两套主题里均比 `overlayBg` 更暗且与文字有足够对比；焦点沿用 `selectionBg`、`selected`、`accent`，来源与说明用 `muted`，错误用 `error`。具体色值在实现时按两套主题目视验收，不写入本 ADR。未聚焦时也靠边框、方括号和标记识别控件，不仅靠颜色。

ASCII 模式外框退为 `+ - |`，开关、选中标记、按钮也用 ASCII（下节）；NO_COLOR 不输出任何配色控制序列，保留同样的边框、焦点符号和错误 `!`。深浅主题只更换色值，布局和文案相同。

### 3. 通用控件与模型页画法

以下 ASCII 示意图只表示结构；普通模式的圆角框、`●━━`/`━━○` 和着色按正文规则呈现。`>` 表示焦点，`*` 表示已选中；色块不是唯一状态信号。终端不能改变单行字号，「灰色小字」按 `muted` 弱化文字实现。每个字段的来源放在控件**下方紧邻一行**，以 `来源：…` 呈现，宽度不足时截断长路径的左侧、保留文件名；当前值为「跟随」时同处显示跟随后的生效值。只读也保留来源及定义它的文件。

开关用于独立布尔值；开为 `●━━`，关为 `━━○`，ASCII 分别为 `[ON ]`、`[OFF]`。模型的图片输入需要「跟随」语义，故在模型页实际使用下述三态分段控件，开关用于将来无需跟随的布尔设置。

```text
> 自动检查 [ON ]  开
  自动检查 [OFF]  关
```

枚举用并排分段按钮，一组选中一项；焦点是整组，`*` 标选中项。按显示宽度预算，放不下就按选项边界换到下一行；高度仍不足时只显示「`<` 当前项 `>` / 共 N 项」，左右切换，不能悄悄截掉不可见选项。协议的「跟随 / Chat Completions / Messages」按此规则。

```text
> 协议  [* 跟随] [  Chat Completions] [  Messages]
  窄屏  < Chat Completions > / 3 项
```

数字、文本采用 `inputBg` 暗底输入框；空框显示「跟随」占位但草稿仍为空，输入的整数按原始字符显示，不格式化。键入时框内显示硬件光标，超宽文本水平滚动以保持光标可见。沿用 [TUI §2](../apps/tui.md) 的页内输入框坐标约定：按终端显示宽度（中文 2 列）计算列，登记相对帧末行差；全屏由输出层换算绝对坐标并与帧同笔写出，`--inline` 沿用 DECRC/DECSC 补位。聚焦改变、字段区滚动、窗体居中或尺寸变化后重新登记；输入法候选窗跟随实际硬件光标，不依赖画出的假光标。

```text
> 上下文长度   [ 128000|          ]
  显示名       [ 跟随            ]
```

「跟随 / 是 / 否」画成一组三态分段按钮，`* 跟随` 意味清除用户覆盖，旁边来源行说明实际生效值。推理「是」保存为 `visible`，「否」为 `none`；已有 `hidden` 的生效值仍显示「是」，数据值不改。图片输入相同。推理生效为「否」时仍按 ADR-0025 隐藏思考档位行。

```text
> 推理  [* 跟随] [  是] [  否]
  来源：models.dev；跟随后为「是」
```

思考档位沿用现有多选弹层语义：「跟随」与「不支持思考强度」均独占，其余六档可多选；新控件只换画法，`[x]`/`[ ]` 在 ASCII、NO_COLOR 下仍可辨。弹层焦点仅在自身，Esc 放弃弹层修改，Enter 确认并回字段。

```text
  思考档位  [编辑档位…]  当前：low / high
  + 档位 ------------------------------+
  | [ ] 跟随  [ ] 不支持思考强度         |
  | [x] low   [ ] medium  [x] high ...  |
  + 空格勾选  Enter 确认  Esc 取消 ------+
```

只读字段用 `muted` 灰显、`[只读]` 明示且跳过焦点；仍显示生效值和来源。输入非法时在原框及其下方用 `!` 和错误色标出具体原因；Core 的跨字段错误置于按钮上方的固定错误行，并将可定位字段标错。保存失败留在对话框、保留草稿和焦点、显示 `! 保存失败：<原因>`；保存中禁用重复提交，完成后恢复。错误行不覆盖来源。

```text
  最大输出 [ 128000 ] [只读]
  来源：由 config.json 决定
> 上下文长度 [ abc ] !
  ! 请输入正整数
```

底部按钮顺序为「取消」「保存」，默认保存为主按钮，焦点用 `>` 加选中态；只读页只留「返回」且不出现保存。按钮单击或 Enter 执行相同动作，失败不会关页。

```text
  [ 取消 ]  > [ 保存 ]
  保存失败时：! 保存失败：文件不可写
```

完整模型编辑页示意（终端够宽时，来源紧跟对应字段；字段较多时中间区域滚动）：

```text
             + 服务商 commandcode / 模型 kimi-k3 ---------------------+
             | 显示名        [ Kimi K3|                        ]       |
             |   来源：用户编辑                                       |
             | 上下文长度    [ 128000                         ]       |
             |   来源：上游                                           |
             | 最大输出      [ 32000 ] [只读]                         |
             |   来源：由 config.json 决定                            |
             | 图片输入      [* 跟随] [  是] [  否]                    |
             |   来源：models.dev；跟随后为「是」                      |
             | > 推理          [  跟随] [* 是] [  否]                  |
             |   来源：用户编辑                                       |
             | 思考档位      [ 编辑档位… ]  low / high                |
             |   来源：用户编辑                                       |
             | 协议          [* 跟随] [  Chat Completions] [ Messages]|
             |   来源：按接口声明推导                                 |
             |                                                        |
             |                         [ 取消 ]   [ 保存 ]            |
             + Tab/方向键移动  空格/Enter 选择  Esc 取消 ---------------+
```

深色主题使用较亮的 `overlayBg`、更暗的 `inputBg` 和主题主色标出焦点；浅色主题沿用同一明暗层次及相同文字、符号和对比逻辑。示意中的直角框只是 ASCII 文本展示，非 ASCII 实际使用圆角。

### 4. 键盘与焦点

焦点顺序为可编辑字段从上到下，再「取消」「保存」；只读字段跳过，纯只读页仅「返回」。打开时聚焦首个可编辑字段（没有则聚焦按钮）；焦点移到滚动区外时自动滚入可见区。`Tab`/`Shift+Tab` 正反向遍历**所有**可聚焦项（首尾循环）；`↑`/`↓` 仅在字段区逐字段移动，抵达首/末字段后停住，不跳到底部按钮。按钮区 `↑` 回最后一个字段、`↓` 留在按钮区；按钮间用 `←`/`→` 移动。这样方向键保留字段内编辑含义，Tab 是跨区域的可靠导航。

- 分段按钮：`←`/`→` 选前/后项，到边界停住；空格或 Enter 确认当前项并留在本组，不触发保存。开关：`←` 关、`→` 开，空格或 Enter 翻转。选项变化即时更新草稿与跟随预览，不写盘。
- 数字/文本框：`←`/`→` 移动字符光标，Home/End 到首尾，Backspace/Delete 分别删除光标前/后的字符；空格作为文本字符输入（数字框因此出现非法输入提示），Enter 结束本框编辑并移到下一可聚焦项，不保存；粘贴按现有页内输入约定，不把终端控制序列当文字。数字框只在保存前按 Core 规则校验，输入过程中保留非法草稿以便修改。
- 思考档位：字段上空格或 Enter 打开多选弹层；弹层 `↑`/`↓` 或 Tab/Shift+Tab 移动选项，空格勾选/取消，Enter 确认，Esc 放弃。弹层内的 `←`/`→` 若选项并排则在同一行移动；不改变勾选。
- 取消/保存按钮：空格或 Enter 执行；保存没有额外快捷键，须先将焦点移到「保存」。保存成功才关闭并回模型列表。

`Esc` 在最内层先关闭多选弹层；编辑页无修改时直接取消返回，有未保存修改时必须打开「放弃修改？ [继续编辑] [放弃]」二次确认，默认继续编辑，方向键/Tab 移动、空格/Enter 执行；确认层 Esc 返回编辑。草稿是否修改按字段用户覆盖状态和值比较，不把仅改变焦点算修改。保存中 Esc 不关闭页面，等待结果；失败后仍可取消。全局 Esc 的选区/补全处理在设置对话框打开时让位于最内层对话框；`Tab`/`Shift+Tab` 被对话框消费，不触发主输入框补全或思考档位切换。`Enter` 不提交主对话，字母键不走斜杠命令；对话框打开时其下页面和主输入框不收键。全局 Ctrl+C 中断/退出语义仍按现有优先级。

### 5. 鼠标、命中与滚动

通用点击规则：只认全屏模式的左键；按下时记录起点和所处层，**松开时**才判定。按下后整个序列没有收到任何移动/drag 事件，且松开位置仍在同一可点击控件命中框内，才算单击；只要收到过一次移动事件，即使拖回原点，也永久按拖选处理，不执行控件动作。没有按下记录、按在控件外或释放到别处都不触发；一次按下最多执行一个动作。这条规则供后续「点击展开折叠块」原样复用，折叠块本身不在本 ADR 实现范围。

命中框取**最终渲染帧**中控件可见字符的显示列宽和绝对行号，含方括号/开关轨道/按钮文字及内侧留白，不含来源、外框与遮挡行；中文按显示宽度计两列，截断/换行、对话框居中、字段区滚动和终端 resize 后每帧重算。分段按钮每段独立命中，文本框点击按显示列定位光标；滚轮在字段区只滚字段，在对话框外维持原页面翻阅规则。对话框覆盖区优先消费鼠标事件，禁止透传到下层全屏内容；边框或空白点击不关闭对话框，下层可见但不可点。拖选继续走现有选区/复制路径；拖从对话框内开始时只选对话框可见文字，不激活控件或底下的对话内容，离框后不跨层选取。关闭对话框后下层选区与滚动位置按进入前状态恢复。`--inline` 不开鼠标上报，本 ADR 不改变其鼠标行为；临时备用屏里的对话框仍只用键盘。

实现本 ADR 时，[tui.md §11](../apps/tui.md)「不做页内可点击控件」应改为：模型编辑对话框开放单击（后续服务商设置控件在推广时开放），其余页内控件暂不开放；双击/三击仍不做。待「点击展开折叠块」实施时再补充思考标题与工具行的点击范围、展开后的锚点行为。本轮只确认 ADR，不修改 tui.md；样板实现时同步修订 §2、§3、§8、§11。

### 6. 实现边界与服务商入口

开关、分段按钮、输入框、来源行、错误行、底部按钮和对话框壳为 `apps/tui` 内复用组件；焦点与命中映射同在 TUI。沿用 `ModelSettingsView`、`ModelSettingsPatch` 和现有 `saveModelSettings`/`updateProviders` 路径；不新增 Core 接口，不改字段语义、来源优先级、校验、配置合并、会话事件或 CLI。若实施时发现现有公开 API 无法表示某项必要行为，先单独提出 Core 变更原因和契约，不能把 UI 状态塞入 Core。

服务商列表底部提示改为「Enter 打开操作（换密钥 / 刷新 / 编辑模型 / 删除）」；受宽度限制时保留「Enter 操作」并在相邻可见提示行列出四项，不悄悄只显示前几个。选中**已配置且可管理**的服务商时按 Delete，直接进入现有删除确认（默认取消），包括过滤框非空时；Backspace 仍只删过滤字符，Delete 不再删过滤字符。未配置、只读条目按 Delete 给出不可删除原因；当前会话正在使用的服务商按 Delete 或操作菜单中的「删除」均拒绝，并提示「先用 /model 切换」，确认框不打开。实际删除仍要用户在确认框里确认，且沿用现有 Core 路径。

## 后果

模型页可以作为服务商页和未来 `/settings` 的可视、键鼠样板，而 Core、数据流和字段校验不变。代价是 TUI 需要维护控件焦点/命中矩形、两套主题对比度、滚动与极小终端退化；自动测试要抓到按下后移出再移回的拖选边界、焦点冲突、IME 坐标与保存失败保留草稿，实际终端截图仍需维护者验收。正式 TUI 文档在样板实现时更新，避免已接受的方案与当前行为混淆。

## 备选方案

保持整页布局、只换开关和分段按钮：改动和鼠标命中测试更少，但不能验证覆盖层与原对话选区的共存，也不能为服务商页和 `/settings` 提供真实的对话框样板；将来仍须再做一次布局、焦点和退化测试。一次性重画全部服务商页和 `/settings`：视觉一致性来得快，但 `/settings` 尚未设计，变更和截图/交互回归成本显著增加，问题也难以定位。本 ADR 选择先做模型样板，再由维护者在 WT 实看后决定推广。
