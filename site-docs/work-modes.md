# 执行方式

在任务前面加上 `/grill-me`、`/goal`、`/plan` 或 `/boost`，可以让当前任务按对应的执行方式推进。桌面端、手机网页、TUI 和逐行 CLI（`nctrn --cli`）都支持这四个命令；单次非交互模式（`nctrn -p`）不解析斜杠命令。

已发出的执行方式消息会在正文前显示命令名（例如 `/plan`），在桌面端和手机网页点击命令名可以展开附加给模型的说明原文。回合运行中发送带执行方式的消息会自动排入队列（`queue`），在当前回合正常结束后作为新回合启动，不能作为插话（`steer`）并入当前回合。

## 追问需求（`/grill-me`）

适合需求还有不少细节没定下来、希望模型先问清楚再动手的场景：

```text
/grill-me 给登录页加上找回密码流程
```

- 模型会先阅读相关代码与文档，能够从仓库里查到的事实不会拿来提问。
- 需要你拍板的问题通过 `ask_user` 一次只问一个，有推荐方案时放在第一项并标注「（推荐）」。
- 当剩下的不确定项都很小时，模型会把达成一致的需求整理成清单，再问一次确认后开始实现。

## 目标模式（`/goal`）

适合交办一个需要多步推进、希望模型自己做到验证通过为止的目标：

```text
/goal 给用户表加上软删除字段并让全部测试通过
```

- 模型先列出可核对的交付清单再开始工作。
- 每当模型准备结束回复但还没有调用 `update_goal` 报告完成时，运行时会在当前回合末尾拦下它，要求逐条核对交付清单的证据（命令输出、测试结果、文件内容），未完成就继续做。
- 如果本会话还有正在运行的后台子代理，当前回合会先正常结束，等后台子代理收束后再继续核对。
- 不再按核对次数或工作时长停止；如果连续三轮目标核对都没有任何工具调用（包括 `update_goal`），目标自动变为受阻。一轮有工具调用就重新计数。旧会话已达到原上限的目标仍显示为已停止，可继续。
- 按 `Esc` 或 `Ctrl+C` 中断当前回合会同时停止目标，之后的普通对话不会被目标核对打断。

管理当前会话的目标：

| 命令 | 作用 |
|---|---|
| `/goal` | 查看当前目标、状态、已用轮数与时长（没有目标时显示「没有目标」） |
| `/goal stop` | 停止目标（已在进行中的回合不再自动续跑） |
| `/goal resume` | 继续已停止、受阻或旧上限的目标（轮数重新计算，工作时长累计；空闲时立即开始新一轮核对） |
| `/goal cancel` | 不确认，立即中断正在运行的回合并移除目标；没有目标时命令无效 |

桌面端的目标行位于任务清单面板内，手机网页位于输入框上方，任务清单不移动；目标详情默认收起，展开状态不保存，也不影响任务清单折叠状态。仅目标小组件的秒表更新，不刷新整页。状态行显示目标、状态、轮数和累计工作时间，空闲或暂停不计时；时长按小时、分钟、秒显示。已完成、取消或因回退停止的目标不显示；运行中、受阻、用户停止/中断以及旧上限目标可见。TUI 增一行目标状态，核对消息只显示 `/goal` 原文；逐行 CLI 不显示常驻目标行。

## 计划模式（`/plan`）

适合改动较大、希望先审阅实施方案再允许修改代码的场景：

```text
/plan 把权限配置迁移到新的结构
```

1. **只读探索与出计划**：进入计划模式时，会话权限预设会自动切换为 `read-only`，并记下进入前的预设。模型只读探索仓库（必要时用 `ask_user` 询问需要你决定的问题），最后在回复里给出完整的 Markdown 实施计划，不做任何文件修改。
2. **评论修订**：计划就是一条普通的助手回复。如果你有修改意见，直接在输入框回复即可，模型会在 `read-only` 下修订并重新给出完整计划。
3. **批准或放弃**：
   - 在桌面端和手机网页，当会话处于计划模式且空闲时，最后一条助手回复下方会出现「批准」按钮；点击「批准」（或在任意客户端输入 `/plan approve`）会恢复进入计划模式前的权限预设（若原本就是 `read-only` 则切到 `default`），退出计划模式并立即开始实施。
   - 输入 `/plan cancel` 会恢复原权限预设并退出计划模式，不开始实施。

计划模式期间目标不会自动续跑：无论先设目标再进计划，还是先进计划再设目标，模型给出计划后都会停下来等你评论或批准。批准或放弃计划后，目标如果仍在进行中，会照常生效。

## 重发与回退

- 自己发出的执行方式消息点「重发」或「编辑并重发」时，会按原执行方式重新发出，例如重发 `/plan` 消息会再次进入计划模式。目标核对、继续目标和批准计划这类由运行时写入的消息不提供这两个按钮。
- 用 `/rewind` 回退时，执行方式消息在列表和回填的输入里带着命令名（目标消息回填为 `/goal` 加原来的目标文字，不含附加给模型的说明原文），回填后直接发送即按原执行方式提交；由运行时写入的消息不回填文字。
- 回退到设定目标的那条消息或更早时，目标随之停止；回退到进入计划模式的那条消息或更早时，按放弃计划处理，恢复原权限预设并退出计划模式。回退到这些消息之后的位置不受影响，只还原文件也不受影响。

## 多代理攻坚（`/boost`）

适合可以拆成几个互不干扰的子任务、希望并行调查与实现的场景：

```text
/boost 为导出模块补齐 CSV、JSONL 两种格式和对应测试
```

- 模型会先把任务拆成互不依赖的子任务，用后台子代理（`background: true`）并行推进，每个会话默认最多同时运行 `3` 个后台子代理。
- 只读调查使用 `explore` 子代理；独立的代码修改在 Git 仓库下使用工作树隔离（`isolation: "worktree"`），每个子代理在各自的独立工作树里修改文件。如果当前工作区不是有提交的 Git 仓库，则只用后台子代理做并行调查，文件修改由主会话自己完成。
- 子代理是非交互的，不能向你弹窗请求权限确认；在 `default` 等较严的权限预设下，可写子代理的写入或命令可能被拒绝，此时主会话会接手完成该子任务。若希望可写子代理自主完成修改与验证，可先将会话权限预设切到 `guarded`、`smart` 或 `bypass`。
- 子代理收束后，主会话用 `apply_subagent_changes` 将各个工作树的改动并回主工作区（必要时用 `3way` 处理冲突），最后在主工作区运行测试或类型检查并按子任务汇总结果。
- 逐行单次模式（`nctrn -p`）与定时任务会话不启用后台子代理，因此不支持 `/boost`。
