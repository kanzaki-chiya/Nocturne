# 回退和分叉

当模型改错了方向，或者你想从之前的某条提问出发尝试另一种方案时，可以使用回退（Rewind）或分叉（Fork）。

## 从哪里回退

回退以历史中的**用户消息**为锚点（运行中发送的「插话」消息属于原回合内部的补充，不能单独作为回退或分叉起点）。

### 桌面端与手机端：编辑并重发

1. 将鼠标悬停在要回退的那条用户消息上：
   - 直接点击「重发」，会连同对话与文件一起回退到该条消息前并按原文重新发送；
   - 点击「编辑并重发」，消息气泡会展开为编辑框，底部显示将撤回的回复轮数与将还原的文件列表。
2. 如果这条消息之后模型通过内置文件编辑工具改过文件，可在「回退方式」单选框中选择：
   - 「对话和文件」：把该消息之后追踪到的文件还原到该消息发送前的检查点，同时截断其后的对话记录；
   - 「仅对话」：保留磁盘上现有的文件改动，只回退对话记录。
3. 修改消息文本后点击「发送」（按 `Esc` 或点击「取消」放弃）。

若你只想还原最新一轮的文件改动、不回退对话，点击该轮改动卡片右上角的「↶ 撤销」→「撤销文件改动」（见 [第一个会话](first-session.md)）。

### 终端（TUI 与 CLI）：`/rewind`

在终端会话中输入 `/rewind`（TUI 在空闲且输入框为空时，也可在 600ms 内连按两次 `Esc`），打开历史用户消息列表。选择一轮后可从四项操作中选择：

1. 「对话和文件一起回退」
2. 「只回退对话」
3. 「只还原文件」
4. 「从这里分叉新会话」

确认回退对话后，目标消息的原始文字会自动填回输入框（图片附件不回填，并提示「原消息的图片未放回」），修改后即可重发。

## 回退影响什么

Nocturne 在每次执行内置文件写入工具（`write`、`edit`、`apply_patch`）前会自动记录文件检查点：

- **可还原的改动**：模型通过上述文件编辑工具新建或修改的文件，回退文件时会自动还原内容或删除新建文件；如果某文件后来又被外部程序改过，预览中会标注 `[已在外部修改]`。
- **未追踪的改动**：通过 `shell` 命令、MCP 工具或外部 Agent 产生的文件变化不会记录检查点，改动卡片与回退预览会提示「未计入统计」或「含未追踪调用」，需要用 `git checkout` 等方式手动清理。

## 分叉会话

分叉会复制当前会话到指定位置为止的事件历史，创建一个独立的新会话；原会话完整保留，磁盘上的文件保持当前状态。

- **终端（TUI 与 CLI）**：输入 `/fork` 直接从当前会话末尾分叉并切换到新会话；也可以在 `/rewind` 选中某一轮后选择「从这里分叉新会话」。
- **桌面端和手机远程端**：在历史用户消息上点「分叉」，从该条消息之前分叉并打开新会话。桌面端输入 `/fork` 会指向这个按钮。运行中，或这条消息不能作为回退起点时，分叉会被拒绝。

从某条消息分叉后，新会话的输入框里已经填好这条消息的原文，光标在末尾，不会自动发送，改完再发即可。用 `/goal`、`/plan`、`/boost`、`/grill-me` 发出的消息会连同命令名一起填回，直接发送就按原来的方式执行。图片附件不会填回；从 Nocturne 自动写入的消息（目标核对、继续目标、批准计划）分叉时，输入框保持为空。终端里用不带位置的 `/fork` 分叉时，输入框也保持为空。新会话不会显示回退提示。
