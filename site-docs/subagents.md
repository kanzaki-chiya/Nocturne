# 子代理

## 什么时候用子代理

当任务包含大量只读代码搜索、多个互不依赖的文件修改或耗时较长的独立验证时，主代理会调用内置 `task` 工具启动**子代理（Subagent）**。

每个子代理在独立的子会话中运行，拥有独立的上下文窗口，完成后只把精炼结论返回给主会话，避免大段中间搜索记录撑满主会话上下文（参见 [上下文和用量](context.md)）。

### 内置档位

`task` 工具提供三个内置档位（Profile）：

| 档位 | 名称 | 默认职责 | 默认工具集 |
| --- | --- | --- | --- |
| `default` | 通用 | 通用子任务，默认跟随当前会话的模型与推理强度 | 全部工具 |
| `quick` | 快速查找 | 快速定位文件、查找函数调用链、阅读文档汇总 | 只读（`read`、`grep`、`glob`、`web_fetch` 及只读 MCP 工具） |
| `deep` | 深度实现 | 跨多文件的复杂功能实现、疑难 Bug 修复与运行测试验证 | 全部工具 |

子代理运行在非交互模式：在当前会话未预先授权的情况下，子代理内需要人工弹窗确认的操作会被直接拒绝。

## 后台运行与工作树隔离

- 主代理可以将互不依赖的子任务设为后台并行运行（`background: true`）。
- 需要修改文件的后台子代理会使用 `isolation: "worktree"` 在独立的 Git 工作树（保存在 `~/.nocturne/sessions/worktrees/`）中执行，不会与主工作区正在编辑的文件冲突。
- 后台子代理完成后，主会话会收到通知，主代理可调用 `apply_subagent_changes`（或由你在面板中点击「应用变更」/「三方合并」）将其改动合并回主工作区。

## 查看与控制子代理

- **桌面端**：在对话流中点击子代理卡片，即可在 [右侧面板](panels.md) 打开子代理详情页，实时查看其推理与工具调用过程；对后台运行中的子代理可在底部输入框向其追加说明或点击「中断」；对使用工作树隔离的后台子代理，完成后可在面板中点击「应用变更」或「三方合并」。
- **终端 TUI**：输入 `/subagents`（或按 `Ctrl+G`）打开子代理视图，用 `←` / `→` 在多个子代理之间切换，查看实时输出或向后台子代理发送消息。

## 配置子代理档位

在桌面端「设置 → 通用 → 子代理档位」或 [配置参考](config.md) 的 `subagents.profiles` 字段中，你可以配置 `quick`、`deep` 或点击「新增档位」添加自定义档位，分别指定模型、推理强度与只读约束。
